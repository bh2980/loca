Translation Workbench 개발 계획 v0.2

작성일: 2026-10-09 (Asia/Seoul)
상태: 설계·개발 계획. 이 문서 작성으로 기능이 구현되거나 검증된 것은 아니다.
범위: 현재 로컬 모노레포의 개편. 이번 작업은 문서 작성만 수행한다.
우선순위: 이번 사용자 합의를 반영한 이 문서가 이전 DEVELOPMENT_PLAN.txt,
REDESIGN_PLAN.txt, PROCESS_REVIEW.txt의 충돌하는 설계보다 우선한다.
UX_FLOW_PLAN.txt의 2026-10-09 v0.2 여정과 함께 구현·검증 기준으로 사용한다.

1. 목표와 확정된 결정

AI가 대부분의 번역 작업을 수행하고 사용자가 원문 흐름, 자료, 프로세스,
결과를 직접 확인·조절하는 로컬 번역 작업실을 만든다. 자동 작품 분석이
완성되어야 번역을 시작할 수 있는 구조를 만들지 않는다.

D01. 장면 지도와 대사 흐름은 크기에 관계없이 D3 + Canvas로 통일한다.
     React Flow 구현·의존성·전용 CSS를 제거한다. 방향이 있는 제어 흐름을
     표현하며, 파일별 칸이나 격자를 사건 순서처럼 배치하지 않는다.
D02. 원문 흐름 그래프와 사용자 작업 프로세스 그래프는 서로 다른 데이터다.
     확대·이동·선택 등 Canvas 기반을 공유하되 원문 연결 편집과 작업 연결
     편집을 혼동하지 않는다. 원문 그래프는 추출 근거를 보존하는 탐색 대상이다.
D03. 프로젝트별 채팅과 여러 세션을 제공한다. 새 세션은 별도 대화 기록을
     가지며, 저장된 프로젝트 자료는 함께 조회한다. 웹 검색은 켜고 끈다.
D04. 채팅은 읽기·조사 후 변경 초안을 제시한다. 사용자가 수락하기 전에는
     작품 자료·번역·용어·상태 등 프로젝트 본문을 변경하지 않는다.
     수락 / 거절 / 피드백 작성 / 초안 직접 편집을 제공한다.
D05. 세션 단위 포괄 변경 권한은 초기 범위에서 제외한다. 이는 서브에이전트
     호출과 다른 개념이다. 서브에이전트도 초기 구현의 필수 조건이 아니다.
D06. 사용자가 AI 프로필, 상태, 라벨, 노드 인스턴스와 프로세스를 생성한다.
     초기에는 제공한 노드 유형과 HTTP 설정으로 구성한다. 임의 코드로
     새 실행 기능을 주입하는 플러그인·스크립트 노드는 후속 범위다.
D07. 프로세스 시작은 한 번이다. 설정한 단계·조건·반복을 자동으로 진행한다.
     기본 템플릿은 검수 통과분 자동 확정, 미해결 대상만 사람 확인이다.
D08. 채팅 변경 승인과 실행 중 자동 반영은 구분한다. 사용자가 선택한 대상과
     저장된 프로세스로 실행을 시작하면 그 실행에 포함된 행동은 매번 채팅
     승인을 받지 않는다. 사람이 확인하는 지점은 사람 확인 노드로 지정한다.
D09. 대사 하나, 장면, 임의로 선택한 여러 대사를 지원한다. 상태·판정 단위는
     원문 ID, AI 호출 단위는 개별 또는 묶음이다. 장면 안의 대사를 한 줄씩
     호출하는 방식으로 고정하지 않는다.
D10. 여러 번역 후보와 대표 번역을 보관한다. 수정 이력·모델·문맥·근거를
     기록하며, 재실행한 결과를 이전 후보 위에 무조건 덮어쓰지 않는다.
D11. 작품 전체 분석·단서 연결·추가 조사는 요청하거나 노드로 넣었을 때만
     수행한다. 실행 범위, 모델 호출·검색 횟수·토큰 한도와 중지를 제공한다.
D12. 추출된 정렬·연결은 실제 사건 순서나 인물의 지식 획득을 보증하지 않는다.
     원본 연결·파생 연결·미확인 참조를 보존하고, 모르는 조건은 그대로 남긴다.
D13. 영어 원문 → 한국어 번역을 우선한다. 원본 게임, orwell_1_reorder,
     상위 orwell_dll과 기존 원문·번역·사용자 연결 설정은 보존한다.
D14. 인물은 노드, 관계는 종류와 방향이 있는 연결선으로 탐색한다. 노드에서
     프로필, 연결선에서 관계 설명·적용 범위·근거를 연다. 작품 설명은 읽기
     문서, 근거는 원문/웹 출처로 이동할 수 있는 인용 목록을 기본으로 한다.

2. 현재 기반과 추가로 필요한 부분

현재 코드에서 재사용할 기반
  - 원문 ID, 그룹, 서사 그래프, 용어 번역 후보·사용처, 번역 이력.
  - 작품 자료의 근거, 버전, 이력, 복원 및 사용한 번역의 갱신 필요 표시.
  - 모델 연결·인증, 작업 설정, 프롬프트 시험, fallback, 호출 기록과 스냅샷.
  - 장면별 AI 묶음 호출, 결과의 원문 ID 대응 검사, 입력 버전 충돌 검사.
  - 실행 중단·재개·재시작 복구의 일부 기반, SQLite 저장, 프로젝트 보관·백업.
  - LargeGraphCanvas의 D3 확대/이동, Canvas, hit test, 미니맵, 레이아웃 worker.

현재 구현의 한계
  - FlowCanvas는 600노드 초과만 Canvas, 나머지는 React Flow다.
  - 그룹/파일 중심 레이아웃과 불완전한 조건 노드 분류를 별도로 고쳐야 한다.
  - 실행은 고정된 Stage와 정적인 Run.steps를 직렬로 수행한다. 사용자 정의
    조건·반복·사람 대기를 가진 그래프 실행기가 아직 없다.
  - AI 프로필은 고정 작업 종류에 묶여 있고 번역 상태도 고정 enum이다.
  - 채팅 세션·도구 호출 반복 처리·웹 조사·변경 제안 승인 기능이 없다.
  - 일반 모델 호출은 일회성 구조화 결과용이다. 채팅을 위해 번역 호출의
    제한을 일괄 해제하지 않고 별도 대화 실행 인터페이스를 추가해야 한다.
  - 작품 자료 신규 생성은 분석 결과 반영 내부에 묶여 있다. 채팅에서 사용할
    독립적인 생성·수정 동작과 승인 경계가 필요하다.
  - 자료 조회는 근거 ID와 단어 일치 중심이다. 인물·사건의 자동 병합,
    경로별 기억 복원이나 누락 없는 관련 자료 발견은 구현돼 있지 않다.
  - 사용자 정의 라벨은 새 데이터다. 서식 검사의 HTML/게임 태그와 구별한다.

3. 그래프와 탐색

3.1 의미와 모양
  장면·대사/번역할 본문: 사각형. 실제 번역 대상과 화자·상태를 표시한다.
  조건·분기: 마름모. 참/거짓 등 원문에 있는 출구와 조건을 구별한다.
  대기: 모래시계. 이벤트: 원과 이벤트 아이콘. 상태 변경: 육각형.
  연결·합류: 작은 점. 해석되지 않은 제어 노드: 별도 미확인 기호와 원형식.
  색만으로 의미를 구별하지 않는다. 제어 노드는 번역량에 포함하지 않는다.
  원문과 조건이 함께 있는 노드의 원본 ID·관계를 보존하며 표시용 분할을
  실제 원문 증가로 집계하지 않는다. IfElseState 같은 원형식도 분류한다.

3.2 배치와 범위
  기본은 위에서 아래로 읽는 방향 그래프이며 분기·합류·되돌아오는 간선과
  순환을 표현한다. D3는 상호작용을 담당하며 계층 배치·간선 경로 계산은
  별도 worker에서 수행한다. 강제 force animation을 기본 배치로 쓰지 않는다.
  파일은 출처/필터 정보이며 배치의 강제 경계가 아니다. 파일 간 연결을 유지한다.
  연결 없는 노드도 검색·선택할 수 있다. 임의 간선으로 이야기를 연결하지 않는다.
  장면 축약은 입구/출구와 제어 조건을 보존해야 한다. 중간 조건을 통과하는
  연결을 생략하거나, 모든 장면 출구가 모든 입구와 연결된 것처럼 만들지 않는다.
  원문에 없는 장면 관계는 파생 근거를 붙인다. 불명확한 연결은 미확정이다.
  전체 대사는 모든 대상에 접근할 수 있어야 한다. 화면 밖 그리기와 확대별
  표현량을 줄일 수 있지만 데이터·연결을 임의 120개로 자르지 않는다.

3.3 사용자 여정과 화면
  장면 지도 → 장면 선택 → 오른쪽의 닫을 수 있는 상세 → 장면 열기.
  장면 안에서는 같은 위치의 읽기/흐름 전환으로 범위를 유지한다.
  작품 전체 대사와 장면 안 대사의 진입점을 구분한다. 선택 장면 전용 모드를
  작품 전체의 동급 탭으로 나열하지 않는다.
  원문·번역·화자·ID 검색 → 화면 밖 노드로 이동 → 상세/읽기 → Back/Forward.
  범위·검색·필터·선택·확대/이동·스크롤·미저장 초안을 복원한다.
  미니맵은 왼쪽 위, 선택 상세는 오른쪽 Canvas 위 패널을 기본으로 한다.
  좁은 화면에서는 본문을 가리지 않도록 패널을 접거나 전체 상세로 연다.
  자료 목록은 표/목록으로 비교하고 상세는 읽기 화면으로 연다.
  반복 상단바·상시 완료 바·중복 뒤로가기 바를 추가하지 않는다.

3.4 성능·접근성 목표
  위상·노드 크기 변경에만 재배치한다. 선택, 번역 텍스트, 상태 폴링 때문에
  전체 그래프를 재배치하거나 큰 JSON을 매 프레임 저장하지 않는다.
  Canvas 미니맵, 공간 인덱스, 확대별 상세 수준, 간선 경로 기준 culling을 적용한다.
  키보드 검색·선택·상세 접근을 제공하며 노드 수만큼 숨은 DOM을 생성하지 않는다.
  브라우저의 실제 전체 맞춤과 읽기 배율을 모두 측정한다. 읽기 전용 Orwell
  약 1만 노드 규모와 합성 분기·순환·고립 노드를 사용한다.
  최초 목표: 지정한 로컬 테스트 환경에서 pan/zoom 프레임 간격 p95 33ms 이내,
  선택 응답 100ms 이내. 최초 배치/로드 시간은 별도 기록한다. 환경·해상도·DPR,
  노드/간선 수와 측정법을 보고하며 Canvas draw 시간만으로 FPS를 주장하지 않는다.
  이 수치는 향후 검증 목표이며 현재 측정 성과가 아니다.

3.5 인물·관계 탐색
  작품 자료에서 인물·관계를 열면 인물 노드와 관계선을 탐색한다. 인물 이름
  검색과 목록 접근도 유지한다. 노드는 원형 인물 아이콘/이름으로 표시하고
  현재 선택, 관련 인물, 적용 범위를 구별한다. Canvas 공통 기반을 재사용한다.
  관계는 방향과 종류를 갖는 연결선이다. 친구/가족/상관/의심 등 관계 이름을
  표시하며 여러 관계와 상호 관계를 보존한다. 유형 이름은 확장 가능하다.
  인물 그래프 배치는 관계 탐색에 맞춘다. 인물의 공간적 위치를 사건의
  선후관계로 표현하지 않으며 서사 CFG의 위→아래 규칙을 그대로 강제하지 않는다.
  인물 노드 → 프로필·말투·별칭·관련 원문. 관계선 → 관계 설명·근거·변화 이력.
  원문 보기 후 Back/Forward에서 선택한 인물/관계와 그래프 위치를 복원한다.
  시점·분기별로 다른 관계를 현재의 단일 사실로 합치지 않는다. 지정 범위가
  없으면 여러 관계의 적용 범위를 상세에서 구별하고 미확정 조건을 남긴다.
  관계 출처는 직접 작성, 원문에 근거한 연결, AI 추정 등으로 보존한다.
  함께 등장했다는 이유만으로 인간관계를 자동 생성하거나 본문에서 실시간
  추측해 선을 그리지 않는다. 저장된 인물·관계 레코드만 그래프에 반영한다.
  기존 자유 서술 프로필은 그대로 읽을 수 있어야 한다. 자동 구조 변환은
  사용자가 요청하는 선택 작업이며 채팅 변경 제안 절차를 따른다.
  작품 설명·배경·번역 기준은 제목/종류/수정일/근거가 있는 목록과 읽기 문서로
  제공한다. 근거는 발췌·출처·연결 대상 목록이며 모든 문단을 그래프 노드로 만들지 않는다.

4. 프로젝트 채팅과 변경 승인

4.1 세션과 도구
  프로젝트별 세션 목록·새 세션·이름 변경·기록 재열기·입력 초안을 제공한다.
  새 세션은 이전 대화를 자동으로 전부 전달하지 않는다. 공용 작품 자료와
  사용자가 명시적으로 첨부한 원문·자료·요약을 조회한다.
  선택 장면/대사를 채팅에 첨부할 수 있고 첨부 범위와 해제를 표시한다.
  프로젝트/세션을 바꿔도 다른 프로젝트의 ID나 승인 대상을 재사용하지 않는다.
  긴 조사는 넓은 대화·자료 비교 화면으로 펼칠 수 있다. 닫으면 원래 그래프와
  읽기 위치로 돌아간다. 채팅이 그래프 공간을 항상 점유하지 않는다.

  초기 읽기 도구: 원문 검색, 원문 ID/장면 범위 읽기, 저장 자료 검색·열기,
  용어/사용처 조회, 실행 단계·진행 집계, 상태·라벨 목록/집계, 변경 이력 조회.
  진행 상황은 질문 시 실제 저장 상태에서 계산한다. 읽은 일부를 전체로 말하지 않는다.
  페이지 단위 읽기와 총수·읽은 범위를 반환하고 원문 전체를 매 요청에 넣지 않는다.
  웹 도구: 설정한 검색 서비스와 페이지 읽기. 모델 연결만으로 웹 검색을
  지원한다고 가정하지 않는다. 채팅 도구 호출을 확인한 연결부터 지원한다.
  웹 토글은 서버 도구 권한에도 적용한다. OFF에서는 요청·직접 URL 읽기를
  수행하지 않고, 이전에 저장된 웹 자료는 출처와 함께 로컬 자료로 표시한다.
  켜진 경우에도 요청 범위에 필요한 조사만 한다. 호출·검색/페이지 수·토큰
  한도를 두고 중지할 수 있다. 검색 서비스 비용과 모델 사용량을 구별한다.
  일반 HTTP 노드의 실행 권한을 채팅에 그대로 노출하여 웹 OFF를 우회하지 않는다.

4.2 변경 제안의 수명
  사용자: 자료/프로필을 생성 또는 수정해 달라고 요청.
  AI: 조사·초안 작성 → 변경 제안 저장 → 생성/변경할 내용을 제시.
  UI: 대상, 새 내용 또는 전후 차이, 근거, 영향 범위 + 수락/거절/피드백/편집.
  수락: 승인한 제안의 해당 버전만 한 번 적용. 적용 결과와 자료 링크를 반환.
  거절: 본문에 반영하지 않고 제안 이력으로 보관.
  피드백: 지시문을 받아 새 제안 버전을 생성. 이전 승인으로 새 버전을 적용하지 않음.
  직접 편집: 편집한 초안이 최종 수락 대상. 기존 본문은 수락 전 유지.

  제안·채팅 메시지·도구 실행 기록의 저장 자체는 승인 대기 중에도 허용한다.
  승인 전 초안은 확정 작품 자료나 번역 문맥에 자동 편입하지 않는다.
  수락 시 source/translation/term/knowledge의 기준 버전과 잠금을 재검사한다.
  중간에 본문이 바뀌면 충돌과 현재 차이를 보여주고 갱신한 제안을 다시 검토한다.
  중복 클릭·재시작·중복 도구 응답이 중복 생성/수정으로 이어지지 않아야 한다.
  하나의 제안에 여러 생성·수정을 묶을 수 있다. 초기에는 제안 단위 수락이며
  부분 적용이 필요하면 승인 전 제안을 나눈다.
  용어 변경 승인에 숨은 모델 실행을 붙이지 않는다. 영향 표시와 AI 재검토
  시작을 구분한다. 별도 실행을 제안할 때는 대상·프로세스·범위를 함께 제시한다.

4.3 권한 경계
  읽기·요청한 조사: 허용된 도구와 범위에서 수행.
  채팅의 프로젝트 변경: 위 변경 제안 수락을 통해 수행.
  직접 UI 편집: 기존처럼 사용자가 저장한 동작을 적용.
  사용자가 시작한 프로세스: 시작 시 고정한 대상·노드·설정에 따라 자동 적용.
  같은 검증/변경 실행 계층을 쓰되 호출 출처와 권한을 구분한다. 채팅 모델이
  내부 API를 직접 호출하여 승인 경계를 건너뛸 수 없게 한다.
  가져온 원문·웹 페이지·API 응답은 자료다. 그 안의 지시가 변경 허락이 되지 않는다.
  세션은 대화의 단위, 포괄 권한은 허용 범위, 서브에이전트는 작업 위임 방식이다.
  초기에는 여러 세션만 제공하고 세션 포괄 쓰기 권한·서브에이전트는 제공하지 않는다.

5. 프로필·상태·후보·프로세스 데이터

  AIProfile: 고유 ID/버전, 이름, 연결/모델, 지원되는 추론 수준, 프롬프트,
  문맥 정책, 도구 정책, 출력 형식, 호출 한도, fallback. 여러 노드가 재사용한다.
  초기 재사용 범위는 프로젝트이며 다른 프로젝트로 복사/가져오기를 지원한다.
  연결·비밀정보는 별도 관리하고 가져온 프로필은 로컬 연결에 다시 연결한다.
  연결 관리와 작업 프로필·프롬프트 시험 화면을 구분하고 짧은 실제 오류만 표시한다.

  StatusDefinition / LabelDefinition: 프로젝트별 사용자 정의 ID·이름·표시 정보.
  각 번역 대상은 현재 진행 상태 하나와 라벨 여러 개를 가진다. confirmed 같은
  자동화/내보내기 의미는 이름 문자열 대신 명시적인 상태 역할로 연결한다.
  실행기의 queued/running/waiting/failed 상태, 갱신 필요 여부, 편집 잠금은 별도다.

  TranslationCandidate: unitId, 후보 ID/버전, 내용, 생성 실행/노드/모델,
  입력·문맥 버전, 검수 결과. 대표 후보는 별도 참조로 선정하며 이력은 보존한다.
  후보 보관 때문에 매번 여러 모델을 호출하지 않는다. 병렬 후보 생성은 설정한
  경우에만 한다. 여러 대사의 일관성을 검수한 묶음과 버전도 함께 기록한다.

  WorkflowDefinition: 노드 유형·인스턴스 ID·설정·포트·연결·입출력 매핑·버전.
  NodeType registry: 제공된 실행 기능과 입력/출력 스키마·부작용·호환 버전.
  WorkflowRun: 시작 시 대상 ID, 프로세스/프로필 버전, 연결 참조, 한도 고정.
  NodeExecution: 실제 입력·출력·분기·문맥 스냅샷·진행·오류·사용량·변경 기록.
  WorkItem: 대상 ID·후보·묶음 ID·경로 범위·현재 작업 위치·수정 횟수·대기 사유.
  ChatSession/Message/ToolCall: 프로젝트와 세션에 귀속된 대화·도구 실행 기록.
  ChangeProposal: 작업 목록·기준 버전·초안·근거·상태·수락 기록·피드백 연결.
  BackupRecord: 완료 원문 집계·다음 임계값·스냅샷 revision·파일·검증 결과.
  Character: 고유 ID·이름·별칭·프로필 자료 ID·근거·버전. 이름 문자열로만 연결하지 않음.
  Relationship: 고유 ID·양끝 인물 ID·방향·종류·설명·분기/시점 조건·근거·버전.
  EvidenceReference: 원문 ID/문서 위치 또는 웹 URL·조회일·발췌·자료 버전.
  작품 자료 본문과 인물/관계 구조가 같은 참조를 사용하도록 하여 별도 복제 문서의
  내용이 서로 어긋나지 않게 한다. 시간 정보가 없는 관계는 임의로 현재 시점으로 확정하지 않는다.

  채팅과 프로세스는 원문 조회, 자료/용어 저장, 상태 변경 등 공통 동작을 사용한다.
  모델이 호출할 도구와 노드의 실행 함수를 중복 구현하지 않는다.
  도구 입력/출력은 필요한 필드와 원문 ID를 유지하는 구조화 데이터다.

6. 번역 중심 초기 노드 카탈로그

사용자는 노드 인스턴스와 이름·설정을 생성하고 선을 연결한다. 새 기능 자체는
등록된 노드 유형으로 제공한다. 번역·검수·인물 분석을 서로 다른 고정 엔진
단계로 강제하지 않고 AI 작업 노드에 프로필과 입출력을 배정한다.

초기 유형                 최소 동작
시작/대상                 수동 실행, 단일·장면·선택 집합, 상태/라벨 필터.
프로젝트 조회             지정 범위 원문·자료·용어·문맥을 읽어 다음 노드에 전달.
AI 작업                   프로필 선택, 실제 문맥 미리보기, 구조화 출력, 오류 출구.
조건/분기                 필드·비교·값, AND/OR, 참/거짓. 대상별 또는 묶음 집계 비교.
프로젝트 행동             후보 저장·대표 선정·상태/라벨 변경·용어/자료 반영·서식 검사.
사람 확인                 원문/후보/차이/근거를 보고 선택·직접 수정·재개/보류.
묶음 처리                 개별/장면별/선택 묶음, 크기 제한, 결과 분배·다시 모으기.
HTTP 요청                 GET/POST JSON, 등록된 인증, 요청/응답 필드 매핑, 오류 출구.
체크포인트·백업           명시적 백업 또는 저장 완료 N개마다, 종료 시 잔여분 백업.

입출력 매핑은 공통 편집 기능으로 먼저 제공한다. 별도 범용 코드 노드를 만들지
않고 앞 노드 출력에서 필요한 JSON 필드를 선택하거나 상수를 넣을 수 있게 한다.
참조되지 않은 라벨·프로필 삭제, 필수 입력 누락, 출력 타입 불일치를 실행 전에 찾는다.
사람 노드에서 거절/보류하면 어느 출구로 이동하는지도 흐름에 명시한다.

후속 유형/기능
  재사용 하위 프로세스, 다중 출구 Switch, 범용 집계/변환, 스케줄·웹훅 시작,
  시간 대기, 공급자별 사전·맞춤법 프리셋, OAuth/복잡한 페이지네이션,
  Code/플러그인/MCP 사용자 확장, 서브에이전트, 분산 실행.
  기본적인 묶기·재집결·조건·유한 반복은 초기 필수이며 이 후속 목록으로 미루지 않는다.

6.1 외부 API: 사전·맞춤법 검사
  사전 조회와 맞춤법은 HTTP 요청의 저장된 설정/프리셋으로 표현한다.
  초기 요청: URL, GET/POST, query/header/JSON body, 인증 참조, timeout/응답 한도.
  초기 인증: 없음 또는 저장된 API key/header/Bearer. 비밀값은 프로세스·채팅·
  실행 로그·백업에 그대로 넣지 않는다. 기존 AI API 연결과 외부 도구 연결을 구별한다.
  HTTPS 및 기존 로컬·사설망 HTTP 정책을 재사용한다. 사용자가 저장한 접속 대상과
  요청 범위를 실행 스냅샷에 남기고 응답에서 임의 주소로 인증정보를 전달하지 않는다.
  source/target/language/term 같은 입력을 서비스 필드에 매핑하고 반환 JSON 경로를
  definitions/suggestions/issues 등에 매핑한다. unitId와 후보 버전을 항상 유지한다.
  서비스가 ID를 돌려주지 않으면 호출별 입력 대응을 보존한다. 순서가 불명확한
  배치 응답을 추측해서 원문에 붙이지 않는다.
  맞춤법 API의 교정안은 후보/지적을 반환한다. 다음 적용 노드가 있어야 본문을 바꾼다.
  외부 응답에도 보호 토큰·서식·기준 버전 검사를 적용한다.
  429/일시 오류 처리와 네트워크 재시도는 번역 수정 반복과 별도다.
  외부 쓰기 요청은 재시도 시 중복 실행 가능성을 다루는 정책이 있어야 한다.
  초기 실서비스 선택·API key 등록은 별도 설정 작업이다. 특정 유료 서비스를
  계획서 작성 중 연결하거나 호출하지 않는다. 검증은 로컬 모의 API로 한다.

6.2 100개마다 백업
  초기 기준: 해당 실행에서 대표 번역으로 저장 완료한 서로 다른 unitId의 수.
  AI 호출 수·후보 수·같은 문장의 재수정 수를 더하지 않는다. 확정 시점을 세고
  싶으면 countOn을 확정 완료로 선택한다. 기준과 현재 수는 노드에서 확인 가능하다.
  committedCount >= nextBackupAt을 검사한다. 95 → 112처럼 배치가 경계를
  넘겨도 백업한다. 단순 count % 100 == 0 조건은 사용하지 않는다.
  초기 스냅샷은 경계를 넘긴 현재 배치까지 포함한다. 정확히 100번째 상태를
  재현하는 기능으로 표기하지 않는다. 여러 경계를 한 번에 넘으면 하나의 현재
  스냅샷에 포함한 임계값을 기록한다. 종료 시 마지막 잔여분도 저장한다.
  실행 ID·unitId별 집계, nextBackupAt, 백업 요청 ID를 영속화한다.
  파일 저장 성공 후 임계값을 전진시킨다. 실패·재시작 시 같은 백업 요청을
  복구하며 중복 집계/중복 백업을 방지한다. 백업 실패는 해당 행동의 오류로 남긴다.
  동시 작업 중에도 일관된 저장 revision에서 임시 파일 작성·검증 후 최종 파일로
  확정한다. 프로젝트용 백업 경로를 사용하며 원본 게임 경로에 쓰지 않는다.
  번역/후보/상태/용어/자료/흐름 정의·버전/대기 작업/카운터를 복원할 수 있어야 한다.
  채팅·제안은 프로젝트 백업 규격에 포함하고 긴 도구 원문 등 제외 항목은 명시한다.
  인증 비밀값은 제외한다. 복원만으로 AI 호출이나 외부 행동이 자동 재시작되지 않는다.
  실행 복구용 DB 체크포인트와 사용자가 보관하는 백업 파일은 구별한다.

7. 프로세스 실행 규칙

  UI의 노드·포트·연결을 저장한 정의를 실행기가 직접 해석한다. 화면의 선과
  실제 동작이 별도 하드코딩된 순서를 따르는 구조를 만들지 않는다.
  임의 선 연결은 입력 타입·미연결 필수 포트·루프 탈출/횟수 한도를 검증한다.
  병합은 선택된 출구와 실제 도착 대상을 기준으로 한다. 실행되지 않은 배타
  분기의 결과를 영원히 기다리지 않는다. 초기에는 검증 가능한 구조의 반복만 허용한다.

  기본 템플릿
    대상 → 저장된 문맥 조회 → 초벌 후보 → 기계 검사·AI 검수 → 판정
      통과: 대표 선정·확정
      수정 필요, 한도 미만: 해당 대상 수정 → 재검수
      한도 도달/미해결: 해당 대상 사람 확인
    용어 쌍 추출 → 후보 등록, 자료 생성, 백업은 사용자가 원하는 위치에 연결한다.

  처음 초벌은 수정 횟수 0이다. 같은 run/unitId/loop에서 완료한 수정 라운드를
  별도로 센다. 세 번째 수정 뒤 재검수도 실패하면 사람 확인으로 보낸다.
  providerAttempt와 fallback 시도는 이 횟수에 더하지 않는다. 반복 한도는 설정 가능하다.
  AI 노드 성공/호출 완료와 대사별 검수 통과/프로젝트 확정은 서로 다른 결과다.

  같은 장면 30개는 한 번에 번역·검수할 수 있고 통과 27개와 수정 3개를 분리한다.
  수정 3개는 같은 노드·프로필·경로 범위·자료 버전에 맞으면 다시 묶어서 호출한다.
  수정 대상과 읽기 전용 문맥을 구분한다. 서로 호응하는 대사를 함께 수정할
  때는 시작 시 허용한 대상 안에서 저장된 규칙에 따라 다시 묶을 수 있다.
  최초 실행 대상 밖으로 쓰기 범위를 넓히려면 추가 대상과 이유를 제시하고
  사용자의 명시적 동의를 받아야 한다. 그 전에는 해당 원문을 참고로만 읽는다.
  기존 확정 대사가 수정 대상에 다시 들어가면 기준 버전과 검수 상태를 재검사한다.
  알려진 배타 경로를 하나의 실제 사건처럼 합치지 않는다. 미확정 순서는 사실화하지 않는다.
  긴 장면은 입력뿐 아니라 예상 출력 크기를 고려해 나눈다. 번역 결과는 unitId로 대응한다.
  누락·중복·알 수 없는 ID 등 구조 오류는 추측해 저장하지 않는다. 배치를 검증한 뒤
  대사별 품질 문제/잠금/버전 충돌을 분리하여 올바른 대상만 후속 단계로 보낸다.

  독립적인 묶음은 연결별 동시 실행 한도 내에서 처리할 수 있다. 공유 후보·자료
  쓰기는 버전/트랜잭션으로 보호하고 선행 결과에 의존하는 노드는 기다린다.
  일시정지 시 현재 호출의 처리 정책을 표시하고 다음 단계 실행을 멈춘다.
  취소는 이후 작업을 막고 완료 기록을 보존한다. 재시작·사람 대기·재개 위치를 저장한다.
  완료되지 않은 외부 호출의 결과가 불확실하면 성공으로 기록하거나 무조건 재호출하지 않는다.
  노드 클릭으로 입력·출력·사용 문맥·변경점·분기 사유·대상별 이력을 확인한다.
  실행 중 강조는 실제 worker 기록에 연결하고 화면 폴링이 방문 이력을 만들지 않는다.

8. 작품 자료·용어·문맥

  기본 문맥은 선택 원문, 사용자가 정한 주변 범위, 등록된 용어/프로필/관련 자료다.
  저장 자료 조회 자체와 AI로 새 자료를 생성하는 호출을 구분한다.
  초기에는 원문 ID·화자/명시 연결·이름/키워드 조회를 활용한다. 모든 관련 단서가
  발견되는 의미 검색이나 완전한 지식 그래프를 초기 번역의 전제로 삼지 않는다.
  자료에는 본문, 근거 원문/웹 출처, 관련 인물·자료, 적용 범위, 확인/주장/추정,
  버전과 생성 이력을 담는다. 알려지지 않은 시점·인물 인지는 미확인으로 남긴다.
  번역자 참고와 등장인물/플레이어가 아는 정보를 구별한다. 원문의 review order는
  서사 시계가 아니다. 웹에서 가져온 다른 편·다른 버전의 정보를 자동 합치지 않는다.
  자료를 무조건 추가하는 대신 기존 대상 항목을 지정해 수정안을 만들 수 있다.
  자동 의미 병합·전체 인물 동일성 해결·분기 기억 시뮬레이션은 후속 범위다.
  모델의 미해결 질문 출력은 지원하되 빈 질문 목록을 문맥 완전성의 증거로 쓰지 않는다.
  조사 노드가 없으면 조사 호출을 추가하지 않고 필요한 질문을 검토 대상으로 남긴다.

  용어 추출은 원문과 대응 번역문 쌍을 사용한다. 실제 번역문에서 근거를 갖는
  용어 쌍을 후보로 등록하고 default·다른 번역·사용 방향·근거를 보관한다.
  특정 후보 제거/변경은 그 candidateId/버전을 사용한 번역을 대상으로 삼는다.
  번역을 지우지 않고 갱신 필요로 표시한다. 사용 정보가 불완전하면 영향 후보로
  구분하며 무관한 사용처까지 확정 소비자로 취급하지 않는다.
  새 용어 추가와 기존 용어 변경을 구분한다. 재검토 대상 등록은 가능하지만
  자동 AI 재검토는 설정한 프로세스/시작 규칙이 있을 때만 수행한다.
  채팅에서 수락한 자료와 실행에서 정책에 따라 적용한 자료를 동일 저장소에서 조회한다.

9. 구현 경계와 마이그레이션

  packages/contracts: 고정 Stage 프로필 참조를 ID/버전 프로필로 확장하고
  사용자 상태/라벨, 후보, workflow/run/item, chat/proposal, tool/API/backup,
  Character/Relationship/EvidenceReference 계약과 버전 마이그레이션 추가.
  packages/core: 변경 계획/적용 경계, 프로젝트 조회 도구, 그래프 실행기,
  대사별 판정/수정 카운터, 후보·영향 추적, 승인·복구·백업 구현.
  packages/providers: 기존 구조화 번역 호출을 보존하고 chat/tool-call 인터페이스,
  능력 검사, 스트리밍/취소와 도구 요청 검증 추가. 도구 미지원 연결은 명시한다.
  apps/worker: 프로젝트/세션/제안/흐름/실행 API, 도구 실행, 이벤트/진행 전달,
  HTTP·검색 서비스 연결. 대화 본문을 매번 전체 상태 폴링에 싣지 않는다.
  apps/web: 공통 Canvas와 의미 모양, 채팅·제안 상세, 프로필/흐름 편집,
  라벨·후보·실행 탐색, navigation 상태 복원.
  packages/adapters: 원본 ID/조건·간선 보존, 장면 축약의 근거 연결을 개선.
  추출 근거 없이 빠진 의미를 채우거나 원본 파일을 수정하지 않는다.

  저장소는 현재 프로젝트 상태를 SQLite JSON으로 보관한다. chat/tool trace와
  실행 이벤트가 커지므로 append/read pagination 경계를 설계한다. 새 테이블이
  필요하면 버전 마이그레이션과 archive/restore를 함께 작성한다.
  기존 stage 프로필은 이름/ID가 있는 초기 프로필로 복사한다. 기존 번역 상태는
  호환 역할로 매핑한다. checked를 사람이 승인했다는 이력으로 꾸미지 않는다.
  기존 번역은 현재 대표 후보로 옮기고 원래 이력·잠금·출처·용어 사용을 보존한다.
  기존 실행은 역사적 기록으로 남긴다. 진행/대기 중 실행을 새 정의로 무음 변환하지 않는다.
  백업·복원은 새 필드를 명시적으로 지원한다. 프로필/흐름은 비밀값 없는 정의를
  포함하고 연결은 참조로 복원한다. 인물·관계·근거 참조도 백업/복원 필드에
  포함하여 고아 참조가 남지 않게 한다. 기존 백업도 읽을 수 있게 한다.
  마이그레이션 전 복사본/백업과 ID·원문·번역·이력 비교로 검증한다.

10. 개발 순서와 완료 기준

M0. 계약·여정·데이터 보존 기반
  새 데이터 계약, 작은 3장면 모의 작품, 변경 적용의 출처별 권한 경계,
  백업/마이그레이션 설계와 불변식 검증. 코드 작성 전에 UX_FLOW_PLAN의 여정을 확인한다.
  완료: 기존 데이터 복사본을 새 형식으로 읽고 복원해도 원문·번역·이력 손실 없음.

M1. 원문 그래프 통일
  공통 D3 Canvas, 의미별 형태, 방향 배치·장면 축약·검색·탐색 상태 보존.
  완료: 작은 그래프부터 실제 규모까지 React Flow 없이 전체 탐색과 성능 여정 통과.

M2. 채팅으로 자료를 만드는 한 흐름
  공통 조회/변경 도구, 세션, 웹 ON/OFF, 도구 호출·제한·중지, 제안 승인/피드백,
  작품 자료 생성·수정·이력, 인물/관계 레코드와 그래프·선택 상세.
  실행 현황 조회도 실제 데이터로 연결. 작품 설명과 근거는 문서/인용 목록으로 제공.
  완료: 조사 → 초안 → 피드백 → 수락 → 자료에서 확인 → 다른 세션에서 조회.
  인물/관계 제안 수락 후 그래프에서 탐색하고 관계 근거를 열어 되돌아올 수 있다.
  거절/미승인/웹 OFF/다른 프로젝트/오래된 제안의 부작용 차단도 확인한다.

M3. 최소 번역 흐름 실행기
  사용자 프로필·상태/라벨·후보, 시작/조회/AI/조건/행동/사람/묶음 유형.
  저장한 정의에서 초벌 → 검수 → 수정/확정 실행. 초기 모의 세트로 끝까지 완주.
  완료: 장면 묶음 유지, 대사별 분기, 수정 한도, 동료 대상 계속 진행, 재시작 복구.

M4. 프로세스 편집 UI와 실행 연결
  같은 Canvas 기반으로 노드 추가/이동/연결, 입출력 매핑, 설정 패널, 검사,
  프로필 시험, 실제 실행 노드 표시와 변경 이력. 단순히 그려진 선으로 끝내지 않는다.
  완료: 사용자가 선이나 조건을 바꾸면 저장된 정의·실제 경로·기록이 일치한다.
  모의 시험은 프로젝트 본문에 반영하지 않으며 실제 실행과 분리한다.

M5. 외부 API와 백업 — 1차 개편의 마지막 필수 확장
  최소 HTTP 요청/응답 매핑, 로컬 사전·맞춤법 모의 API, 100개마다 백업.
  완료: API 결과가 올바른 원문에 연결되고 변경은 적용 단계에서만 일어남.
  임계값 건너뛰기·실패·재시작·잔여분·복원에서 누락/중복/비밀 노출 없음.

M6. 통합 여정과 릴리스 검사
  M0~M5의 작은 작품 전체 여정, 기존 프로젝트 보존, 뒤로가기/새로고침,
  큰 그래프 실측. 모의·실제 서비스 확인 여부를 구별한 결과 보고.
  실제 모델/외부 유료 API 호출은 사용자가 범위와 실행을 정한 뒤 소량으로 검증한다.
  모든 구현이 끝날 때까지 실사용을 막지 않는다. M2는 자료 준비에, M3~M4는
  작은 번역에 사용할 수 있다. 아직 없는 노드/도구를 작동하는 것처럼 노출하지 않는다.

후속: 재사용 하위 프로세스, 더 많은 API 인증/프리셋, 선택형 반복 조사,
문맥 관련성 평가, 관계·단서 병합, 서브에이전트·사용자 코드 확장.
RAG/GraphRAG, 전체 자동 분석, 웹 기반 무제한 탐색은 선행 의존성이 아니다.

11. 핵심 검증 사례

T01. 3장면: 분기/합류/순환/고립 원문과 문서 열람 연결, 조건·대기·이벤트 형태.
T02. 전체 검색 → 화면 밖 노드 → 상세/읽기 → Back/Forward/새로고침 상태 복원.
T03. 약 1만 노드 원본 범위의 ID·간선 보존과 전체 맞춤/확대 상태 실제 반응 측정.
T04. 프로젝트 A 세션 1/2 → B → A에서 대화·입력·첨부·미승인 초안 분리.
T05. 웹 OFF 도구 호출 0회, ON은 출처/범위/중지 기록. 저장 웹 자료와 새 요청 구별.
T06. 초안 생성/거절은 본문 불변. 피드백은 새 제안. 수락은 한 번만 반영.
T07. 수락 전 원문/자료/용어/번역 수정 시 오래된 제안 차단·현재 차이 확인.
T08. 채팅 승인 없이 내부 API·간접 용어 재검토가 실행되지 않음. 시작한 흐름의
     자동 반영은 반복 승인 없이 수행하며 사람 노드만 설정된 대상에서 대기.
T09. 장면 30개 한 묶음 중 27개 통과·3개 수정. 3개만 다시 묶이며 원문 ID 유지.
T10. 누락/중복 ID, 잠금, 기준 버전 충돌, 서식 토큰 손상, 배타 경로의 섞임 처리.
     승인된 실행 대상 밖의 원문은 추가 동의 없이 수정되지 않음.
T11. 수정 3라운드 후 사람 대기. 네트워크 retry/fallback은 수정 횟수에 영향 없음.
T12. 사람 대기·취소·worker 재시작 후 결과 보존과 재개 위치/설정 버전 유지.
T13. 같은 원어의 A/B 번역 후보 중 A 제거 시 A 사용처만 확정 영향으로 처리.
T14. HTTP 응답 필드 매핑·ID 대응·지연/429/잘못된 JSON·수정안 비자동 적용.
T15. 백업 집계 95→112, 한 번에 여러 임계값, 같은 대사 재수정, 쓰기 실패 후
     재시작, 종료 잔여분, 백업 복원. 각 파일의 실제 포함 revision을 확인.
T16. 새 후보·프로필·라벨·흐름·채팅·제안을 포함한 백업과 구버전 백업 호환.
T17. 실제 흐름 그래프를 편집해 다른 분기로 실행하고 노드별 입력/출력/변경 확인.
T18. 인물 A/B와 관계 초안은 승인 전 그래프에 확정 자료로 표시되지 않음.
     수락 후 노드/연결선 상세에서 같은 자료 버전과 근거를 열 수 있음.
     분기에 따라 다른 관계, 별칭, 고립 인물, 근거 원문 왕복과 뒤로가기를 확인.

검증은 임시 DB·모의 모델·로컬 모의 API·읽기 전용 원본으로 시작한다.
모델 번역 품질 평가와 실행 하네스 검증을 구분한다. 타입 검사/빌드 통과만으로
사용자 여정이나 실제 서비스 지원을 검증했다고 쓰지 않는다.
이번 문서 작성에서는 위 테스트를 실행하거나 기능 구현 완료를 선언하지 않는다.
