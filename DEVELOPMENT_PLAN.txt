AI가 번역 프로젝트의 대부분을 수행하고, 사용자는 UI에서 방향을 정하고
결과와 쟁점을 확인하는 로컬 번역 작업실을 만든다. 작품 전체의 의미를 먼저
파악하고, 장면과 대화의 연결을 따라 번역하며, 용어·설정 변경의 영향을
추적하여 필요한 부분을 다시 수정한다. 작은 실제 번역 묶음부터 사용하면서
확장한다. 시스템 구축 완료를 기다리느라 번역 착수를 무기한 미루지 않는다.

1. 합의한 제품 방향과 범위

확정된 방향
  R01. AI가 자료 정리, 번역, 검수, 재검토, 작업 진행 관리를 기본 수행한다.
       사용자가 문장마다 자료를 붙여 넣고 실행 버튼을 누르는 흐름을 요구하지 않는다.
  R02. 직관적인 UI를 첫 구현부터 포함한다. 번역 본문과 근거를 읽고 수정할 수 있다.
  R03. 씬 → 대화 묶음 → 대사의 연결·순서를 활용한다. 문서는 관련 장면과 연결한다.
  R04. 작품 전체를 먼저 분석하여 복선과 후반 맥락을 활용하되, 등장인물과 플레이어가
       그 시점에 아는 정보는 별도로 구분한다.
  R05. 용어집, 줄거리, 배경설정, 인물 프로필, 말투, 호칭, 관계를 관리한다.
  R06. 용어 페이지에서 연결된 스크립트를 찾고, 용어 변경 시 영향을 받은 번역을
       재검토 대상으로 올린다. AI가 재검토와 수정을 이어서 수행한다.
  R07. 원문·번역·작품 자료·작업 이력을 분리하고, 사람의 수정과 잠금을 보호한다.
  R08. 모노레포 안에 UI, 실행부, 공유 데이터 형식과 번역 규칙을 함께 관리한다.
  R09. 게임별 추출기는 외부 단계다. 표준 입력을 만드는 변환기를 경계로 연결한다.
       현재 Orwell 추출본은 첫 지원 사례이며 그 파일 구조 전체가 표준은 아니다.
  R10. 단일 모델로 시작할 수 있어야 한다. 등장인물별 역할극이나 다중 에이전트
       토론을 필수 실행 조건으로 두지 않는다.

초기 개발의 경계
  - 우선 사용 환경은 현재 사용자의 Windows 로컬 작업 환경이다.
  - 초기 언어쌍은 영어 → 한국어이며 데이터에는 언어 식별자를 명시한다.
  - 단일 사용자와 하나의 로컬 작업실을 우선 지원한다.
  - 코드의 모노레포와 실제 게임·번역 프로젝트 데이터의 저장 위치를 분리한다.
  - 원본 게임 수정, 새 게임의 리버스 엔지니어링, DLL 후킹·폰트 교체·패치 배포는
    별도 작업이다. 작업실은 적용 도구에 전달할 번역과 원문 매핑을 내보낸다.
  - 모든 게임의 실행 규칙을 재현하는 엔진, 모든 분기의 완전한 인물 심리
    시뮬레이션, 협업 서버·권한 체계, 클라우드 배포는 초기 필수 범위에서 제외한다.

2. UI와 주요 사용 흐름

2.1 작업실
  왼쪽: 작품의 장면·대화·문서 목록, 작업 상태, 현재 위치.
  가운데: 화자와 흐름이 보이는 원문·번역 본문. 대화 단위로 연속해서 읽는다.
  오른쪽: 선택한 대사의 용어, 인물·관계, 관련 사건·문서, 근거, 검수 지적.
  상단: 현재 AI 작업, 처리 범위, 진행 상황, 일시정지·재개·취소.

  첫 화면은 마지막 작업 위치를 복원하고, 판단이 필요한 항목과 AI 진행 상태를
  함께 보여준다. 원문·번역 나란히 보기와 번역 중심 읽기를 지원한다.
  변경 비교는 단어나 구절 중심으로 읽을 수 있게 한다. 분기와 그 적용 조건은
  해당 장면에서 펼쳐 볼 수 있으며, 검토용 순서와 확정된 선후관계를 구분한다.
  AI 지시창은 선택한 작품·장면·번역 항목을 문맥으로 받아 작업을 생성한다.
  전체 채팅 이력을 읽어야 번역 상태를 알 수 있는 구조로 만들지 않는다.

2.2 검토함
  용어 변경, 의미 해석 불확실, 정보 공개 문제, 수동 수정과의 충돌, 원문 변경,
  검수 실패를 작업 가능한 목록으로 모은다.
  각 항목은 원문·현재 번역·수정안·이유·근거·영향 범위를 함께 보여준다.
  수정안 채택, 직접 수정, 다시 AI에 맡기기, 보류, 근거를 남긴 예외 처리를 지원한다.
  모든 AI 결과를 사람이 하나씩 승인하도록 강제하지 않는다. 자동 처리 정책을
  만족하는 결과는 저장·검수하고, 쟁점이 있는 항목만 검토함으로 보낸다.

2.3 작품 자료실
  용어, 등장인물, 관계, 사건, 배경설정, 장면 요약, 번역 기준을 탐색·편집한다.
  자료의 설명만 보여주지 않고 그 자료가 사용된 대사·문서와 근거 발췌를 연결한다.
  인물 자료에는 상대별 호칭·존댓말·말투와 변화 시점, 대표 원문·번역을 포함한다.
  수정 시 사용처와 예상 영향이 표시되고, 저장된 변경은 재검토 작업으로 이어진다.

2.4 보조 화면
  실행 이력: 작업 단계, 입력 버전, 결과, 오류, 호출량·비용, 재개 위치.
  설정: 모델 연결, 자동 처리 정책, 작업 범위, 비용 상한, 내보내기 설정.
  연결 보기: 현재 장면이나 용어와 관련된 그래프. 전체 그래프는 필요할 때 연다.
  근거 영역에는 원문 인용과 짧은 검토 사유를 보여주며 모델의 내부 사고 기록을
  요구하거나 사실 확인의 근거로 취급하지 않는다.

UI 레퍼런스의 적용 범위
  - Cursor Agents Window: AI 작업 지시, 작업 목록, 생성된 변경의 검토.
  - Scrivener: 장면별 긴 본문 읽기와 원고 옆 참고 자료.
  - Obsidian Backlinks: 용어·인물 자료에서 연결된 스크립트와 문맥으로 이동.
  - Linear Triage: 판단할 항목의 처리·보류·관련 항목 연결.
  이들은 기능과 탐색 방식의 참고다. 특정 제품의 화면 전체를 그대로 복제하지 않는다.

3. AI의 기본 작업 흐름

  1) 입력 검사와 작업 범위 설정
     원문·언어·ID·참조를 검사하고 본편, 공용 UI, 테스트, 다른 언어를 구분한다.
     사용자가 정한 범위 안에서 AI가 이후의 작업 묶음을 선택한다.

  2) 작품 전체 선행 분석
     선택한 작품 범위를 나누어 읽고, 작품 개요·사건·용어·인물·관계 후보를 만든다.
     후보마다 원문 근거와 적용 범위, 불확실성을 남긴다. 분석 범위와 미처리 구간을
     기록하며, 일부만 읽은 상태를 전체 작품 파악 완료로 표시하지 않는다.
     긴 작품은 부분 분석 후 통합한다. 요약에서 원문으로 돌아갈 수 있어야 한다.

  3) 번역 기준 초안 작성
     표기, 호칭, 인물별 말투, 반복 표현, 문서·UI의 문체를 정리한다.
     AI가 임시 기준을 작성하고 진행할 수 있다. 모든 용어 후보를 사람의 사전 승인
     대기로 만들지 않으며, 영향이 큰 충돌은 검토함에 모은다.

  4) 장면과 대화의 작업 순서 구성
     주어진 순서·연결을 이용해 읽기와 번역 순서를 정한다.
     병렬·미확정 구간은 그렇게 표시하고, 분기는 별도의 문맥을 가진 작업으로 처리한다.

  5) 번역용 문맥 준비
     현재 장면 전체, 앞뒤 대사, 관련 문서, 인물·관계, 용어, 기존 확정 번역,
     필요한 후반 장면을 묶는다. 대상 원문과 참고용 원문을 구분한다.
     사용한 자료의 ID·버전을 저장하며 UI에서 해당 자료로 이동할 수 있게 한다.

  6) 번역
     대화 묶음을 함께 보면서 순서를 유지해 번역한다. 말의 주고받음과 감정 흐름에
     맞춰 묶음 안의 앞 대사도 다듬을 수 있다. 긴 묶음을 나눌 때는 앞뒤 문맥을
     겹쳐 제공하되, 각 요청이 번역할 원문 ID의 범위를 명시한다.

  7) 검수와 제한된 수정
     기계 검사 후 의미·호칭·말투·정보 공개·관련 문서와의 일관성을 검수한다.
     수정 횟수와 비용을 제한하고, 계속 실패하거나 해석이 충돌하면 쟁점으로 남긴다.

  8) 결과 반영
     입력 버전이 유효하고 적용 정책을 만족하면 결과를 저장한다.
     잠긴 번역, 동시 수정 충돌, 해결되지 않은 쟁점은 기존 번역을 유지하고 수정안이나
     검토 항목을 남긴다. 모델의 자기평가 점수만으로 확정 여부를 결정하지 않는다.

  9) 다음 묶음 진행과 전체 검토
     작업 상태를 저장하고 다음 묶음으로 넘어간다. 장·작품 단위로 용어, 말투,
     반복 인용과 누락을 다시 점검한다. 개별 문장 검수와 작품 전체 검수는 구분한다.

4. 작품 지식, 분기와 정보 공개

지식은 세 관점으로 구분한다.
  - 번역자 관점: 작품 전체의 사실, 후반의 반전, 복선이 회수되는 의미.
  - 등장인물 관점: 해당 시점·경로에서 경험했거나 전달받은 사실, 믿음과 오해.
  - 플레이어 관점: 그 시점까지 공개된 정보와 아직 모호해야 하는 내용.

번역자는 후반의 진실을 참고할 수 있다. 그 지식을 등장인물의 현재 지식으로
간주하거나 원문보다 먼저 번역문에 드러내서는 안 된다. 예를 들어 후반에 뜻이
밝혀지는 모호한 표현은 그 의미를 이해하면서 초반의 모호함을 보존한다.

각 사건·설정에는 다음을 기록한다.
  근거 원문 ID, 사실/믿음/발언/추정 구분, 관련 인물, 적용 분기·시점,
  알려진 관찰자·수신자, 확정 여부, 충돌하는 근거, 자료 버전.
AI의 해석과 검토 대화는 자동으로 작품의 사실이 되지 않는다.

분기와 순서 규칙
  - 공통 사실과 특정 경로에서만 발생하는 사건을 분리한다.
  - 서로 배타적인 경로가 합류했다고 두 경로의 기억을 합치지 않는다.
  - 같은 노드를 다시 방문하는 것과 새 사건이 발생하는 것을 구분한다.
  - 순환·병렬 구간과 알 수 없는 조건을 억지로 하나의 재생 순서로 확정하지 않는다.
  - 현재 Orwell의 review_rank는 정적 검토 순서다. 실제 사건 발생 시간이나
    인물의 지식 획득 순서로 그대로 사용하지 않는다.
  - 초기 버전은 주어진 분기 조건과 필요한 경로 선택을 이용한다. 완전한 실행기
    없이 판단할 수 없는 조건은 미확정으로 남기고 UI에 표시한다.

초기 체크포인트는 작업을 재현하기 위한 저장점이다.
  현재 장면·작업, 경로/조건 선택, 입력·자료·용어집 버전, 번역 결과 버전,
  사용한 문맥, 모델·프롬프트 설정, 완료·대기 작업을 저장한다.
저장된 결과를 그대로 복원하는 동작과 새 모델 호출로 다시 실행하는 동작을 구분한다.
재실행은 같은 번역문이 나온다는 보장이 없으며 별도 결과 버전으로 기록한다.

5. 용어집과 변경 영향 처리

5.1 용어 데이터와 사용처
  용어는 고유 ID, 원어·별칭, 의미, 권장 번역, 허용·금지 표현, 적용 범위,
  근거, 결정 사유, 후보/임시/확정 상태, 버전을 가진다.
  같은 철자의 다른 의미는 다른 용어 항목으로 구분할 수 있어야 한다.
  표면 문자열이 같다는 이유만으로 모든 사용처를 확정 연결하지 않는다.

  사용처에는 원문 ID와 등장 위치, 장면·문서, 문맥 발췌, 연결 근거를 저장한다.
  명시적으로 연결된 사용처와 검색/AI가 제안한 후보를 구분한다.
  한국어 조사·활용·별칭을 고려하며 사람이 예외를 기록할 수 있다.
  입력이 갱신되거나 별칭·범위가 바뀌면 기존 연결 외의 새 후보도 검색한다.

5.2 용어 페이지
  상단: 정의, 권장 번역, 상태, 적용 범위, 최근 변경.
  사용처 목록: 장면/문서, 원문, 현재 번역, 사용 부분 강조, 검토 상태.
  항목을 선택하면 해당 대화·문서의 앞뒤 문맥으로 이동한다.
  변경 저장 시 영향받는 사용처와 AI 재검토 작업의 진행 상태를 보여준다.

5.3 변경 종류별 처리
  - 권장 번역 변경: 기존 사용처의 번역 재검토.
  - 의미·적용 범위 변경: 해당 용어를 적용하는 것이 맞는지부터 재검토.
  - 별칭 추가/수정: 기존 연결 점검과 새 사용처 검색.
  - 허용·금지 표현 변경: 현재 번역의 일치/위반 여부 재검사.
  - 단순 관리 메모 변경: 내용 해석에 영향이 없는 변경이면 재번역 없이 이력 저장.

5.4 변경 후 자동 흐름
  용어 버전 갱신 → 사용처 영향 분석 → 갱신 필요 표시 → 작업 큐 등록
  → AI 문맥 확인·수정·검수 → 버전 충돌 확인 → 결과 반영 또는 검토함 이동.

  완료된 번역도 '용어 갱신 필요' 상태가 될 수 있다. 기존 번역을 지우거나
  미번역 상태로 되돌리지 않는다. 번역 단계와 자료의 최신 여부는 별도 상태다.
  각 결과는 검토에 사용한 용어 버전을 기록한다.
  AI는 영향받은 표현과 필요한 주변 문장을 수정하며 관련 없는 문장을 무작정 다시 쓰지 않는다.
  원문 ID, 문서 링크 대상, 내부 식별자, 보호 토큰은 용어 변경 대상으로 취급하지 않는다.
  수정이 필요 없는 사용처에는 사유를 남기고 새 버전에서도 유효한 예외인지 검토한다.

  짧은 시간에 여러 변경이 발생하면 같은 항목의 작업을 합치거나 이전 작업을
  새 버전에 의해 대체된 것으로 표시한다. 오래된 버전의 결과는 최신 번역에 적용하지 않는다.
  UI에서 영향 없음, 대기, 처리 중, 반영 완료, 판단 필요, 예외 유지, 실패를 구분한다.

5.5 다른 자료로 확장
  같은 구조를 인물의 말투·호칭·관계·설정 변경에도 적용한다.
  예: A가 B에게 특정 사건 이후 반말을 쓰도록 기준이 바뀌면 인물 조합과 적용
  시점에 해당하는 대사만 재검토한다. 판단할 수 없는 시점은 검토 항목으로 남긴다.

6. 번역 편집, 검수와 사람이 정한 기준

번역 상태는 다음을 별도로 관리한다.
  - 작업 단계: 미번역 / 초안 / 검수 완료 / 확정.
  - 최신 여부: 최신 / 자료 변경으로 재검토 필요 / 원문 변경 / 버전 충돌.
  - 편집 보호: 자동 반영 가능 / 사람 잠금.
  - 확정 근거: AI 정책에 따른 확정 / 사람 확정, 관련 검수·결정 기록.

사람의 직접 수정도 버전과 이력을 남긴다. 수정 이유를 번역 기준으로 일반화할
후보를 AI가 만들 수 있지만, 한 문장의 예외를 자동으로 모든 장면에 확장하지 않는다.
적용 인물·상대·시점·작품 범위를 기록한다. 잠긴 번역도 재검토 대상에 올릴 수 있으나
AI는 현재 값을 덮어쓰지 않고 변경안과 영향만 제시한다.

기계적 검사
  원문 ID 누락·중복, 대상 밖 항목 생성, 빈 결과, 자리표시자, 서식 태그,
  링크 대상, 보호 문자열, 설정된 줄 수·길이 제한을 검사한다.
  문장부호·줄바꿈은 원문과 무조건 동일하도록 강제하지 않고 프로젝트의 서식 규칙을 따른다.
  실제 게임의 글자 넘침은 문자 수만으로 확정하지 않는다. 화면 자료와 후속 적용 검증으로 연결한다.

언어·문맥 검사
  의미 누락·첨가, 부정·수치·지시 대상, 호칭·존댓말, 인물 말투, 용어,
  의도적인 거짓말·모순·중의성·정보 공개 시점, 문서와 인용 대사의 대응을 확인한다.
  같은 원문에 다른 번역이 있다는 사실 자체를 오류로 확정하지 않는다.
  각 지적에는 대상 범위와 근거, 수정 제안 또는 불확실 사유를 남긴다.

자동 수정은 횟수와 범위를 제한한다. 의미 해석이 불확실한 항목은 근거 없는
수정을 반복하지 않고 보류할 수 있으며 독립적인 다음 작업은 계속 진행한다.

7. 표준 입력과 게임별 변환기

표준 입력은 게임 내부 구현을 몰라도 번역할 수 있는 최소 정보부터 정의한다.
schema_version을 두고 초기 버전은 0.1로 시작한다. 의미 있는 변경에는
호환 규칙이나 변환 절차를 남긴다. ID는 프로젝트 범위에서 고유한 문자열이다.

기본 개체
  ProjectManifest
    프로젝트·작품 식별자, 입력 버전, 원어·번역어, 파일 목록, 지원 기능, 추출 출처.
  SourceUnit
    원문 ID, 원문 그대로의 텍스트, 종류, 언어, 원문 해시, 불투명한 원본 위치 정보.
  Group
    장/씬/대화/문서/UI 묶음, 제목, 포함 항목, 상위 묶음과 참조 관계.
  Occurrence
    원문이 사용되는 위치, 소속 묶음, 화자·청자, 해당 사용처의 문맥·조건.
  Relation
    앞뒤 연결, 대화 시작, 분기, 참조·인용 등 관계의 종류, 조건, 근거와 신뢰 구분.
  Constraints
    보호 토큰·태그·링크와 알려진 표시 제약. 알 수 없는 정보는 미확정으로 보존.

원칙
  - 원문 하나는 기준 저장소에 한 번 저장하고, 여러 보기와 사용처에서 ID로 참조한다.
  - 서로 다른 원본 ID의 문장이 같아도 자동으로 하나로 합치지 않는다.
  - 화자·분기·그래프가 없는 자료도 가져올 수 있어야 한다.
  - 원본 순서, 그래프에서 만든 검토 순서, 수동 확정한 순서를 구분한다.
  - 관계의 누락과 불확실성을 표현할 수 있어야 한다.
  - 게임별 파일/pathID/메서드 등은 source_ref에 보존하고 공통 번역 규칙이 직접 해석하지 않는다.
  - 출처와 서식은 가져오기·내보내기 과정에서 검증한다. 원본 파일에는 쓰지 않는다.

같은 원문 ID가 여러 경로에서 재사용되는 경우
  사용처별 문맥은 보존하지만, 대상 게임이 하나의 번역만 받으면 여러 경로에
  맞는 번역을 선택해야 한다. 문맥별 번역이 필요한 충돌은 UI에 표시한다.
  변환기/적용기가 명시적으로 지원할 때만 사용처별 번역 변형을 내보낸다.
  초기 작업실이 새로운 런타임 분기 패치 기능을 암묵적으로 제공하지 않는다.

현재 Orwell 입력의 연결 계획
  ../extracted/catalog.jsonl
    원문 ID·언어·원문·토큰·출처의 입력. 직접 편집용 번역 저장소로 사용하지 않는다.
  ../extracted/scenes/ 및 ../extracted/documents/
    대화·문서 묶음, 연결과 읽기 순서. 같은 record_id의 중복 보기는 참조로 통합한다.
  ../analysis/scenes/document_references.json
    문서와 장면의 연결 근거.
  ../analysis/binary/
    하드코딩 문자열의 별도 입력 경로. 원시 문자열 전체를 사용자 표시문으로
    확정하지 않고 검토 후보와 사용처를 구분한다. 번역 ID와 원본 위치 매핑을 보존한다.
  ../analysis/season1_overlap/ 및 ../orwell_1_reorder/
    기존 번역 후보와 문맥의 참조 자료. 동일 원문이라는 이유만으로 자동 확정하지 않는다.

현재 2편 카탈로그는 9,400개 후보이며 영어 8,157개, 독일어 288개,
언어 미확정 955개를 포함한다. 전체를 본편 영어 대사 수로 해석하지 않는다.
1편 대조에서는 정확히 일치하는 원문에도 이전 번역이 복수인 현재 항목 112개가
확인되었다. 재사용 후보에는 이전 작품·사용처·번역 출처를 함께 표시한다.

8. 저장 데이터와 변경 이력

공통 코어가 관리할 주요 데이터
  - 프로젝트, 원문 스냅샷, 묶음, 사용처, 연결.
  - 용어/용어 버전/사용처 연결, 인물/관계/설정/사건/번역 기준과 버전.
  - 번역/번역 버전, 검수 결과, 수동 잠금, 예외·결정 사유.
  - 문맥 묶음: 사용한 원문과 자료 ID·버전, 적용 경로와 정보 공개 구분.
  - 실행, 작업, 단계별 결과, 체크포인트, 호출 기록, 영향 분석 결과, 검토 항목.
  - 원본 식별자와 내보내기 대상의 대응, 내보내기 기록.

번역과 작업 상태의 기준 저장소는 하나로 둔다. UI와 worker가 각각 독립된
JSON 파일을 수정하며 동기화하는 구조를 피한다. 내보낸 JSON은 명시적인
가져오기 절차를 거치지 않는 한 기준 저장소를 대신하지 않는다.

수정 이력에는 변경 전후, 수행 주체, 사유, 사용한 입력·기준 버전을 남긴다.
되돌리기도 기록되는 새 변경이며 과거 이력을 지우지 않는다. 자료를 되돌리면
그 변경에 대한 영향 분석도 수행한다.

재추출 입력은 새 스냅샷으로 가져온다. ID·출처·원문 해시를 대조해 기존 번역을
이어 붙이고, 원문 변경·삭제·매칭 충돌을 구분한다. 파일 위치 기반 ID가 게임
버전 사이에서도 항상 유지된다고 가정하지 않는다.

9. 장시간 작업, 동시 수정과 비용

worker는 브라우저와 별도로 실행한다. UI 새로고침·종료가 작업을 취소하지 않는다.
worker나 컴퓨터가 종료되면 작업은 멈추며, 다음 실행에서 저장된 상태로 복구한다.

작업에는 다음을 기록한다.
  실행 ID, 대상 묶음/원문, 단계, 상태, 시도 횟수, 작업 시작 입력 버전,
  용어·프로필·프롬프트·모델 설정, 결과 위치, 오류, 사용량, 중단·재개 정보.

  - 일시정지: 새 작업 시작을 멈춘다. 진행 중 요청은 가능한 범위에서 마무리하거나
    중단하고, 결과와 상태를 저장한 뒤 재개 지점을 만든다.
  - 취소: 남은 작업을 취소한다. 완료된 번역과 이력은 보존한다. 늦게 돌아온 응답의
    적용 여부를 실행 상태로 확인하고 취소된 작업에 자동 반영하지 않는다.
  - 재개: 입력 버전을 다시 확인한다. 바뀐 문맥에 의존하는 작업은 이전 결과를
    그대로 적용하지 않고 최신 자료로 재검토한다.
  - 실패 복구: 오류 원인을 분류하고 일시적 실패만 제한적으로 재시도한다.
    반복 실행되더라도 번역 적용과 검토 항목 생성이 중복되지 않게 한다.

사람이 편집하는 동안 실행된 AI 결과에는 낙관적 버전 검사를 적용한다.
작업 시작 시 번역 버전이나 의존 자료가 현재 값과 다르면 직접 덮어쓰지 않고
오래된 결과로 분리하여 재검토한다. 적용 직전 검사와 저장은 하나의 트랜잭션으로 처리한다.

토큰·호출·비용과 재시도 횟수에 상한을 둔다. 상한 도달 시 결과를 보존하고
이유를 표시한다. 모델 응답이 토큰 제한으로 잘린 경우 완료 번역으로 처리하지 않는다.
현재 처리 대상, 완료 범위, 실패와 대기 사유를 보여주며 근거 없는 완료율·예상 시간을 만들지 않는다.

10. 모노레포와 모듈 책임

예정 구조

  translation_workbench/
    apps/
      web/             UI와 로컬 API
      worker/          AI 작업 실행, 재개, 진행 이벤트
    packages/
      contracts/       표준 입력, 작업·결과·이벤트 형식과 검증
      core/            번역·자료·영향 분석·저장 규칙
    adapters/
      orwell/          기존 추출본을 공통 입력으로 변환
    tests/
      fixtures/        작은 검증용 데이터
    docs/              결정 기록과 사용 안내

  위 디렉터리는 개발 시 구성한다. 이 계획 작성 단계에서 애플리케이션 골격이나
  의존성을 생성했다는 뜻은 아니다.

의존 방향
  web / worker / adapters → core 또는 contracts
  core → contracts
  contracts는 UI·게임 엔진·모델 공급자에 의존하지 않는다.

게임별 조건을 화면이나 AI 프롬프트 곳곳에 하드코딩하지 않는다.
AI 제공자와 실행 프레임워크 연결은 worker 쪽 경계 안에 둔다.
실제 재사용 경계가 생기면 AI 호출·저장 모듈을 별도 패키지로 분리할 수 있다.
초기부터 작은 기능마다 패키지를 만들지는 않는다.

실제 프로젝트 데이터는 설정 가능한 로컬 디렉터리에 둔다. 코드 저장소에는
테스트에 필요한 작은 데이터와 스키마만 넣고, 게임 원본·대용량 추출·비밀 키·
실행 로그를 일괄 포함하지 않는다. 상위 기존 폴더와 orwell_dll에는 쓰지 않는다.

11. 기술 선택 제안

아래는 요구사항과 구분되는 구현 기본안이다. 착수 단계의 작은 실험으로 확정한다.

  언어·모노레포
    TypeScript와 워크스페이스 패키지 관리로 UI·worker·계약을 함께 관리하는 안.
    pnpm을 기본 후보로 두고, 빌드 작업 의존성이 필요해지면 Turborepo를 검토한다.

  UI
    React 기반 로컬 웹 UI를 기본 후보로 둔다. API를 같은 앱에 둘 수 있는
    프레임워크와 별도 API 구성을 비교하고, 처음부터 데스크톱 패키징을 요구하지 않는다.

  AI 실행
    Eve를 1차 검토 후보로 둔다. 공식 시작 문서의 현재 요구사항은 Node.js 24 이상이다.
    실제 구현 전에는 설치한 버전의 문서로 Windows 실행, UI 연결, 지속 실행,
    취소·재개와 저장 연동을 확인한다. 이 항목의 채택은 사용자와 확정한 기술 결정이 아니다.
    프레임워크의 세션 이력과 번역 프로젝트의 기준 데이터는 역할을 구분한다.

  모델 연결
    하나의 모델로 분석·번역·검수를 단계별 수행할 수 있는 구성을 우선 만든다.
    공급자 연결을 교체 가능하게 하고 모델·프롬프트 버전을 실행 기록에 남긴다.
    기본 연결 검토는 AI Gateway를 포함하되, 실제 공급자·모델·인증 방식·비용 상한은
    사용 환경에 맞춰 정한다. 특정 클라우드에 프로젝트 데이터를 반드시 저장하는
    구조로 만들지 않는다. 모델 호출 경로와 데이터 저장 위치를 별도로 설명한다.

  저장·검색·큐
    로컬 단일 사용자용 SQLite와 파일 저장을 첫 후보로 둔다.
    ID·명시적 연결·텍스트 검색부터 시작하고, 의미 검색은 실제 검색 실패와 개선
    효과를 확인한 뒤 보강한다. 임베딩 유사도를 분기·시점 접근 범위 판정으로 쓰지 않는다.
    영속 작업 큐의 소유자는 하나로 정한다. 프레임워크와 자체 큐가 같은 재시도·재개를
    각각 수행하지 않도록 책임과 복구 규칙을 먼저 검증한다.

  검증
    계약·도메인 단위 검사, 저장/큐 통합 검사, 브라우저 주요 흐름 검사,
    작은 고정 번역 사례와 사람의 비교 평가를 조합한다.

12. 구현 단계와 단계별 완료 조건

P0. 설계 확인과 첫 작업 화면
  - 작은 실제 장면 묶음과 분기·합류·용어 변경을 포함한 검증 사례를 정한다.
  - 입력 계약 0.1, ID/사용처/순서의 의미, 자동 반영·잠금 규칙을 정리한다.
  - 모노레포 경계를 만들고 UI의 작업실·자료실·검토함 연결을 확인한다.
  - 런타임과 저장·재개 연동을 작은 실험으로 확인하고 기술 결정을 기록한다.
  완료 조건: 선택한 대사에서 문맥·용어·사용처로 이동하는 UI 흐름을 시연할 수 있다.
  모의 결과를 사용하는 부분은 실제 AI 결과와 구분해 표시한다.

P1. 기준 데이터와 편집 가능한 UI
  - Orwell 입력 변환, 언어/본편/테스트 구분, 원문·사용처·연결 저장.
  - 대화 순서대로 읽기, 번역 편집, 자동 저장, 변경 이력, 잠금·되돌리기.
  - 용어 페이지와 사용처, 검토함, 원문과 번역의 내보내기 대응.
  - 기준 데이터 저장소와 레코드 버전 검사를 먼저 연결한다.
  완료 조건: 동일 입력 재가져오기에서 중복이 생기지 않고 기존 편집이 유지된다.
  장면에서 용어로 이동한 뒤 사용처를 통해 원래 대화 문맥으로 돌아올 수 있다.

P2. 첫 실제 AI 번역 작업 흐름
  - 작은 프로젝트의 전체 선행 분석, 용어·인물·번역 기준 초안 생성.
  - 다음 장면 선택, 문맥 구성, 대화 묶음 번역, 기계 검사와 문맥 검수.
  - 실행·일시정지·재개·취소, 실패 표시, 비용 제한과 진행 UI.
  - 용어 수정부터 영향 표시·재검토 작업·수정안·검수까지 기본 흐름 연결.
  - 잠긴 번역과 실행 중 사람이 바꾼 번역에 대한 충돌 처리.
  - 재개·결과 적용 시 의존 자료 버전 검사와 오래된 결과 적용 차단.
  - 첫 문서·대화 묶음에서 단일 모델 기준선과 비교하고 오류·수정 시간·비용 기록.
  완료 조건: 문서와 관련 대화 한 묶음을 불러온 뒤 AI가 분석·번역·검수하고,
  사용자가 UI로 결과와 쟁점을 확인한 다음 내보내기까지 완료할 수 있다.
  용어를 바꾸면 관련 항목만 다시 처리되고 최신 버전의 반영 상태를 확인할 수 있다.
  13번 A01~A12를 작은 고정 사례에서 검증한다. 기본 정보 공개 구분, 수동 편집 보호,
  중단 복구, 오래된 결과 차단, 내보내기 보존 검증을 이후 단계로 미루지 않는다.
  기준선보다 나아진 점과 남은 오류를 기록하고, 자동 처리 범위를 그 결과에 맞춘다.
  이 단계부터 실제 번역에 사용하면서 다음 기능을 보완한다.

P3. 작품 전체로 확장
  - 큰 입력의 단계별 분석과 근거 검색, 분기별 문맥·정보 공개 구분 보강.
  - 인물·관계·말투 자료의 변화 시점과 변경 영향 처리.
  - 복수 변경의 작업 통합, 예외 관리, 재개 시 변경 영향 범위의 정밀화.
  - 1편 번역과 기존 확정 번역의 재사용 후보 제시, 대화·문서 간 인용 검토.
  - UI·문서·하드코딩 문자열의 종류별 처리와 선택 범위 확대.
  완료 조건: 본편의 여러 장면과 공용 자료를 누락 없이 구분해 진행하고,
  다른 분기 지식 혼입과 의도하지 않은 일괄 수정 없이 변경 영향을 추적한다.

P4. 반복 사용과 품질 확인
  - 원문 버전 변경, 재추출 병합, 내보내기 왕복·출처 추적 강화.
  - 실제 번역 샘플로 기준선과 비교하고 수정 시간·비용·주요 오류를 측정한다.
  - 백업·복구, 시작/종료, 실패 안내와 작업 재개 절차를 정리한다.
  - 다른 형태의 작은 표준 입력으로 게임 전용 필드가 필수로 새어 나오지 않는지 확인한다.
  완료 조건: 반복 실행과 복구 후에도 원문·번역·연결·이력이 보존되고,
  사람이 실제로 번역 결과를 검토하고 수정하는 과정에서 사용할 수 있다.

후속 확장
  다중 모델 검수·토론, 더 정교한 의미 검색, 큰 그래프 탐색, 여러 사용자 협업,
  데스크톱 배포, 다른 게임 변환기는 실제 필요와 효과를 확인해 추가한다.
  캐릭터별 역할극과 게임 실행 시뮬레이션은 별도 실험으로 다루며 P2의 선행조건이 아니다.

13. 검증 기준

기능·데이터 검증은 자동화하고, 번역의 해석과 표현은 작은 비교 평가로 확인한다.
외형만 존재하는 화면을 기능 완료로 판정하지 않는다.

  A01 입력·원문 보존
    ID 중복·누락·미해결 참조를 검출하고, 가져오기/내보내기에서 원문과 출처가 보존된다.
    동일 문장이 다른 원본 ID에 있거나 한 원문이 여러 장면에 나타나는 사례를 포함한다.
  A02 장면·대화 순서
    대화 묶음과 선후관계를 보존한다. 병렬·순환 구간과 review_rank의 한계를 표시한다.
  A03 지식 범위
    후반의 복선 의미를 번역자는 참고하되 현재 인물의 지식이나 번역문에 먼저 노출하지 않는다.
    다른 분기에서만 발생한 사건을 현재 경로의 사실로 사용하지 않는다.
  A04 용어 변경
    연결된 사용처가 빠짐없이 점검되고 새 별칭의 미연결 후보도 검색된다.
    관련 없는 의미의 사용처는 무조건 바뀌지 않으며 예외의 근거가 남는다.
  A05 최신 여부
    완료 번역의 내용은 유지하면서 갱신 필요를 표시한다. 사용한 용어 버전을 확인할 수 있다.
  A06 수동 편집 보호
    사람이 편집·잠금한 뒤 도착한 AI 결과가 현재 번역을 덮어쓰지 않는다.
  A07 재시도·재개
    브라우저 새로고침, worker 중단/재시작, 요청 실패와 늦은 응답을 시험한다.
    중복 적용·중복 검토 항목이 생기지 않고 완료 결과가 보존된다.
  A08 변경 중 실행
    용어가 연속 변경되거나 입력이 바뀌면 오래된 작업이 최신 결과로 반영되지 않는다.
  A09 자동 검수
    보호 토큰·태그·링크·대상 ID 오류를 검출하고, 잘린 모델 응답을 완료 처리하지 않는다.
  A10 UI 전체 흐름
    장면 → 대사 → 용어 → 사용처 → 변경 영향 → AI 재검토 → 변경 비교 → 원래 장면 이동을 확인한다.
    키보드 탐색, 한글 입력, 긴 원문·번역, 좁은 창, 오류·빈 상태도 확인한다.
  A11 자동 진행과 개입
    정상 항목은 매번 사람의 확인 없이 진행한다. 보류 항목 때문에 독립적인 모든 작업이 멈추지 않는다.
  A12 내보내기
    원본 ID/적용 대상 매핑과 확정 상태를 검증하고, 미해결 충돌·미지원 번역 변형을 숨기지 않는다.

번역 효과의 초기 비교
  같은 장면의 원문·기본 용어집을 준 단일 모델 결과를 기준선으로 삼는다.
  작품 자료와 그래프 문맥을 추가했을 때 오역·누락·첨가·호칭·용어·정보 공개
  오류와 사람이 최종 수정하는 시간이 어떻게 달라지는지 기록한다.
  문서와 관련 대화, 짧은 응답, 인물 지식 차이, 분기, 복선, 보호 토큰을 포함한다.
  AI 점수와 유창성만으로 품질 향상을 확정하지 않는다. 생성 경로를 가린 비교를
  활용하고, 작은 시범 결과를 모든 게임에 대한 증명으로 확대하지 않는다.
  작업별 호출량·비용과 자료를 수정하는 사람의 시간도 함께 기록한다.
  다중 모델을 시험할 때는 같은 근거와 비슷한 비용 예산의 단일 모델 재검토와 비교한다.

14. 주요 위험과 대응

  범위 확대
    P2의 작은 실제 번역 흐름을 먼저 완성한다. 완전한 게임 실행기는 별도 범위로 유지한다.
  잘못된 프로필·요약의 반복 전파
    근거 원문, 자료 버전, 확정/추정 구분과 오류 정정의 영향 추적을 유지한다.
  분기·미래 정보 혼입
    검색 전에 프로젝트·분기·관점 범위를 적용하고 사용한 자료를 결과에 연결한다.
  자연스러워졌지만 의미가 바뀐 수정
    원문 대조와 변경 비교를 제공하고 언어적 평가에 사람의 검토를 포함한다.
  동일 원문 또는 용어의 무조건 통일
    사용처 문맥과 의미를 유지하고 서로 다른 원본 ID와 예외를 보존한다.
  작업 폭증과 비용 증가
    변경별 작업 통합, 제한된 재시도, 실행 상한과 영향 범위 선택을 제공한다.
  UI에서 결과를 이해하기 어려움
    처음부터 실제 긴 대사로 작업실·자료실·검토함을 연결해 사용성을 확인한다.
  특정 게임·모델·프레임워크에 대한 결합
    입력 변환과 모델 실행의 경계를 유지하고 공통 계약을 독립 검증한다.

15. 착수 시 결정할 사항

계획 작성만으로 확정하지 않은 항목이다. 독립적으로 진행할 수 있는 설계·UI 작업은
이 결정 전체가 끝날 때까지 대기하지 않는다.

  - UI 프레임워크와 로컬 API 구성, 영속 실행 프레임워크의 실제 채택.
  - 모델 공급자·모델·인증 방식과 첫 시범 작업의 비용 상한.
  - 후보 자료와 번역의 자동 확정 정책, 반드시 검토함으로 보낼 조건.
  - 첫 검증용 문서·대화 묶음과 본격 번역을 시작할 장면 범위.
  - 내보내기에서 확정·검수 완료·미해결 항목을 포함하는 정책과 적용기 계약.
  - 프로젝트 데이터의 저장 위치와 백업 주기.

기본 진행 가정은 로컬 단일 사용자, 영어 → 한국어, 한 모델의 단계별 실행,
기존 자료 읽기 전용 가져오기, UI 포함 모노레포다. 이 가정과 다른 결정을 하면
계획과 결정 기록을 함께 갱신한다.
