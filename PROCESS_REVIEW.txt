용어 쌍은 원문·대응 번역문에서 추출한다. 실제 모델 검증은 별도 실행 요청 시에만 한다.

1. 먼저 확인할 것

Orwell 전체를 처리하기 전에 사람이 전체를 읽을 수 있는 작은 가상 작품으로
작업 흐름부터 검토한다. 아래 영어 원문은 이 검토를 위해 작성한 샘플이며,
실제 게임 추출물이나 번역 정답 데이터가 아니다.

  1단계: 아래 사례로 단계·산출물·자동 반영·검토함의 동작을 검토한다.
  2단계: 모의 응답을 사용하는 UI에서 같은 과정을 수행한다. 모델 호출은 없다.
  3단계: 준비된 실제 연결로 같은 소량 원문을 번역하고 모의 실행과 구분한다.
  4단계: 흐름이 성립하면 Orwell에서 소량을 가져와 변환·내보내기 대응을 확인한다.

초기에는 번역 품질을 높이기 위한 모든 기능을 만들지 않는다. 자료를 준비하고,
번역하고, 변경이 생겼을 때 필요한 부분을 다시 확인하는 한 흐름을 완주한다.

2. 작업 단계와 모델 배정

작업 단계                    입력                          산출물
입력 검사                    원문·묶음·연결                ID/참조/서식 검사 결과
작품 분석                    가상 작품 전체                개요·사건·복선·근거 목록
용어 후보 추출               원문 + 작품 분석              용어 후보·의미·사용처
인물·관계 정리               원문 + 작품 분석              말투·호칭·관계·지식 범위
초벌 번역                    장면 문맥 + 작품 자료         원문 ID별 번역 초안
기계 검사                    초안 + 원문 제약              누락·토큰·태그 검사 결과
문맥 검수                    원문·초안·관련 작품 자료      지적·근거·필요한 수정안
결과 반영                    검수 결과 + 시작 버전         번역 새 버전 또는 검토 항목
용어 변경 후 재검토          바뀐 기준 + 사용처 + 문맥     유지/수정/예외 판단과 새 버전
내보내기                    적용 가능한 번역 + 원본 매핑  ID와 번역의 대응 결과

입력 검사·기계 검사·버전 검사·저장·내보내기는 일반 코드로 수행한다.
모델은 해석과 번역이 필요한 단계에 연결한다.
용어와 인물 후보는 독립적으로 생성할 수 있고, 번역 전에 서로 충돌하는 기준을 확인한다.
문맥 검수 후 수정은 정한 횟수 이내에서만 반복한다.

설정 UI의 예시
  작업 단계              연결            모델                     effort
  작품 분석              연결 A          사용자가 선택             지원값 중 선택
  용어 후보 추출         연결 A          Luna 계열(사용자 예시)    medium(지원 시)
  인물·관계 정리         연결 A/B        사용자가 선택             지원값 중 선택
  초벌 번역              연결 B          번역에 배정한 모델        지원값 중 선택
  문맥 검수              연결 C          검수에 배정한 모델        지원값 중 선택
  용어 변경 후 재검토    연결 B/C        사용자가 선택             지원값 중 선택

A/B/C는 사용자가 만든 연결 이름의 예시다. 같은 연결 안에서 모델만 달라도 된다.
예를 들어 용어 추출은 Codex CLI, 번역은 OpenAI 호환 API, 검수는 다른 CLI로
배정할 수 있다. 모두 한 연결·한 모델을 쓰는 설정도 가능하다.
각 연결에서 실제로 쓸 수 있는 모델 ID와 옵션을 확인하기 전에는 예시를 실행 설정으로 확정하지 않는다.
Luna라는 표시 이름을 모든 API에서 통하는 모델 ID로 취급하지 않는다.
단계별 모델 배정은 여러 캐릭터 에이전트가 서로 토론하는 기능과 별개다.

프로필에는 timeout·재시도·출력 한도·동시 실행 제한도 포함한다.
실행 시작 시 확정한 설정 버전을 기록한다. 설정을 고쳐도 이미 진행 중인 호출의
모델이 바뀌지는 않는다. 과거 번역을 새 설정으로 바꾸려면 대상 범위를 골라 재실행한다.
지원하지 않는 effort는 숨겨진 기본값으로 바꾸거나 무시하지 않고 실행 전에 알린다.

3. 작은 가상 작품: 야간 이송 기록

분량: 대사 18개 + 문서 2개 + UI 문구 2개 = 고유 원문 22개.
인물: 조사관 Mira, 기록 담당 Jun, 상관 Vale.
기본 말투안: Mira는 간결한 질문, Jun은 조심스러운 응답, Vale는 권위적인 짧은 발언.
이 말투안도 검토용 초안이며 영어 원문에 없는 감정이나 사실을 추가할 근거는 아니다.

흐름
  S0 조사 시작
    ├─ 경로 A: S1A 기록 확인 ─┐
    └─ 경로 B: S1B 접선 약속 ─┴─ S2 공통 보고 → S3 후반 공개

A와 B는 배타적이다. 실제 작업에서는 두 경로를 각각 번역하되 기억을 섞지 않는다.
S2의 같은 원문 ID는 두 경로에서 재사용된다. 사용처는 별개지만 내보낼 번역은 공통이다.
문서 D01은 S0에서 볼 수 있고, 문서 D02는 S3에서 공개된다.
번역자는 전체 준비 단계에서 D02와 S3를 참고할 수 있다.

S0 조사 시작
  S0-01 Mira: The Watch Office sent me.
  S0-02 Jun: Then you know about the night train.
  S0-03 Mira: Only that it stopped running.
  S0-04 Jun: Some things still arrive on time.

S1A 기록 확인 — 경로 A에서만 등장
  A-01 Mira: Show me the record.
  A-02 Jun: I copied it before they sealed the cabinet.
  A-03 Jun: The archive code is 731.
  A-04 Mira: I'll keep that between us.

S1B 접선 약속 — 경로 B에서만 등장
  B-01 Mira: Keep the record. Tell me where to wait.
  B-02 Jun: By the east gate, after the bell.
  B-03 Jun: Watch your step near the harbor.
  B-04 Mira: I won't ask about the cabinet.

S2 공통 보고
  S2-01 Vale: Did you get what you needed?
  S2-02 Mira: Enough to continue.

S3 후반 공개
  S3-01 Vale: The night train was never a train.
  S3-02 Vale: It was our name for moving people off the record.
  S3-03 Mira: The Watch Office made them disappear?
  S3-04 Vale: That's what the report will say.

문서
  D01:
    Watch Office Notice
    Cabinet access requires written authorization.
  D02:
    Transfer log
    Operation NIGHT TRAIN — list removed.

UI
  U01: Open {document_name}
  U02: <b>Watch Office</b>: {count} unread

관찰 기준
  - S0의 night train은 후반 의미를 참고하되 원문보다 먼저 정체를 명시하지 않는다.
  - 경로 A의 Mira는 731을 안다. 경로 B의 Mira가 이 코드를 아는 것으로 기록하지 않는다.
  - 경로 B의 접선 약속을 경로 A에서 이미 정한 사실로 기록하지 않는다.
  - S2-02는 경로 A/B 모두에 맞는 번역이어야 한다. 경로에 없는 구체 내용을 추가하지 않는다.
  - S3-04의 발언을 곧바로 감시 기관의 유죄를 확정하는 객관적 사실로 요약하지 않는다.
  - U01/U02의 자리표시자와 U02의 태그를 보존한다.

4. UI에서 검토할 한 번의 실행

순서 1: 가상 작품 불러오기
  장면 트리와 원문을 읽고 두 경로가 구분되는지 확인한다.
  원문 수 22와 경로별 사용처 수를 구분한다. 중복 사용처를 새 원문으로 복제하지 않는다.

순서 2: 단계별 실행 설정
  용어 추출, 초벌 번역, 검수에 각각 실행 프로필을 배정한다.
  모의 단계에서는 실제 API/CLI 이름과 혼동하지 않도록 '모의 연결'을 표시한다.
  프로필을 바꾸면 이번 실행의 예상 배정표에서 그 변경을 확인한다.

순서 3: 자료 준비
  AI가 생성한 개요·용어·인물 자료와 근거 원문을 확인한다.
  임시 기준으로 진행할 수 있고 모든 후보를 사람이 하나씩 확정할 필요는 없다.
  경로·관점 범위를 벗어난 사실이 붙어 있으면 해당 자료를 고치고 영향 항목을 확인한다.

순서 4: 장면 번역과 검수
  대화 묶음 단위로 초안이 나타난다. 현재 단계와 사용 모델이 표시된다.
  기계 검사와 문맥 검수를 거친 정상 결과는 자동 반영된다.
  모호한 해석은 검토함에서 원문·현재 번역·제안·근거를 나란히 확인한다.

순서 5: 용어 변경
  Watch Office의 권장 번역을 '감시국'에서 '관측국'으로 바꾼다.
  직접 사용처의 예상 집합: S0-01, S3-03, D01, U02.
  관련 문맥을 함께 점검할 수 있지만 다른 대사를 이유 없이 다시 쓰지 않는다.
  완료 번역은 지워지지 않고 갱신 필요로 표시된다.
  별칭 'Watch'를 추가해도 B-03의 동사 Watch를 기관명으로 바꾸면 안 된다.

순서 6: 사람이 수정한 항목 보호
  S3-03의 번역을 사람이 직접 고쳐 보호 상태로 만든 뒤 용어 재검토를 실행한다.
  다른 사용처는 정상 반영되고 S3-03은 수정안만 검토함에 남아야 한다.
  사용자가 수정안을 선택하거나 직접 고치면 새 번역 버전을 기록한다.

순서 7: 실행 중 변경·일시정지·오류
  재검토가 실행되는 동안 S0-01을 직접 수정한다. 늦게 온 AI 결과는 덮어쓰지 못한다.
  용어를 다시 변경하면 이전 용어 버전의 응답을 최신 결과로 반영하지 않는다.
  UI 새로고침, worker 재시작, 모델 오류, 잘린 응답을 각각 모의 입력으로 확인한다.
  중단 전 완료 결과는 남고, 재개한 작업이 번역이나 검토 항목을 중복 생성하지 않는다.

순서 8: 내보내기와 결과 검토
  각 원문 ID에 대응하는 적용 가능한 번역을 확인한다.
  미해결 항목과 보호된 수정안은 정책에 따라 명시적으로 표시한다.
  원문·번역·변경 이력·사용 모델·자료 버전에서 관련 근거로 이동할 수 있어야 한다.

프로세스 검토의 질문
  지금 AI가 무엇을 하는지 보이는가?
  번역이나 용어가 바뀐 이유와 사용처를 찾을 수 있는가?
  원하는 부분만 고쳐 다시 맡길 수 있는가?
  불확실한 항목 때문에 독립적인 모든 작업이 멈추지는 않는가?
  필요한 판단만 사람에게 오고 평범한 항목은 자동 진행되는가?

5. 연결 확인 기록 — 2026-10-08

아래는 도움말과 공식 문서로 확인한 연결 가능성이다. 인증·모델 접근 권한,
실제 번역 결과, 스키마 준수, Windows 취소 동작을 시험했다는 뜻이 아니다.

OpenAI 호환 API
  작업실의 지원 계약으로 정의할 대상이다. 실제 서버는 아직 선택하지 않았다.
  Chat Completions와 Responses 지원을 구분하고, 서버·모델별 기능을 따로 확인한다.
  공식 API 규격을 따른다는 것만으로 모든 제3자 서버의 동일 동작을 보장하지 않는다.

Codex CLI
  설치 확인: codex-cli 0.154.0.
  위치: C:/Users/bh298/AppData/Roaming/npm/codex.ps1
  exec 비대화형 실행, stdin 입력, --json 이벤트 출력,
  --output-schema, --output-last-message, --model, exec resume를 도움말에서 확인했다.
  초기에는 새 작업 입력과 출력 계약으로 연결하고 숨은 세션 기억에 의존하지 않는다.

Grok Build
  설치 확인: 1.0.30, X.AI LLC 서명.
  위치: C:/Users/bh298/.grok/bin/grok.exe
  -p/--single, --prompt-file, --prompt-json, JSON 계열 출력,
  --json-schema, --resume/--continue/--fork-session을 확인했다.
  일반 텍스트 stdin은 확인하지 못했으며 입력 파일 경로를 우선 검토한다.
  agent stdio의 ACP JSON-RPC는 별도 연결 방식이다.
  설치 도움말의 --session-id는 새 UUID 생성용이다. 재개와 혼동하지 않는다.
  후속 버전의 중단 처리 개선을 설치 버전의 동작으로 가정하지 않는다.

Antigravity CLI
  설치 확인: 1.2.7, Google LLC 서명. 실제 실행 명령은 agy다.
  위치: C:/Users/bh298/AppData/Local/agy/bin/agy.exe
  -p/--print, json/stream-json 출력, --json-schema,
  --input-format stream-json, --continue/--conversation을 확인했다.
  설치 도움말의 timeout 기본값은 0s이므로 어댑터에서 명시적으로 제한한다.
  stdin 종료는 현재 턴 완료 후 종료이며 즉시 취소와 같지 않다.
  stream의 control_request/control_response가 취소 명령이라고 가정하지 않는다.

공통 연결 시험의 순서
  도움말·버전 탐지 → 옵션 유효성 → 작은 요청 → 최종 결과 검사 → 사용량/오류 처리
  → timeout·취소·늦은 응답·재개 확인 → 준비됨 표시.
  모델 출력만으로 CLI에 데이터베이스 쓰기 권한을 줄 필요는 없다.
  미검증 연결은 그대로 표시하고 준비된 연결부터 프로세스를 검토한다.

이번에 작성한 것
