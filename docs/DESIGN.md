# loca — 설계

이 문서와 `README.md`가 유일한 기준이다. 항목마다 **[구현됨]** 또는 **[계획]**을 붙여, 문서가 실제 동작과 어긋나지 않게 한다.
흐름을 바꾸기 전에 여기의 여정과 수용 기준부터 고친다. 결정이 바뀌면 10장에 남긴다.

## 0. 개발 실행 [구현됨: 2026-10-14 수정]

여정: 저장소 루트에서 `pnpm dev` → API 초기화 완료 → Vite가 개발 주소를 표시 → 브라우저에서 프로젝트 목록을 연다. Windows·macOS에서는 서버 소스와 공유 패키지 폴더의 파일 변경을 감시해 자동 재시작하며, `node_modules` 알림으로 반복 재시작하지 않는다. Linux에서는 Node의 기본 모듈 감시를 사용한다. API가 준비되기 전에 Vite가 요청을 받아 첫 화면을 502 오류로 만들지 않는다.

수용: 빈 격리 DB와 기존 격리 DB에서 기본 API 4317·Vite 4318이 함께 열린다. Vite의 `/api/projects`와 `/api/events` 프록시가 성공한다. API 준비가 30초 안에 끝나지 않으면 주소와 서버 로그 확인 안내를 남기고 Vite 시작을 실패시킨다. 파일 변경 후 API가 다시 응답하며, Ctrl+C로 두 서버가 종료되고 같은 명령으로 다시 실행할 수 있다. 프로덕션 빌드는 실행 중인 API 없이 성공한다. 그래프 워커는 파일 감시의 내부 의존성 메시지를 계산 결과로 받아들이지 않고, 실제 성공·실패 응답을 받아 배치를 저장한다.

## 1. 제품 정체성과 원칙

게임에서 추출한 **표준 포맷** 원문을 가져와서, 사용자가 직접 정의한 **번역 상태**(예: 미번역 → 초벌 → 검수 통과 → 확정)와
그 사이를 잇는 **워크플로 노드**(AI 번역·검수·수정, 형식 검사, 조건 분기, 상태 변경)로 번역 작업을 AI로 자동화하는 Windows 로컬 작업실.
작품 자료·인물·관계·장면/대사 그래프는 **AI 노드에 문맥을 주기 위해** 존재한다.

원칙:
- **AI는 초안, 사람이 확인한다.** 사용자가 누르지 않은 AI 변경은 없다. AI 결과는 수락 카드·제안·후보·초안으로만 들어온다.
- **원문은 읽기 전용 근거다.** 번역은 대사별 후보 여러 개 + 대표 번역 1개로 관리한다.
- **근거 없는 것을 만들지 않는다.** 원문 그래프 관계는 추출 근거일 뿐 실행 순서·사건 순서가 아니며, 없는 간선·관계를 만들지 않는다. 장면 연결은 대사 그래프에서 파생했음을 표시한다. 라벨은 실제 범위와 근거를 말한다.
- **실행 모델은 워크플로 하나뿐이다.** 상태는 대사가 지금 어디 있는지, 워크플로는 AI가 상태를 옮기는 자동 작업(사용자가 실행할 때만), 검토함은 사람이 상태를 옮기는 곳이다. 상태 변경이 숨은 동작을 일으키지 않는다.
- **특정 게임에 묶이지 않는다.** 스킬·도구 설명·예시는 범용으로 쓴다. 특정 게임 전용 변환기는 `scripts/`에 따로 둔다.

## 2. 핵심 문제: 번역 문맥

게임 번역은 앞뒤 상황을 모르면 틀린다. 한 줄을 제대로 옮기려면 AI가 **누가 누구에게 하는 말인지, 앞에서 무슨 일이 있었는지,
두 사람이 어떤 사이인지, "그날"·"그 사람"이 무엇을 가리키는지, 이 시점에 인물이 무엇을 아는지**를 알아야 한다.
어떤 문맥을 주느냐가 번역 품질을 정하는 핵심이다.

### 2.1 현재 문맥 [구현됨] (`apps/server/src/services/context.ts`)

AI 노드 설정의 "문맥"에서 항목을 켜고 끈다(용어집 · 청자·말투 규칙 · 앞 단계 지적 사항 · 앞 대사(줄 수) · 이전 장면(개수) · 인물 명단 · 인물 프로필 · 인물 관계 · 작품 문서, 그리고 상한). 줄 수·개수가 있는 항목도 다른 항목처럼 켜고 끄며 켰을 때만 수를 정한다. 번역 후보를 만드는 노드는 "기존 번역: 보지 않고 새로 번역 / 보고 고침"을 고르고, 판정(검수) 노드는 늘 현재 번역을 본다. AI 노드의 "문맥" 설정에서 항목을 켜고 끈다. 기본은 실험 결과(2.4)를 따른다: 청자·말투 규칙, 용어집, 앞 대사 8줄(현재 번역 포함), 장면 설명, 이전 장면 1개, 상한 약 12,000토큰. **인물·관계·문서는 기본 꺼짐**이고 노드마다 켠다. 저장된 워크플로는 저장된 값을 그대로 쓴다. 켠 경우에도 확인 안 된 AI 항목(출처 AI·검토 전)은 사실과 섞지 않고 별도 입력 `aiNotes`("AI 추론, 확인 안 됨")로 보내며 시스템 프롬프트가 추측이라고 알린다. 인물 매칭에서 일반 단어 별칭(you, sir, player 등)과 3글자 미만 별칭은 뺀다(이름은 그대로 매칭).

| 항목 | 지금 방식 |
|---|---|
| 작품 문서 (켰을 때) | 문서 화면에서 "번역 문맥에 넣기"를 켠 문서만 전문 그대로, 모든 호출에 |
| 인물 (켰을 때) | 묶음의 화자·원문에 이름/별칭이 나오면 프로필 전체. 일반 단어·3글자 미만 별칭은 매칭에서 제외 |
| 관계 (켰을 때) | 등장한 두 인물 사이 관계 전부 |
| 장면 | 묶음이 한 장면이면 그 장면의 제목·설명 |
| 이전 장면 | 파생 장면 연결에서 바로 앞 장면 중 앞에서부터 N개(선택 기준 없음), 제목·설명만. 연결점(허브)을 거친 연결은 '앞 장면'으로 치지 않는다 |
| 앞 대사 | 대사 그래프를 거꾸로, 들어오는 길이 하나인 동안 따라가 N줄. 여러 길이 합쳐지는 곳에서는 **갈래별로 나눠**(선택지·조건 간선 라벨, 최대 4갈래) 각각 따라가며, 프롬프트에 "플레이어는 이 중 한 갈래를 거쳐 왔다"고 알린다. 그래프에 없으면 장면 순서. 묶음 안의 줄과 묶음의 앞 줄에 이미 붙은 줄은 다시 넣지 않는다. 현재 번역은 설정으로 뺄 수 있다 |
| 용어 | 확정 용어 중 원문에 나온 것 |

- **상한**: 용어 → 앞 대사 → 인물 → 관계 → 장면 → 이전 장면 → 문서 순으로 채우고, 넘치는 항목은 빼고 기록한다(임시 우선순위). 토큰은 UTF-8 바이트/4로 추정하며 화면에 "추정"으로 표시한다.
- **기록**: 실행 단계마다(run_steps.context) 넣은 항목·이유·크기·뺀 것이 남고, 실행 상세의 AI 호출에서 본다. 보낸 프롬프트 전문도 남는다(System One 판정은 제외).
- **미리보기**: 대사 패널의 "AI 문맥" 탭과 `loca context <키>`가 AI 노드를 골라, 모델을 부르지 않고 실행과 같은 방식으로 만든 문맥(앞 대사·갈래, 항목, 프롬프트 전문)을 보여 준다. 묶음은 그 대사가 속한 장면에서 실행기처럼 나눠 계산하며, 실제 실행 범위에 따라 더 작을 수 있다고 표시한다.

### 2.2 문제

| | 문제 | 예 |
|---|---|---|
| P1 | 엉뚱한 것이 들어간다 | 세계관 문서 전체가 매 호출에 들어감. ~~다른 선택지의 대사가 이어진 대화처럼 섞임~~(갈래별로 나눔, 2.1) |
| P2 | 필요한 것이 안 들어간다 | "번역 문맥에 넣기"가 꺼진 문서. 이름 없이 가리키는 인물·사건. 한참 전 장면의 사건 |
| P3 | 시점을 모른다 | 나중에 밝혀질 사실이 프로필에 있으면 인물이 이미 아는 것처럼 번역됨 |
| P4 | ~~무엇이 들어갔는지 보기 어렵다~~ | 미리보기·실행 기록의 문맥 항목으로 해결(2.1) |
| P5 | 지식을 사람이 다 써야 한다 | 수만 줄짜리 게임의 인물·관계·사건을 손으로 정리하기는 비현실적 |

### 2.3 해결 방향

- **P4 → 보이게 한다** [구현됨]: 미리보기와 실행마다의 문맥 항목 기록(2.1).
- **P1 → 바로 고친다** [구현됨]: 문맥 총량 상한, 갈래가 합쳐지는 곳에서는 섞지 않고 갈래별로(2.1). 항목 우선순위는 임시값이며 최종 알고리즘이 아니다. 관련 없는 "번역 문맥에 넣기" 문서가 매번 들어가는 문제는 상한으로만 완화된다(남음).
- **P2·P3·P5 → 작품 지식을 만들고 골라 쓴다** [계획, 실험 후 결정]:
  1. AI가 대본을 읽어 **작품 지식 초안**(3장)을 근거와 함께 만든다.
  2. 사람이 초안을 확인·수정한다.
  3. 번역할 때 장면 단위로 **문맥 후보**를 구조로 모은다: 화자·등장인물, 장면에 연결된 사건, 관계, 같은 갈래의 앞 대사, 용어.
  4. **System One 판정 모델**이 후보를 거르는 데 돕는다(2.5).
  5. 필수 항목 보존, 중복 제거, 총량 상한, 분기·시점 제약을 지키며 최종 문맥을 짠다.
- 선택은 **장면(묶음) 단위**로 한다. 줄마다 후보 수백 개를 판정하면 비용이 감당되지 않는다. 앞 대사처럼 가까운 문맥과 지칭 해소만 줄 단위다.
- 질문을 늘려 다시 찾는 방식(질의 확장)과 임베딩 검색은 처음엔 쓰지 않는다. 구조(화자·그래프·사건)로 못 찾는 경우가 평가에서 많으면, 장면당 1회로 상한을 두고 추가한다.

### 2.4 번역 모델에 넘기는 것

실험(Detroit·Orwell, `.loca/EXPERIMENTS.md`) 결과 번역기에는 **작고 구체적인 것**만 준다. 서사 분석(개요·인물·관계·사건)은 사람이 보고 규칙을 정하는 자료이고, 번역기에 통째로 넣지 않는다.

| 문맥 | 효과 | 결정 |
|---|---|---|
| 청자 + 확정 말투 규칙(쌍별 반말/해요체/하십시오체) | 말투 일치 46%→91%, 종합 99:14 (Orwell 147줄) | **기본** [1차] |
| 지칭("they → 경찰"), 앞 일의 결과 한 줄 | 정보가 실제로 붙은 줄만 Sonnet으로 다시 심사하자 정보 없는 쪽이 우세(지칭 54:31, 앞 일 29:12). 예전의 "개선"은 프롬프트가 같은 줄의 무작위 차이였다 | 넣지 않음 |
| 앞 대사의 기존 번역 | 묶음 첫머리에만 붙어 Orwell 407줄 중 6줄에 들어감, 차이 없음(E9) | 기본 끔(토글) |
| 장면 제목, 장면 한 줄 요약, 앞 대사 원문 | 407줄에서 말투 일치·chrF가 같은 조건 반복과 같은 수준. 장면 밖 정보가 필요한 줄은 14줄(3%)이고 거기서도 요약이 번역을 바꾸지 않음(E9) | 그대로 둠(비용 작음). 요약을 만들려고 분석을 늘리지 않음 |
| 지금 태도 서술, 말투 서술("공손하게 대함") | 효과 없음(서술형 말투로는 교정 노드도 258줄 중 2줄만 수정) | 넣지 않음. 사람이 규칙을 정할 때 참고 |
| 인물 프로필 전체·사건 요약 묶음 | 해롭거나 효과 없음 | 넣지 않음 |

AI의 결론을 사실처럼 넘기지 않는다. 프롬프트의 문맥은 칸을 나눈다.

| 칸 | 들어가는 것 |
|---|---|
| 사실 | 사람이 확인한 지식, 원문·변환기가 준 정보, 확정 용어, 확정 말투 규칙 |
| 원문 근거 | 확인 안 된 `observed` 주장이 가리키는 **원문 대사 자체**. AI 결론 대신 원문을 읽게 한다 |
| 추론 힌트 | 확인 안 된 `inferred` 주장·지칭 해소. "AI 추론, 확인 안 됨"과 확신도·다른 후보를 함께 적고 소량만 |
| 번역자 노트 | 인물은 모르는 작품의 사실(반전 등). "대사에서 드러내지 말 것" |

- 추론 힌트를 쓴 번역은 출력에 표시하게 해 검토 대상으로 모을 수 있게 한다. 확신이 낮으면 모호함을 살려 옮기게 한다.
- 사람이 확인할 순서는 많은 줄의 문맥에 쓰이는 지식부터다.

### 2.5 System One의 역할 [계획, 실험 후 결정]

System One(TypeSafe의 판정 모델 체계. 현재 모델 Jev)은 확률을 돌려주는 **판단**이며 **검증이 아니다**.
- 쓰는 곳: 문맥 후보 1차 거르기(관련 있는가, 의미 해석을 바꾸는가, 말투·호칭에 영향을 주는가, 지칭 대상을 특정하는가, 관련도 점수), 풀리지 않은 지칭의 후보 고르기.
- 쓰지 않는 곳: 시간·순서 판단(그래프로 코드가 한다), 주장의 사실 확인.
- 편집기 후보: 비슷한 줄 중 참고할 만한 것 고르기, 화자→청자 말투 일치 판정(실험 후). 서식 위치 고르기는 E12에서 39%로 보류. 생성(이어 쓰기)에는 쓰지 않는다.
- 1차 거르기는 필요한 것을 놓치지 않는 쪽(느슨한 기준선)으로 잡고, 꼭 필요한 항목은 판정을 거치지 않는다.
- 기준선은 사람이 확인한 평가 세트로 모델마다 다시 정한다. 결과에는 모델 이름을 남긴다.

### 2.6 확인해야 할 것과 방법 [계획]

모르는 것: **문맥이 이 번역을 실제로 낫게 하는가**, **AI가 만든 지식이 쓸 만한가**. 기능·화면을 만들기 전에 앱 바깥(`loca export` → `.loca/` 작업 폴더 → JSONL 결과)에서 확인한다. 실험은 프로젝트의 번역을 바꾸지 않는다.

- **자료**: Detroit: Become Human 공개 전사(영어·공식 한국어, 선택지·조건·관계 변화 표시 포함)를 주 평가 세트로, 덜 알려진 Orwell 1(기존 번역 있음)을 대조군으로. 유명 작품은 모델이 이미 알고 있을 수 있어 둘을 비교한다. 데이터는 커밋하지 않는다.
- **조건**: 같은 번역 모델·같은 줄에서 문맥만 바꾼다.

| 조건 | 문맥 |
|---|---|
| N | 없음 |
| C0 | 현재 문맥 구성(2-A 적용 후) |
| A | AI가 대본 전체를 훑어 만든 개요·인물·사건(사람 확인 없음). 한 번에 전부 읽기와 장면별 분석 후 통합을 비교 |
| O | 사람이 고른 정답 문맥 |
| (이후) | 구조 후보 + 판정 없음 / + System One / + 일반 모델 판정 |

- **해석**: O도 별로 낫지 않으면 문맥은 병목이 아니다. A가 O에 가까우면 단순한 전체 분석으로 충분하다. A가 O보다 크게 못하면 분석·선별을 정교하게 만들 근거가 된다.
- **채점**: 공식 번역과 항목별로 비교한다(지칭 대상, 인물 쌍별 말투 어미, 호칭, 용어). 표본은 사람이 조건을 가린 채 비교한다.
- **오류 구분**: 후보에 없었음 / 판정이 틀림 / 조합에서 빠짐 / 정답 문맥이 있었는데도 번역이 틀림. 단계마다 기록이 남아야 구분된다.
- **규모**: 수십 건은 탐색용이다. 회수율 같은 결론은 수백 건 이상에서 낸다. 말투 정답은 공식 번역의 어미에서 자동으로 뽑아 규모를 늘린다. 후반에 밝혀지는 사실이 초반 해석을 바꾸는 사례를 반드시 넣고, 장 하나가 아니라 한 인물의 이야기 전체로 분석한다.
- **공정성**: 실험 번역의 문맥에서 기존 번역을 뺀다.
- 정답 데이터는 **계속 쓰는 평가 세트**로 둔다. 새 모델이 나오면 같은 세트로 다시 잰다. 모델(분석·판정·번역)은 사용자가 단계마다 고른다.

  1. 나온 줄 [구현됨: 2026-10-14]: 용어마다 원문에 나오는 대사 수와 첫 예문 5개를 앱이 센다(낱말 단위, 원문 언어 무관, 편집기·실행 창과 같은 일치 규칙). 새 용어나 원문을 고친 용어는 용어집을 열 때 센다. 용어집의 '나온 줄' 열과 #대본에 안 나옴이 이것을 쓴다. (대문자 이름을 코드로 찾던 '대본에서 찾기'는 영어 대본에만 맞고 작품 분석과 겹쳐 없앴다.) 빈 번역은 "빈 번역 AI로 채우기"가 요청당 100개씩 묶어 예문과 함께 후보로 채운다(확정은 사람). 용어집은 같은 원문(대소문자 무시)을 두 번 두지 않는다: 직접 추가·수정과 채팅 저장은 '이미 있는 용어입니다: …'로 거절하고(채팅은 나머지만 저장), 거절해 숨긴 용어와 같은 원문을 추가하면 그 용어가 되살아난다.
  2. 의미 정리(AI): 후보마다 등장 사례 몇 개와 서사 분석(참고용)을 주고 고유명사/일반어, 의미 갈래, 번역 후보를 제안한다. 의미가 여럿인 용어만 등장 사례를 의미에 연결한다(보기 고르기 → System One choice 질문에 적합).

### 3.2 순서와 시점 [계획]

분기가 있으므로 "몇 장부터"로 시점을 적지 않는다. 대사 L과 다른 지점 X의 관계는 대사 그래프(노드 단위)로 계산한다.

| 관계 | 판정 | 뜻 |
|---|---|---|
| 반드시 거침 | 시작점에서 L까지 모든 경로가 X를 지난다(X가 L의 지배 노드) | 이 시점에 확실히 일어났다 |
| 거쳤을 수 있음 | X에서 L로 닿지만 지배 노드는 아님 | 루트에 따라 다르다 |
| 이후 | L에서 X로 닿고 반대는 안 됨 | 아직 아니다 |
| 반복 가능 | 서로 닿음(순환) | 따로 표시 |
| 서로 닿지 않음 | — | `graph.flow`가 `complete`면 한 플레이에서 함께 안 나옴, `partial`이면 순서 모름 |

- 조건 분기는 가능한 경로를 줄이기만 하므로, 조건을 무시하고 계산한 "반드시 거침"은 보수적으로 맞다.
- 지식마다 **기준 지점 집합**(일어나거나 밝혀지는 대사·노드. 루트마다 다를 수 있음)을 둔다. L에서의 상태는 확실(기준 지점 집합이 L을 지배) / 루트에 따라 다름 / 아직 아님 / 모름이다.
- 말투 구간도 같다: 뒤 구간의 시작 지점이 앞 구간의 시작 지점에 지배되고 둘 다 L에 대해 확실할 때만 뒤 구간을 쓴다. 그 밖은 "말투 불확실"로 표시하고 지어내지 않는다. [1차 구현됨: `graph-order.ts`. 확실히 거친 시작 중 가장 늦은 것을 쓰고, L로 이어지지 않는 갈래의 시작은 대본 순서상 앞이어도 쓰지 않는다. 시작 지점이 L로 이어지지만 지배하지 않으면(어느 루트에선 안 거침) 대본 순서로 고르고 "루트에 따라 달라 대본 순서 기준"으로 표시하며, 규칙의 "적용되는 대사"에 그 수를 밝혀 사람이 확인하게 한다(2026-10-12 결정: 허브가 많은 게임에서 규칙을 빼면 쌍 대부분의 규칙이 사라지고, 한 줄의 번역은 어차피 하나라 골라야 한다). 줄이나 시작 지점이 그래프 밖이거나 서로 이어지지 않은 그래프 조각(장마다 따로 만든 그래프)에 있어도 대본 순서로 고르고 "그래프 밖이라 대본 순서 기준"으로 표시한다]
- **작품의 사실**(기준 지점 없음, 번역자용), **밝혀지는 지점**, **인물의 믿음**(누가·기준 지점·나중에 거짓으로 밝혀질 수 있음)을 나눈다. "A와 B가 형제"가 후반에 거짓으로 밝혀지면, 사실은 "형제 아님", 믿음은 "그 지점까지 형제라고 믿음"으로 둘 다 남는다.

### 3.3 근거 층(주장) [계획]

AI는 대본에서 **근거 달린 주장**을 뽑는다. 예: "Bob은 Carol을 'sis'라고 부른다 — 근거 C1-014".
- 주장마다 **인식 수준**: `observed`(원문에 그대로 쓰여 있고 인용이 곧 근거) / `inferred`(동기·인과·지칭처럼 추론이 필요).
- **검증**은 코드가 하는 것만 그렇게 부른다: 근거 키가 있는가, 인용이 원문과 같은가. 근거가 주장을 지지·반박·판단 불가 중 무엇인지는 **모델 판단**으로 기록하고(모델 이름 포함), 종류별 정확도를 사람 표본으로 잰다. `inferred`는 어떤 모델 판단으로도 자동 확정되지 않는다.
- 주장은 사람이 하나씩 승인하는 대상이 아니라 초안의 바탕이다. 자동 저장되지만 확인 전에는 2.4의 "원문 근거"·"추론 힌트"로만 쓰인다.
- 서로 맞지 않는 주장은 하나를 고르지 않고 "근거가 엇갈림"으로 드러낸다.
- 주장은 지우지 않고 상태를 바꾼다(`candidate`/`accepted`/`rejected`/`superseded`, 분석이 낡으면 `stale`).

### 3.4 초안과 확인 [계획]

- 사람이 확인하는 단위는 **초안 하나**(인물 프로필, 관계, 사건, 말투 규칙)다.
- 초안의 문장마다 근거를 바로 열어 볼 수 있다.
- 프로필·관계·사건 초안과 검색 대상은 **주장에서 다시 만들어지는 결과물**이다. 따로 고치는 사본이 없으므로 주장 상태가 바뀌면 바로 빠진다. 사람이 고친 문장은 그 위에 덮는 층이라 다시 분석해도 남고, 근거 대사가 바뀌면 "근거가 바뀜"만 표시한다.
- 주장이 바뀌면 그 주장을 문맥에 썼던 번역(실행 기록의 문맥 항목으로 찾음)에 재검토 태그를 붙이자고 **제안**한다. 자동 재번역은 없다.
- **정본은 앱 DB다.** AI는 DB를 직접 바꾸지 않는다. `.loca/`의 분석 결과는 분석 실행 하나의 산출물이며, "분석 결과 가져오기" 제안을 사람이 수락해야 DB에 들어간다.
- 분석 결과에는 (단계, 장면, 입력 해시, 프롬프트 버전, 모델)을 붙인다. 대본·프롬프트가 바뀌면 해시가 달라진 장면만 다시 돌리고 영향받는 통합 결과만 다시 계산한다. 실패한 장면은 그것만 다시 시도하고, 빠진 장면은 커버리지로 표시한다.
- 분석 절차(가설): 뼈대(코드: 화자·그래프 관계) → 개요 → 장면별 분석(개요를 보며 지칭 해소) → 통합(별칭·사건 병합, 관계 변화, 충돌) → 검증(코드)·모델 판단. 실험에서 한 번에 전부 읽기와 비교한다.
- 분석은 워크플로 엔진(대사 1개 = 실행 항목 1개)에 넣지 않는다. 실험 동안은 스크립트, 검증되면 프로젝트 단위 백그라운드 작업.
- 확인 화면은 실험 결과를 본 뒤 만든다.

### 3.5 누가 정했나: AI와 사람 [구현 중: 2026-10-13]

상태는 그대로 두고, 모든 곳에 **"현재 상태를 누가 정했나"(AI / 사람)** 한 칸을 더한다. 상태를 AI용·사람용으로 둘로 나누지 않는다.

- **대상과 상태**: 대사의 상태는 사용자가 정의한 단계 그대로, 자료(문서·인물·관계·사건·말투 규칙)와 용어의 상태는 정해진 후보 / 확정 / 버림 그대로다. 여기에 `status_by`(ai / human)가 붙는다. 대사는 AI가 정했으면 그 실행(`status_run_id`)도 남긴다.
- **자동으로 기록한다**: 워크플로의 '상태 변경' 노드(후보를 대표 번역으로 올리기 포함), 작품 분석, '자료 반영'·'용어 후보 추가' 노드가 정한 것 → AI. 사람이 상태를 바꾸거나, 번역을 고치거나, ⌘↵로 다음 상태로 보내거나, 자료·용어를 고치거나 올리거나 버리거나, 채팅·CLI 제안을 수락하거나, 파일을 가져온 것 → 사람. 사람 손을 탄 AI 항목은 다시 분석해도 바뀌지 않는다(예전 `reviewed`를 대신한다).
- **출처는 따로다**: 출처는 내용을 누가 만들었는지(작품 분석 / 워크플로·채팅 / 대본에서 찾음 / 가져오기 / 사람)이고, 누가 정했나는 지금 상태를 누가 정했는지다. 사람이 내용을 고치면 출처도 사람이 된다. 사람이 고치지 않고 올리기만 하면 출처는 그대로이고 정한 쪽만 사람이 된다.
- **표시는 하나**: AI가 정했고 아직 사람이 보지 않은 상태에는 상태 칩·확정 표시 옆에 작은 ✦ 하나(`AiMark`, 툴팁 "AI가 정함 · 아직 사람이 확인하지 않음")를 붙인다. 대사 목록에서는 중복을 피하려고 번역 아래 #AI가 정함 칩 하나로 표시한다(편집 중에도 동일). 후보는 원래 결정 전이라 ✦을 붙이지 않는다.
- **확인함**: 고른 대사·자료·용어의 상태는 그대로 두고 정한 쪽만 사람으로 바꾼다. 자료·용어 후보에서는 같은 버튼이 '정식으로 올리기'(확정 + 사람)다.
- **AI를 어디까지 허용할지**
  - 번역: 워크플로가 이미 정한다(상태 변경 노드를 어디까지 두느냐). 더해 상태마다 **'사람만 지정'**을 켤 수 있다(설정 › 상태·태그). 실행이 그 상태로 보내려 하면 대신 첫 '검토함에 표시' 상태로 보내고 이유("‘최종’은 사람만 지정할 수 있어 검토함으로 보냈습니다")를 줄의 지적 사항으로 남긴다. 검토함 상태가 없으면 상태를 바꾸지 않고 같은 이유를 남긴다. 후보는 대표 번역으로 올라가고 태그는 그대로 바뀐다.
  - 자료·용어: AI › **사용 방식**에서 종류(용어·문서·인물·관계·사건·말투 규칙)마다 AI 결과를 '자동 확정'(바로 문맥에 쓰임, ✦ 표시) 또는 '후보로만' 받는다. 작품 분석, '자료 반영', '용어 후보 추가'가 모두 이 설정을 따르고 각자의 스위치는 없다. 기본은 모두 자동 확정. 번역이 빈 용어는 늘 후보, 말투 규칙의 '확인 권장' 조건(대사가 많은 주요 쌍, 엇갈리거나 근거가 맞지 않음)은 자동 확정일 때 그대로 붙는다.
- **쓰는 쪽이 고른다**: AI 노드의 문맥 설정에 **'사람이 확정한 것만'**(기본 끔 = AI 확정 포함)을 둔다. 켜면 그 노드의 프롬프트에는 AI가 확정하고 아무도 확인하지 않은 용어·자료가 들어가지 않는다(검수 노드를 사람 확정 기준으로 돌릴 때).
- **찾기**: 대사 목록과 모든 자료·용어 표에서 자동 표시 #AI가 정함으로 거른다(URL의 `marks`). 홈의 할 일에 '#AI가 정함' 수를 대사·문서·인물·관계·말투 규칙·사건·용어별로 보이고, 각 수는 그 링크가 여는 목록과 같은 정의(`marks.ts`의 aiDecided·statusBy 'ai')로 센다.

## 4. 정보 구조 [구현 중: 2026-10-13 개편]

메뉴는 일의 흐름(문맥 준비 → 실행 → 번역·검토) 다섯 개다. 같은 메뉴 안의 화면은 상단 바의 **섹션 탭**으로 오간다(탭마다 주소가 따로라 Back/Forward와 링크가 그대로 동작한다).

```
[프로젝트 전환]   상단 바: 섹션 탭 · 검색(⌘K) · 채팅 토글
─ 홈        다음 할 일(검토 대기 · 청자 미상 · 확인 권장 말투 규칙 · AI가 확정하고 확인 안 한 것 · 멈추거나 실패한 실행; 누르면 그 조건으로 걸러진 화면), 상태별 진행, 진행 중 실행
─ 번역      [대사 | 그래프]
   대사     왼쪽 묶음 목록(장별 접힘, 진행 막대, 맨 위 '모든 대사'·'검토 대기') · 가운데 대사 목록(고른 줄에서 바로 번역 편집, 키보드로 이동·저장·다음 상태) · 우측 대사 패널(검사 / 후보·이력 / AI 문맥).
            검토함은 따로 없다: '검토 대기'는 ‘검토함에 표시’ 상태의 대사만 거르는 필터이고, 최근 실행의 지적 사항을 줄마다 보인다
   그래프   장면 그래프(파생 연결, 여러 장면을 잇는 허브는 '연결점' 노드) / 대사 그래프(원본 노드, 연결이 아주 많은 허브의 간선은 배치에서 빼고 연한 직선으로) 전환. 대사 그래프는 구역(장·Day)마다 따로 배치해 구역 선택으로 보고("전체 (한 장)"도 고를 수 있다), 장면 밖 노드는 제시되는 구역에 붙으며 다른 구역으로 이어지는 선은 "→ 구역" 이름표 노드로 그린다.. 채팅 에이전트는 show_graph로 장면·화자·대사 키·본문 검색(+앞뒤 N단계)으로 노드를 골라 보기를 만든다: '강조'는 가장 많이 담긴 구역에서 그 노드만 진하게(강조 해제 가능), '따로 그리기'는 고른 노드만 배치하고 바깥으로 이어지는 선은 이름표로 그린다. 채팅 결과의 '그래프에서 보기'로 연다(보기는 graph_views에 노드 집합으로 저장, URL의 mark·section으로 다시 열림). Canvas. 선택 → 우측 상세 → 장면·대사로 이동. 대사 그래프에서는 패널의 줄을 누르거나(마우스를 올리면 연필) 캔버스에서 Enter로 **노드 옆 번역 카드**를 열어 그 자리에서 번역한다(⌥↓/⌥↑ 흐름을 따라 다음·앞 줄, 갈림길·합류에서는 멈추고 알림)
─ 문맥      [문서 | 인물·관계 | 사건 | 용어집]
   자료     문서 / 인물·관계 / 사건. 인물·관계는 한 그래프(인물 노드 + 관계 선; 인물을 누르면 우측에 인물 프로필, 선을 누르면 그 쌍의 관계·말투 규칙; 노드는 끌어 옮기면 이 브라우저에 기억, '배치 되돌리기'; 선 이름은 고른·가리킨 인물의 선에만) 또는 표 두 개(관계 / 인물). 사건은 흐름 그래프(기본) 또는 표. 흐름은 구역(장·막·Day)마다 위에서 아래로 놓고, 사건 위치는 근거 대사 중 가장 앞 대화 줄(대화 근거가 없을 때만 UI·문서 줄), 근거가 대본에 없으면 '위치 모름'. 선은 대사 그래프에서 한 사건의 줄이 다른 사건의 줄로 이어질 때만 바로 다음 사건에 긋고, 한 사건에서 여러 선이 나가는 것은 같은 선택지·조건에서 갈라질 때뿐이다(선택지 이름 표시, 갈래 속 갈래도 그대로). 상태 노드가 함께 여는 장면들처럼 그 밖의 경우는 선 없이 대본 순서로 둔다. 카드는 끌어 옮기면 이 브라우저에 기억, '배치 되돌리기'). 작품 분석은 이미 있는 인물(가져온 이름만 있는 인물 포함)의 빈 프로필·말투·근거만 채우고 써 둔 것은 바꾸지 않는다
   용어집   표 + 우측 상세
─ 워크플로  [워크플로 | 실행 기록 | API 키]   (사이드바는 구분선으로 홈 | 번역·문맥 | 워크플로·AI, 설정은 맨 아래)
   워크플로 목록 → 편집기(React Flow) → 실행(범위는 번역 화면에서 고른 묶음·대사가 미리 채워짐)
   실행 기록 AI가 한 일 전부를 작업 하나씩 한 표로: 워크플로 실행·작품 분석·용어 AI 채우기(상태·진행·AI 호출 수와 입력/출력 토큰). 채팅은 작업이 아니라 대화라 여기 없고, 채팅 패널의 대화 목록에 대화별 요청 수와 토큰을 보인다. 행을 누르면 우측 패널에 그 작업의 모델 요청(무엇·연결·모델·토큰·시간·실패 이유, 진행 중 실시간)과 실행 상세 / 자료 / 용어집 링크. 작품 분석·용어 채우기 호출은 보낸 내용(지시문과 대본)을 남겨 호출마다 "보낸 내용"으로 펼쳐 본다(크기·추정 토큰·복사). 실패한 호출은 모델·CLI가 실패 전까지 출력한 것(원문 출력 또는 잘린 답, 끝 20만 자)도 "받은 출력"으로 남아 같은 자리에서 펼쳐 본다. 진행 중인 작품 분석은 단계(대본 준비: 줄·장면·추정 토큰 → AI가 읽는 중: 모델·경과·예상 시간 → 결과 검사와 저장)로 보이고, 예상 시간은 같은 모델의 지난 분석 속도(입력 1천 토큰당 초, 앱 전체 기록의 중앙값)로 계산하며 기록이 없으면 없다고 말한다. 작업이 끝나거나 실패·멈추면 어느 화면에서든 알림(결과 요약과 이동 버튼)이 뜬다. 다른 화면의 링크로 연 대사는 그 대사가 있는 페이지가 열리고 목록 가운데에서 한 번 깜빡인다. 모델 시험은 프로젝트 밖이라 AI › 연결의 그 연결 패널(최근 시험)에. 개요의 실행 카드도 진행 중 호출을 보인다
   API 키   HTTP 호출 노드가 고르는 키(OS 키체인), 그 노드만 쓴다(AI 연결의 키는 연결마다 따로). 앱 전체 공용
─ AI        [연결 | 사용 방식]
   연결     AI를 부르는 통로(API·CLI·pi) 표 → 우측 패널: 설정 · 기본 모델(추론 수준) · 호출 조건(시간 제한·최대 시도·최대 출력 토큰·동시 실행 수) · 막히면(이 연결이 요청 한도·네트워크·시간 초과로 실패하면 넘길 다른 연결·모델, 그 연결의 "막히면"도 이어서 따른다, 최대 3단계) · 시험(모델을 골라 한 문장 번역, 최근 시험) · 삭제(노드·대화·막히면 경로가 쓰는 연결은 지울 수 없다고 어디서 쓰는지 말한다). 연결과 키는 모든 프로젝트 공용
   사용 방식 AI가 사람 대신 하는 것을 한곳에: ① 편집기 AI(AI 번역·다듬기 모델 — CLI도 됨 · 자동완성 켜기·API 모델 · 둘이 같이 쓰는 하루 한도, J3b) ② AI가 만든 것을 바로 확정(자료 종류·용어마다 자동 확정 / 후보로만) ③ AI 에이전트 도구(채팅·터미널) — 채팅 패널의 AI와 loca tools·loca call이 같은 도구를 쓴다. 대상(대본·번역 / 자료 / 용어집 / 워크플로 / 상태·태그 / 웹) × 할 일(읽기 / 변경 제안 / 실행) 표로, 칸마다 스위치 하나(일부만 켜졌으면 n/m). 줄을 펼치면 도구별 스위치. 편집기 연동은 워크플로 × 변경 제안이다. 터미널 읽기 명령과 워크플로에는 영향 없음
─ 설정      [프로젝트 | 상태·태그]

   상태·태그 사용자 정의 상태(초기/일반/최종, 색, 검토함 표시, 사람만 지정)와 태그
```

## 5. 사용자 여정과 수용 기준

공통: URL search params가 화면 상태(필터·정렬·페이지·선택·탭)의 기준이다. 표의 필터는 엑셀처럼 열 머리글에서 고른다. 그래프 viewport와 미저장 초안은 sessionStorage에 둔다. 저장이 끝나면 그 저장에 보낸 글과 지금 초안이 같을 때만 초안을 지운다: 응답을 기다리는 동안 더 고친 초안은 저장 성공·실패, 줄 이동, SSE 갱신 뒤에도 남는다(번역 편집기·자료 편집기 공통). 오른쪽 창·설정의 폼(용어, 자료 항목, 프로젝트, 형식 규칙, 상태·태그, pi 설정)은 항목마다 미저장 수정을 따로 보관해 다른 항목으로 갔다 오거나 Back/Forward·새로고침해도 남는다(새 항목 추가 폼은 그 창 안에서만). 수정 시작 때의 값을 기준으로 사람이 바꾼 필드만 사람 것이고, 손대지 않은 필드는 다른 곳(채팅 제안 수락, 워크플로, 다른 창)에서 바뀐 값을 그대로 따라가며 저장은 사람이 바꾼 필드만 보낸다. 같은 필드가 양쪽에서 다르게 바뀌었으면 "고치는 동안 …이(가) 다른 곳에서 바뀌었습니다"를 보이고 '바뀐 내용 불러오기'/'내 수정 유지' 중 사람이 고른다. 수용 기준: 용어 A의 메모를 고치고 B로 갔다 A로(또는 Back) 돌아오면 메모가 남아 있다. target=T1·note=N1에서 note만 N2로 고치는 동안 다른 곳에서 target이 T2가 되면, 화면은 T2를 보이고 저장 뒤에도 target은 T2다.
Back/Forward는 이전 화면 상태를 복원한다. 서버 변경은 SSE 토픽으로 받아 해당 쿼리만 다시 읽는다. 쓰기 요청은 응답 헤더(x-changed)에도 자신이 바꾼 토픽을 실어, 화면이 SSE를 기다리지 않고 바로 다시 읽는다(SSE가 끊겨도 저장이 바로 보인다). SSE는 20초마다 ping을 받고, 45초 동안 아무것도 안 오면 다시 연결하며 그동안 놓친 것을 전부 다시 읽는다. 폴링·SSE 갱신·이동은 방문 기록을 만들지 않는다.
URL 파라미터 이름 규칙: 창에서 고른 항목은 그것이 무엇인지로 부른다(`line`·`node`·`term`·`status`·`tag`·`mark`·`key`·`conn`·`job`·`run`, 종류가 섞인 자료 항목은 `item`). 나머지는 뜻마다 이름 하나: 탭 → `tab`(실행 상세의 `steps|plan` 포함), 표현 방식(그래프·표·타임라인·카드) → `display`(자료 › 인물·관계의 `table`=관계 표, `characters`=인물 표), 대사 화면의 '장면에서 찾아가기' → `mode=find`(목록이 기본이라 값이 없다). 옛 이름의 별칭은 두지 않는다. `view`는 쓰지 않는다.
검색 상자는 한 가지로 동작한다: 입력하는 동안 목록이 걸러지고(250ms 쉬었다가 반영, 한글 조합 중에는 반영하지 않음) 값은 URL에 `replace`로 쓰여 방문 기록을 만들지 않으며, Esc나 지우기 버튼은 바로 지운다(`SearchInput`). 대사 `q`, 묶음 목록 `gq`, 용어집 `q`, 그래프 노드 찾기 `q`, 실행 창의 장면 찾기(창 안 상태)가 모두 이것이다.
여러 줄을 체크박스로 고른 것(`usePicked`)은 화면·프로젝트·목록(장면·검토함, 자료 탭·표현)마다 sessionStorage에 둬서 Back/Forward와 새로고침 뒤에도 남는다. 그 목록을 떠나면 그 목록의 고름은 다음에 돌아올 때까지 그대로 있고, 동작이 끝나면 비운다.

**J1. 프로젝트 시작** [구현됨] — "표준 파일 가져오기" → 검증 결과(장면/대사/그래프 수, 오류 위치, 경고: 그래프 밖 대사·인물 목록에 없는 화자·빈 원문) → 생성. 같은 검사를 `loca format check`로 앱 없이 돌릴 수 있다.
기본 상태 세트와 기본 워크플로 템플릿이 함께 만들어지고 그래프 배치는 서버 백그라운드에서 한 번 계산된다(진행 표시).
가져온 뒤 홈 맨 위의 **시작하기**가 일의 순서를 보인다: ① AI 연결 추가 ② 작품 분석 ③ 말투 규칙 훑어보기(선택) ④ 용어 정하기(선택: 용어가 없으면 "대본에서 용어 찾기"(코드, AI 비용 없음)를 이 단계에서 누른다. 자동으로 돌리지 않는 것은 후보가 어디서 왔는지 보이게 하려는 것. 그 뒤엔 후보 수와 번역이 빈 수, 용어집으로) ⑤ 번역 실행 ⑥ 검토하고 확정. 단계는 프로젝트 데이터(연결·끝난 분석·확인 권장 규칙·확정 용어·실행 기록)로 저절로 체크되고, 아직 안 한 필수 단계 중 첫 단계에만 주 버튼이 붙는다. 분석과 실행이 한 번씩 끝나면 사라진다.
복구: 스키마 오류는 경로와 함께 표시하고 아무것도 저장하지 않는다.

**J2. 번역·원문 탐색** [구현 중] — 번역 › 대사: 왼쪽 묶음 목록(장별 접힘, 진행 막대, 제목 검색, 종류 필터)에서 묶음을 고르면 가운데에 그 묶음의 대사가 대본 순서로 나온다. 맨 위 '모든 대사'는 묶음과 관계없이 전체, '검토 대기'는 검토 상태의 대사(J7). 대사 목록 도구 막대의 [필터] 하나에, 위에는 태그처럼 보이는 목록이 있다: **자동 표시**(#남은 줄 · #AI가 정함 · #청자 미상(대사만) · #같은 원문 다른 번역 · #메모 — 저장하지 않고 줄에서 계산하므로 어긋나지 않는다; 목록·자료·용어집 모두 URL 파라미터 하나 `marks`(표시 id 배열)로 거르고, 정의는 `packages/shared/src/marks.ts` 한 곳이다. 대본은 고른 표시가 모두 있는 줄만 남기지만, 자료·용어의 #후보와 #AI가 정함은 한 항목이 둘 다일 수 없으므로 같이 고르면 둘 중 하나인 항목을 보인다. 청자 이름은 `listener`, 메뉴에는 이름만), **문제 유형** 태그, **내 태그**. 여러 개를 고르면 모두 해당하는 줄만 남는다(메뉴는 열린 채). 아래에는 상태·화자·청자 하위 메뉴. 고른 것은 칩(#이름)으로 보이며 URL에 남는다(태그는 여러 개). 필터는 두 가지로 보인다(기본은 모든 필터가 **목록**, 해당 줄만): **찾아가기**([장면에서 찾아가기]) — 장면을 원래 순서대로 다 보이고 해당 줄에 표시, 위의 찾기 막대가 '장면 전체에서 #청자 미상 찾는 중 3/472줄 · 이 장면 20줄'과 [↑][↓](⌥↑/⌥↓, 장면 끝에서 다음 장면으로)를 보이며, 장면 목록에는 장면별 해당 줄 수가 붙고 장면을 바꿔도 필터가 유지된다. 처리해서 해당하지 않게 된 줄은 다음 줄로 넘어간다. **목록**(기본, 찾아가기에서는 [맞는 줄만 보기]) — 해당 줄만 모아 보이고 장면이 바뀔 때마다 장면 제목 줄([장면 열기])을 둔다. 목록에서는 [장면에서 찾아가기]로 돌아간다. 맥락이 필요한 일(청자·말투·검수)은 찾아가기, 여러 줄을 한꺼번에 바꾸는 일은 목록이다.
가운데 목록의 줄을 고르면 그 자리에서 번역 편집기가 열린다(다른 줄은 읽기 전용 텍스트). 키보드: 편집기 밖에서 ↑↓ 또는 어디서든 ⌥↑↓로 줄 이동(찾아가기 중에는 ⌥↑↓가 이전·다음 해당 줄), ↵로 편집기에 들어감, 편집기에서 ⌘S 저장, ⌘↵ 저장하고 다음 상태(기본은 최종 상태)로 옮긴 뒤 다음 줄, Esc는 편집기에서 나옴(초안은 남는다). 화자·청자·상태·태그는 열 머리글에서 거른다.

(이 문서의 단축키는 맥 표기다. 화면의 안내는 운영체제를 따라 윈도우·리눅스에서 ⌘→Ctrl, ⌥→Alt, ⇧→Shift로 보인다: lib/keys.ts의 keyLabel.) 편집기는 순수 텍스트(저장되는 것은 입력한 그대로)지만 CAT 툴처럼 돕는다: 서식 토큰(자리표시자·태그)은 원문과 번역 모두 원문 순서대로 번호 칩으로 보이고 한 번에 지워진다. CAT 툴처럼 여는 태그와 닫는 태그는 한 쌍에 번호 하나(⟨1 … 1⟩, 감싸는 범위가 보인다), 짝 없는 토큰은 ⟨2⟩. 칩은 번호마다 색이 다르다(6색을 돌려 씀, 경고·선택지·성공 색은 피함): 쌍과 번역 속 같은 토큰이 색으로도 맞는다. 내용은 마우스를 올리면 바로 툴팁. 번역의 토큰은 원문의 같은 토큰 번호를 따르고(닫는 태그는 자기가 닫는 태그의 번호) 원문에 없는 토큰은 ?(경고색). 목록의 다른 줄과 제안도 같은 칩. ⌥1…9로 n번째를 넣는다(⌘1…9·⌘⇧T는 브라우저·데스크톱 앱이 탭 단축키로 먼저 가져가 페이지에 오지 않는다): 짝 없는 토큰은 커서 자리에, 쌍은 고른 글자를 감싸고, 고른 게 없으면 한 번에 하나씩 — 처음 누르면 여는 태그, 커서를 옮겨 다시 누르면 닫는 태그(memoQ F9). 한글 조합 중에 눌러도 조합이 끝난 뒤 들어간다(Tab도 같다). 원문의 칩을 눌러도 같다. 원문의 확정 용어는 밑줄(마우스를 올리면 번역어, 누르면 커서 자리에 넣음)이고, 번역에 쓰인 용어 번역어는 표시되며 입력 중 자동완성으로 나온다(태그 안의 글자는 용어로 보지 않는다). ⌘⇧S 원문 복사. [그래프에서 보기]·[자세히]는 확정 버튼 아래가 아니라 고른 줄의 화자 줄 높이, 번역 열 오른쪽 아이콘이다(편집기 아래는 번역에 필요한 것만: 버튼·힌트·제안). 편집기 아래 **제안**(최대 3개, ⌥⇧1…3; 넣으면 입력 칸을 바꾸고 ⌘Z로 되돌린다): 이 줄의 다른 후보 → 같은 원문을 다른 곳에서 번역한 것(대소문자·문장부호·토큰 내용 무시, 화자 → 청자 표시, 미확정 표시) → 비슷한 줄(단어 단위 편집 거리 70% 이상, 다른 단어 표시). 프로젝트 자체가 번역 메모리다(외부 TMX는 아직 없음). 검사에는 원문 숫자 누락과 공백(이중·앞뒤), 그리고 번역 언어가 한국어면 **변수 뒤 조사**(`{name}을`: 값의 받침에 따라 틀림, 을(를) 병기형은 통과)가 더해졌다. 새 번역을 저장하면 같은 원문(대소문자·끝 문장부호 무시)인데 최종이 아니고 다르게 번역된 줄을 알림으로 알리고 [모두 이 번역으로]를 제안한다(누르기 전엔 바꾸지 않음, 화자→청자를 함께 적어 말투가 갈릴 수 있음을 보인다). 필터 메뉴의 **번역이 갈린 같은 원문**은 같은 원문이 서로 다르게 번역된 줄만 보인다. 머리줄의 키보드 버튼이나 `?`로 단축키 목록(운영체제 표기)이 뜬다. 그래프 패널의 대사 표도 번호 칩을 쓴다. 원문에서 낱말을 드래그하면 그 자리에서 **용어로 추가**(번역은 편집기에서 골라 둔 글로 채워짐, 이미 있으면 알림). 고른 줄의 화자 줄 메모 버튼으로 **줄 메모**(의문점, 개발사에 물어볼 것)를 남긴다: 편집기 아래 노란 칸, 목록에서는 번역 아래 #메모 칩, 필터 메뉴의 "메모 있는 줄". 메모는 상태·누가 정했나를 바꾸지 않는다. 화자 이름에 마우스를 올리면 **화자 카드**: 인물 프로필·말버릇, 청자별 말투 규칙(말투·호칭, 확인 전 표시), 인물·관계로 가는 링크(번역 목록과 그래프 카드). 편집기 아래 **이전 번역과 비교**: 지금 번역과 그 앞의 다른 후보를 단어 단위로(지운 말 취소선, 더한 말 표시). 실행이 정한 줄(✦)은 펼친 채, 사람이 정한 줄은 링크로 접어 둔다. 그래프 카드에도 줄 메모가 있다. 길이 제한은 게임마다 다르므로(글자 수·UTF-8·UTF-16·EUC-KR 바이트) 프로젝트가 켤 때만 쓰는 규칙으로 남겨 둔다(미구현).
우측 대사 패널: 원문·화자·청자·상태·태그, 탭 [검사(형식·용어·말투, 최근 실행의 지적) | 후보·이력 | AI 문맥].
대사 목록에는 줄마다 체크박스가 늘 있고(선택 모드 없음), 목록 위 **머리줄**이 평소에는 [☐] 원문 · 번역 열 이름, 줄을 고르면 'n개 선택 · 확인함 · 상태 바꾸기 · 청자 바꾸기(대사만; 이 목록의 화자 → 여러 사람·혼잣말 → 다른 인물 → 직접 입력) · 태그 · 선택 해제'로 바뀐다(머리줄 체크박스는 보이는 줄 전체, 일부면 반쯤). 버튼 이름은 짧게(상태 · 청자) 두고 목록 폭이 좁으면 확인함 · 태그 · 선택 해제가 아이콘만 남아 머리줄이 한 줄을 지킨다. 청자를 모르는(또는 AI가 자신 없는) 대사는 화자 옆 청자 자리에 경고색 '→ 청자 미상'이 보이고, 누르면 #청자 미상 필터가 걸린다(행은 선택되지 않는다). 알려진 청자 이름에 마우스를 올리면 화자처럼 인물 카드가 뜬다. 고른 줄에서는 '→ 청자 ⌄'를 눌러 그 자리에서 청자를 바꾼다(대사 패널의 청자 선택과 같은 목록: 이 장면에서 말하는 사람 → 여러 사람·혼잣말 → 다른 인물 → 직접 입력). 고른 줄의 원문 아래에는 원문에 나온 확정 용어 칩, 그 아래 인물 정보(이 화자 → 청자의 말투 규칙 — 입력 중 번역의 말투가 다르면 경고색 —, 화자의 말버릇, 둘의 관계를 한 줄씩), 맨 아래 메모가 온다. 청자는 원문의 맥락이라 태그 줄에 칩으로 두지 않는다. 화자 줄에는 태그·메모 아이콘을 두지 않고, 상태(✦ 포함)는 번역 열 위에 이름으로 보인다. [AI 실행]은 도구 막대 오른쪽 하나뿐: 고른 줄이 없으면 열린 장면, 있으면 'AI 실행 · 고른 n줄'. 실행 창은 그 범위가 채워진 채 열린다. 아래 막대는 쪽 넘김만. 줄은 체크박스 · 원문 · 번역 세 열이 같은 세 행(화자 줄 | 본문 | 태그)을 나눠 쓰는 그리드다(번역 열 앞에 세로선). 원문과 번역의 첫 줄은 화자 줄·태그 높이와 관계없이 늘 같은 높이에서 시작하고, 고른 줄도 글자 크기가 그대로라 줄바꿈이 바뀌지 않는다. 원문 위 작은 줄이 상태 점 다음에 화자를, 화자가 없는 줄은 종류(UI · 문서 · 지문)를 흐리게 보인다. 고른 줄의 [그래프에서 보기]·[메모]·[자세히] 아이콘은 같은 행의 번역 열 오른쪽 끝이다. 번역이 없으면 흐린 '미번역'. 장면 제목 옆 아이콘이 [대사 그래프에서 보기]·[AI로 요약(채팅)]이고, 진행도는 장면 목록에만 있다. 장면 목록의 '장면 찾기'는 장면이 20개 이상(또는 검색 중)일 때만 보인다. 장면 목록의 장(章)은 처음에 모두 접혀 있다. 장면을 고르면(링크·찾아가기 포함) 그 장이 한 번 펼쳐지고, 사용자가 다시 접으면 다른 장면을 고를 때까지 접힌 채다. 장면 검색 중에는 결과가 보이도록 모든 장이 펼쳐진다. 펼친 장은 탭마다 sessionStorage에 남는다.
태그는 상태와 별개인 다중 표시로, 선택한 대사에 붙이거나 떼고 실행 범위로 쓴다(태그마다 체크 하나, 일부만 붙으면 ‘일부’). 대사 행의 번역 아래에는 해당하는 자동 표시와 태그를 #AI가 정함 → #메모 → 문제 유형 → 사용자 태그 순으로 한곳에 모은다(#청자 미상은 화자 옆 청자 자리)(#남은 줄은 너무 흔해 뺀다). 편집 중에도 입력 칸 바로 아래, 버튼·힌트·제안 위의 같은 태그 줄을 사용하고 번역이 없어도 표시한다. 작은 칩으로 보이고, 누르면 그 태그로 목록이 걸러진다(행은 선택되지 않는다). 실행 시작의 '태그로'는 **자동 표시**를 태그 위에 함께 보여 주며, 대사 목록 필터와 같이 고른 표시와 태그를 모두 가진 줄이 범위다. 조건 노드는 `unit.marks`(`CONDITION_MARK_IDS`: remaining · ai · unknownListener · noted)로 "줄에 #메모 표시가 있음"처럼 같은 표시를 태그처럼 검사한다.
그래프: 전체 맞춤 → 확대/이동 → 노드 클릭 → 우측 상세 → "장면에서 보기". Back은 viewport와 선택을 복원.
검색(⌘K)은 프로젝트 어디로든 가는 이동: 장면 제목, 용어(원어·번역어 → 용어집), 인물(이름·별칭 → 자료 › 인물), 자료 문서(제목·본문), 대사(원문·번역·화자·ID → 장면의 그 줄). 대사 목록의 '찾기'는 보이는 줄을 거르는 것으로 역할이 다르다.
수용: 9,000+ 노드 그래프에서 pan/zoom이 끊기지 않고(Canvas 1개), 체인 간선이 곧게 아래로 내려간다.

**J2 태그 배치 변경 (2026-10-14)** — 진입: 장면 또는 검색·태그 필터가 걸린 대사 목록. 행동: 번역 아래의 자동 표시·문제 유형·사용자 태그를 읽고 누르면 현재 목록에 해당 필터를 적용한다. 태그 클릭은 행을 열거나 체크박스를 바꾸지 않는다. 편집기를 열어도 같은 순서로 입력 칸 아래에 표시하고, 저장 전 초안에 대한 새 판정은 하지 않는다(태그는 저장된 줄 기준). 보존: URL의 검색·태그·표시·장면·선택·페이지와 sessionStorage의 초안·체크 선택. 복귀: 그래프 이동 후 native Back/Forward와 새로고침에서 해당 상태가 복원된다. 증거: 번역이 없는 줄과 있는 줄, 편집 중인 줄 모두 오른쪽에서만 태그가 보이고, 한 줄에 #AI가 정함이 한 번만 보인다. 9,040줄 목록에서도 같은 배치와 필터를 확인한다.

**J2b. AI 문맥 보기** [구현됨] — 대사 패널 "AI 문맥" 탭 → AI 노드 고르기(워크플로 › 노드, 기본은 번역 후보를 만드는 첫 노드) → 이 대사의 앞 대사(갈래별), 묶음에 넣는 문맥 항목(이유·추정 토큰·상한 초과로 뺀 것), 실제 프롬프트. 탭과 노드는 URL(`lineTab`, `aiNode`)에 남는다. 실행 상세 › AI 호출의 각 단계에서도 넣은 문맥을 본다.

**J3. 대사 검사** [구현됨] — 대사 패널은 편집기의 번역 기준으로 형식 검사(자리표시자·태그·줄바꿈·빈 번역)와 원문에 나온 용어(확정·후보, 반영 여부)를 바로 보인다.

편집기의 검사 줄 [구현됨: 2026-10-14] — 기준은 원문 아래(용어 칩·말투 규칙·원문 서식 칩, 지금 번역과 맞는지 ✓/⚠), 판정은 입력 칸 아래 한 줄: 빠진 서식은 칩(누르면 넣기), 쓰지 않은 확정 용어는 '⚠ 용어 n'(툴팁에 어느 용어), 말투 규칙과 다른 말투는 '⚠ 말투', 그 밖의 형식 문제는 아이콘과 한 단어(툴팁에 문장). '✓ 검사 통과'는 용어·말투·형식이 모두 맞을 때만 보인다. 수용: 원문 아래 용어 칩이 ⚠인데 아래에 ✓가 뜨는 일이 없다.
자리표시자·태그 규칙은 프로젝트 설정의 ‘형식 규칙’(프리셋 체크 + 직접 정규식, 시험 입력란)으로 정하고, 표준 파일의 project.formatRules로 미리 넣을 수 있다. 형식 검사 함수도 같은 규칙을 쓴다.

**J3b. 편집기의 AI 도움: 이어 쓰기·서식 배치** [계획, 설계만 · 2026-10-13]

원칙: AI가 낸 글은 흐린 글씨(고스트)로만 보이고 **Tab으로 받아야** 편집기에 들어간다(말 없이 바꾸지 않는다). 받고 저장·확정하는 것은 사람이므로 사람이 정한 번역이다(사람 후보, 누가 정했나 = 사람). 기본은 꺼져 있다.

*A. 이어 쓰기* [구현됨: 2026-10-13, 모의 LLM으로 확인 · 실제 모델은 사용자가 고른 뒤] — 설정 › 프로젝트 › 편집기 자동완성(켜기, API 연결 모델, 하루 최대 호출, 오늘 사용). `POST /units/:id/complete`, 호출 기록 종류 'editor'. 흐린 글씨 안의 서식도 번호 칩. 편집기 버튼 줄의 [AI 자동완성]으로도 부른다(누르면 커서가 글 끝으로 가서 흐린 글씨가 보인다). 한국어 입력기가 켜져 있으면 ⌥/·⌥1…·⌥⇧1…이 조합 중 키(keyCode 229)로 와서 단축키로 안 잡히므로 물리 키(code)로도 받는다. 추론 수준은 고른 대로("모델 기본값"이면 보내지 않음, 생각이 긴 모델은 low를 고르라고 안내), 15초가 넘으면 그만두고 더 빠른 모델을 고르라고 알린다. 기다리는 동안 "자동완성 받는 중… n초 · 취소", Esc로도 취소. (FreeLLMAPI gemini-3.8-flash가 30초를 넘긴 일이 있었다. 스트리밍은 다음 단계.) — 무료 API(OpenRouter 무료 모델: 분당 20회·하루 50 또는 1,000회, FreeLLMAPI: 여러 무료 제공자를 한 주소로 묶고 한도에 걸리면 다른 제공자로 넘김)를 주로 쓴다는 전제. 둘 다 OpenAI 호환이라 기존 'OpenAI 호환 API' 연결에 주소만 넣는다.
- **줄마다 한 번 부른다**: 줄을 열었을 때 칸이 비어 있거나 ⌥/(직접 부르기)를 누르면 그 줄의 번역 초안을 한 번 받아 둔다. 입력이 멈출 때마다 부르지 않는다(무료 한도가 몇 줄 만에 바닥난다).
- 보이기: 받아 둔 초안 중 지금까지 쓴 글과 앞이 맞는 곳 다음을 **지금 문장 끝까지만** 흐린 글씨로. 계속 치면 브라우저 안에서만 따라간다. 쓴 글이 초안과 갈라지면 흐린 글씨는 사라지고, ⌥/로 다시 부를 때만 새로 받는다.
- 받기: Tab 전부(지금 문장), ⌘→ 한 낱말, Esc 버림.
- 보낼 것(줄 문맥을 작게): 원문, 지금까지 쓴 번역, 앞 대사 3줄(원문·번역), 화자→청자와 말투 규칙(말투·호칭), 원문에 나온 확정 용어, 원문의 서식 토큰 목록. AI 노드 문맥 빌더를 워크플로 없이 줄 하나로 부르는 가벼운 모드를 만든다(토큰 상한 작게).
- 서버: `POST /units/:id/complete {prefix}` → 초안. 다른 줄로 가면 요청 취소(AbortController → 모델 AbortSignal). 받은 초안은 줄마다 브라우저에 남겨 다시 열 때 재사용.
- 한도: 429면 조용히 멈추고 "한도 도달 · n분 뒤"를 작게 보인다(Retry-After를 따른다). 설정에 오늘 호출 수와 직접 정하는 하루 상한. FreeLLMAPI처럼 요청마다 모델이 바뀔 수 있는 곳은 모델을 고정하라고 안내한다(문체가 줄마다 흔들린다).
- 모델: 프로젝트 설정 '편집기 AI'에서 연결·모델·effort(기본 low). API 연결만 고를 수 있다(CLI·pi는 한 번에 수 초, 이유를 적어 둔다). System One은 생성 모델이 아니라 여기 쓰지 않는다.
- 고스트 안의 서식 토큰도 번호 칩으로(흐리게).

*B. 서식 배치* — 본문만 쓰고 서식은 따로 넣기
- [구현됨: 규칙 부분] 번역에 원문의 서식 단위가 빠져 있으면 버튼 줄에 [서식 n개 넣기](규칙으로 자리를 찾은 것)와 "서식 n개는 자리를 못 찾음"이 뜬다. 누르거나 ⌥T면 제자리에 점선 칩(고스트)이 보이고 Tab으로 넣는다(Esc나 다른 입력이면 사라짐). Orwell 공식 번역 108줄(태그를 지우고 다시 넣기): 규칙이 24줄(22%)을 모두 넣었고 24줄 모두 공식 번역과 같았다(틀린 자리 0). 2줄은 바깥 태그만, 82줄은 AI 몫.
- 규칙으로 먼저(AI 없음): ① 원문 전체(끝 문장부호 빼고)를 감싼 쌍 → 번역 전체를 감싼다. ② 원문 맨 앞·맨 뒤의 토큰 → 번역 맨 앞·맨 뒤. ③ 쌍이 감싼 원문이 확정 용어이고 그 번역어가 번역에 있으면 → 그 번역어를 감싼다.
- **AI로 남은 서식 배치: 보류**(2026-10-13, 실험 E12). 규칙이 못 찾은 Orwell 86줄·태그 90개에서 판정 모델이 공식 번역과 같은 자리를 고른 비율: System One(Jev) 39%(어절 경계에 번호를 달고 시작·끝을 따로 물은 방식이 가장 나음, 글자마다 번호 17%, 번호 없이 글자 위치 2%), Microsoft-Decision-1 31%. 생성 모델은 무료 자동 라우팅이 형식 오류로 비교 불가. 사람이 후보를 확인하는 수고가 직접 넣는 수고와 비슷해 넣지 않는다. 규칙이 못 찾은 서식은 "자리를 못 찾음"으로 알리고 사람이 ⌘1~9·원문 칩으로 넣는다. 더 나은 판정 모델이 나오면 같은 평가 세트(.loca/tag-eval)로 다시 잰다.

*C. AI 번역 / 다듬기* [구현됨: 2026-10-14 개정] — 버튼 줄에 버튼 둘, 누르면 바로 실행한다(지시 입력 없음). `POST /units/:id/assist {mode, draft}`. ⌥.(Ctrl/Alt+.)는 번역 칸에 글이 있으면 다듬기, 없으면 AI 번역.
- **AI 번역**: 원문에서 새로 번역한다(번역 칸의 글은 보지 않는다).
- **다듬기**(번역 칸에 글이 있을 때만): 그 글은 번역가의 것이라 말·낱말·문체를 그대로 두고, 이유가 있는 곳만 이 순서로 고친다 — ① 의미(빠지거나 더해지거나 틀린 뜻, 부정·숫자·누가 무엇을) ② 규칙(확정 용어, 화자→청자 말투·호칭, 원문 서식의 누락·초과·자리, 변수 뒤 조사) ③ 표현(번역투, 어색한 조사·어순, 띄어쓰기·맞춤법). 맞는 곳은 바꾸지 않는다. 고칠 곳이 없으면 후보를 만들지 않고 "다듬을 곳이 없습니다"(공백만 다른 답도 같다). 바꾼 곳마다 종류(의미·규칙·표현)와 짧은 이유를 받아 후보 메모로 남긴다(`다듬기 — 규칙 · 용어: 펜 항구 → 쿠헤스마 — …`).
- 결과는 입력 칸에 바로 들어간다(CAT 툴이 번역 결과를 넣을 때처럼 덮어쓰고, 저장은 하지 않는다). ⌘Z 한 번이나 [되돌리기]로 원래 글. 다듬기는 칸 아래에 바뀐 곳(지운 말 취소선, 더한 말 표시)과 이유 줄, [원래대로]를 칸이 그 답을 담고 있는 동안 보인다. 고칠 곳이 없으면 칸은 그대로이고 '다듬을 곳이 없습니다'.
- 실제 모델로 과잉 수정이 얼마나 나는지는 재지 않았다(깨끗한 번역은 그대로, 결함 넣은 번역은 그 결함만 고치는지). 필요해지면 평가 세트부터 만든다.
- 모델: AI › 사용 방식의 'AI 번역·다듬기 모델'. 연결 종류를 가리지 않는다(CLI도). 자동완성과 달리 기다리기로 한 호출이라 느려도 된다. 고르지 않았으면 팝오버는 고르러 가는 링크만 보인다.
- 문맥: 워크플로 AI 노드와 같다(말투 규칙·용어·앞 대사·문체).
- 기록: 답은 그 줄의 **AI 후보**(메모 "AI 번역" / "다듬기 — 이유…")로도 남는다. 칸에 넣은 그대로 저장하면 그 후보가 대표 번역으로 올라가 출처가 AI로 남는다. 기다리는 동안 "AI 번역 중…/다듬는 중…"과 취소. 줄을 옮기면 요청을 취소한다.
- 한도·기록: 자동완성과 하루 한도를 같이 쓰고(429면 사유와 기다릴 시간), AI 호출 기록의 종류는 '편집기'.

수용 기준: Tab 없이는 편집기 글이 바뀌지 않는다 · 줄 하나에 자동 호출은 한 번뿐이다 · 다른 줄로 가면 요청이 취소된다 · 한도에 걸리면 조용히 멈추고 알린다 · CLI 연결은 고를 수 없다(이유 표시) · 서식 배치는 본문을 바꾸지 않는다 · 꺼져 있으면 요청이 한 번도 가지 않는다.

**J4. 상태 설계** [구현됨] — 상태 추가(이름·색·종류) → 순서 변경. 사용 중인 상태 삭제는 옮길 상태를 고르게 한다. 상태마다 ‘검토함에 표시’와 ‘사람만 지정’(실행이 이 상태로 보내면 대신 검토함으로, 3.5)을 켤 수 있다.

**J5. 워크플로 구성** [구현됨] — 템플릿 또는 빈 워크플로 → 노드 추가 → 포트 연결 → 노드 설정(우측 패널).
저장 전 검증: 진입 노드 1개, 끊긴 필수 포트, 고르지 않았거나 지워진 연결·모델, 없는 상태, 탈출 조건 없는 순환. 오류는 해당 노드에 표시.
편집 초안은 이동·새로고침에도 유지된다. 워크플로는 하나를 고쳐 쓰고 지난 내용은 따로 남기지 않는다: 화면에는 버전 번호 대신 마지막 저장 시각을 보이고, 실행은 시작할 때의 워크플로를 통째로 복사해 두므로 실행 상세가 그때 쓴 노드를 보여 준다(내부 번호는 동시 저장 충돌을 막는 데만 쓴다).

**J6. 실행** [구현됨, 2026-10-13 개편] — 실행 창은 한 화면에 시작 전에 정할 것만: **무엇을**(이 장면 / 고른 대사 / 장면 고르기 / 태그 / 전체 N줄 — 전체는 미리 고르지 않고, "N줄을 실행합니다" 한 문장, 이미 진행된 줄도 다시 돌리기), **준비 상태**(이 줄들 기준: 청자를 모르는 대사, 확인 안 한 말투 규칙·용어, 5줄 이상 말하는데 말투 규칙이 아예 없는 화자→청자 쌍, 고치러 가는 링크 — 고치지 않고도 시작 가능. 확인 안 한 규칙·용어의 링크는 이 실행에 걸리는 항목만 보이도록 `ids`(최대 100개, 넘으면 `more`=true이고 링크는 전체 목록으로 가며 "(전체 목록에서 보기)"라고 적는다)를 싣고, 용어집·자료 표는 이를 "이번 실행 범위 n개" 칩으로 보이며 다른 필터와 함께 쓴다. 자료 › 관계 표는 그 규칙을 가진 쌍만 남긴다. 청자 미상 링크는 한 장면 실행이면 그 장면으로 좁히고, 그 밖의 범위는 프로젝트 전체 목록으로 간다고 링크에 적는다), **얼마나**(AI 요청 수 · 연결의 최근 실행 호출 중앙값과 동시 실행 수로 잰 시간 · 제공자가 알려 준 평균 비용 또는 구독 사용, 이력이 없으면 "첫 실행 뒤에 압니다"), **모델**(AI 단계마다 작품 분석과 같은 모델 고르기, 기본은 그 노드에 저장된 모델; 바꾸면 '이번 실행만 · 원래대로'가 붙고 그 단계는 고른 모델 하나로만 돈다 — 함께 나누던 모델은 이번엔 빠진다. 워크플로 정의는 바뀌지 않고 실행 기록에 실제로 쓴 모델이 남는다. 모델을 다 고르기 전에는 시작할 수 없고, 요청 수·시간·비용은 고른 모델로 다시 잰다. `start_run`·`plan_run`·`loca plan --model`도 같은 선택을 받는다: 노드 이름이나 id, 또는 `*`(모든 AI 단계) → 연결 이름이나 id와 모델). 위와 겹치는 경고 목록(CLI 구독, 청자 미상, 규칙 없는 쌍, 고정 토큰 미측정)은 두지 않는다. 실행 창은 시작 전 확인이라 모달에 들어가는 만큼만 둔다: "자세히"는 없다. 묶음 구성은 실행 상세의 "번역 계획", 단계별 요청은 실행 상세의 단계 보기에서 본다. 호출·입력 토큰 상한은 고르지 않고 예상의 1.3배가 자동으로 걸린다(닿으면 일시정지, 실행 상세에 표시). 시작 버튼은 "N줄 실행 시작". (묶음 목록과 토큰 숫자를 맨 앞에 늘어놓던 두 단계 창은 판단에 도움이 안 됐다.)
  - **실행 중 안전장치** [구현됨]: 재시도로 풀리지 않는 실패(인증·연결 설정)는 첫 번에, 호출이 연달아 실패하면(워크플로 설정, 기본 3번. 소진된 구독 한도도 여기서 걸린다), 시작할 때 정한 호출 수·입력 토큰 상한에 닿으면 실행이 **일시정지**하고 이유를 실행 상세에 보인다. 이미 보낸 호출은 끝까지 기록한다. 이어서 실행하면 이유가 지워진다. 한 실행의 실행기 오류는 그 실행만 멈추고, 다른 실행과 서버는 계속 돈다.
  - **번역 준비(Preflight)** [구현됨]: 시작 전에 같은 대화상자에서 실행 계획을 보여 준다. **모델을 부르지 않고 코드로 계산**하며, 작품 이해는 작품 분석의 책임이고 여기서는 실행만 설계한다.
    - 대상: 범위 안 줄 수, 그중 미번역·번역된 줄
    - 자료 상태: 쓸 작품 분석 버전, 확정 말투 규칙 수, 청자 미상 줄 수, 남은 후보 자료 → 위험으로 표시
    - 묶음 계획: 실행기와 **같은 묶음 함수**로 첫 노드의 묶음 수, 묶음당 줄·토큰 분포를 계산. "묶음 구성 보기"로 묶음마다 든 장면(줄 수)과 장면이 앞 장면과 같이 묶인 이유(그래프로 이어짐·화자 겹침·덜 찬 묶음 채움)를 보인다(앞 300묶음)
    - 예상 호출·토큰: 첫 노드는 정확한 수. 조건으로 도는 노드(검토 → 수정)는 최대치와, 지난 실행 비율 기준 예상치를 범위로. 연결별 요청당 고정 토큰은 실측 기록에서 가져오고, 없으면 "실측 없음"으로 표시. 구독 한도를 쓰는 연결이면 그 사실도 표시
    - "시작"이 승인이다. 계획은 실행 기록에 저장한다: 워크플로와 노드마다 고른 모델의 스냅샷(연결 종류·모델·추론 수준·호출 조건·막히면 경로), 작품 분석 버전, 묶음 설정, 예상치. 나중에 줄을 다시 번역할 때 당시 자료·설정과 비교할 수 있다.
  - 검증과 선택 재번역은 별도 단계가 아니라 워크플로 노드(검토·검사)와 "고친 곳만 다시" 실행으로 둔다. 검증 방식도 사용자가 워크플로로 정한다.
시작 시 워크플로 정의와 고른 모델(연결 설정 포함)을 스냅샷으로 고정해, 나중에 연결 설정을 바꿔도 실행 상세는 그때 쓴 것을 보인다. 진행은 실행 상세의 노드별 카운트로 보이고 일시정지/재개/취소 가능.
수용: 검수 통과분은 확정, 실패분은 수정 노드로 돌아가 N회 후 ‘사람 확인 필요’(검토함)로 간다. 서버 재시작 후 이어서 진행.

**J7. 사람 확인** [구현 중] — ‘검토함에 표시’ 상태의 대사는 어떻게 그 상태가 됐든 번역 › 대사의 '검토 대기'에 모인다(메뉴 배지에 수). 따로 된 검토 화면은 없다: 같은 대사 목록이 지적 사항(최근 실행)을 줄마다 보이고, 같은 편집기·검사·후보 패널을 쓴다.
다음 상태로 옮기면(⌘↵, 기본은 최종 상태) 그 줄은 필터에서 빠지고 다음 줄이 골라진다.
편집기를 고친 경우에만 번역을 함께 저장한다. 워크플로에는 사람 확인 노드가 없다: 상태 변경 노드로 검토 상태로 보내고 흐름을 끝낸다.

**J8. 채팅 에이전트** [구현됨] — 어느 화면에서든 채팅 패널 → 질문·요청 → 에이전트가 조회 도구로 읽고 → 변경은 수락/거절 카드 → 수락 시 반영.
패널을 열고 닫거나 세션을 바꿔도 본문 화면·방문 기록은 그대로다. 각 화면은 지금 보는 것(페이지, 선택한 장면·대사·노드)을 보고하고(`useReportView`),
메시지에 첨부되어 입력창 위 칩으로 보이며 뺄 수 있다. 입력창 아래의 `ModelPicker`로 채팅할 연결·모델·추론 수준을 고른다(대화마다 저장, 새 대화는 마지막에 고른 것으로 시작). 지시문은 작업실 에이전트 지시문 하나다. 응답이 도구 결과만 남기고 멈추거나 출력 한도에 걸리면 그 사실과 "계속" 버튼을 보인다.
답은 요청이 아니라 대화에 속한다: 새로고침하거나 창을 닫아도 서버에서 끝까지 받아 저장하고, 다시 열면 지금 단계(답을 쓰는 중 / 도구를 쓰는 중 / 도구 결과를 받고 n번째 요청)와 경과 시간, [중단]을 보인다. 답 없이 끝났으면(서버 재시작 등) 그 이유와 [다시 보내기]를 보인다. 패널을 닫아 둔 사이 대화가 바뀌면(답이 옴) 채팅 버튼에 점이 찍히고, 패널을 열면 사라진다.
**AI 버튼**(✦)은 모델을 직접 부르지 않고 이 에이전트에 정해진 요청을 보내며, 결과는 같은 카드로 온다:
워크플로 "AI로 만들기", 노드 "AI로 작성/다듬기"(열린 편집기 초안에만 적용, 저장은 사용자), 대사 "AI 제안/다듬기"(후보로만 추가),
용어집 "빈 번역 AI로 채우기"(후보 유지), 묶음 "AI 요약"(수락하면 장면 설명 = 장면 문맥).

**J9. 작품 분석** [1차] — 위에서 아래로: 작품을 먼저 이해하고, 그 위에 청자와 말투 규칙을 얹는다. 사람이 초안을 다 확인하는 것은 현실적이지 않으므로 **자동 확정이 기본**이고, 틀린 것을 발견했을 때 고치고 영향받은 줄만 적게 다시 돌리는 길을 둔다.
1. 문맥 › 자료 › "작품 분석" → `ModelPicker`로 연결·모델·추론 수준 선택(긴 문맥 모델 권장, 출력 한도는 연결 설정). 대본 전체(장면·화자·선택지·조건 분기 표시)를 **한 번에** 읽힌다. 모델 문맥 창을 넘으면 장면 경계에서 나눠 앞 결과에 덧붙인다(처음엔 약 30만 토큰씩, 모델이 너무 길다고 거절하면 그 부분을 반으로 나눠 다시 읽는다). 프로젝트 단위 백그라운드 작업이며 진행·취소·실패 장면이 보이고(SSE), 번역·상태는 바꾸지 않는다.
2. 결과는 근거 대사 키가 달린 **초안**: 개요, 인물(별칭·프로필·말투 특징), 관계(변화 지점), 사건(요약·원인·결과·관련 인물), **말투 규칙**(화자→청자, 여섯 말투 등급 중 하나, 호칭, 바뀌는 지점의 대사 키), **장면별 청자**(장면마다 화자가 주로 누구에게 말하는지와 확신도. 줄마다 받으면 출력이 너무 커서 장면 단위로 받는다). AI › 사용 방식에서 그 종류가 자동 확정(기본)이면 확정(✦)으로, 후보로만이면 후보로 저장된다. 어느 쪽이든 출처는 작품 분석, 정한 쪽은 AI이고 모델·작업 id가 남는다.
   - 자동 확정이면 말투 규칙은 **모두 바로 쓰인다**(한글 번역이 없는 게임의 한글 패치가 주 용도라 대조할 정답이 없고, 긴 확인 목록은 결국 아무도 보지 않는다). 대신 **확인 권장** 표시와 이유가 붙는다: 대사의 80%를 덮는 **주요 화자→청자 쌍**(틀리면 수백 줄이 틀린다), 나눠 읽은 부분끼리 **엇갈린** 규칙, **근거 대사의 화자가 규칙의 화자가 아닌** 규칙. 사람이 정한 규칙과 다른 AI 규칙만 후보로 옆에 둔다. 틀린 규칙은 번역을 읽다 발견해 고치고 그 쌍의 대사만 다시 돌린다.
   - 장면별 청자는 화자의 기본 상대와 **예외 줄**(그 화자가 그 장면에서 다른 사람에게 한 줄: 줄 id·청자·확신도)로 받는다. 예외 줄은 그 줄의 AI 추정으로, 나머지는 기본 상대로 들어간다(출력은 예외만큼만 는다). 장면별 청자는 아무도 정하지 않은 대화 줄에만 출처 **장면 추정**으로 들어간다. 가져온 청자, 사람이 정한 청자, 줄마다 추정한 청자(청자 추정 노드, 출처 AI 추정)는 바꾸지 않는다. 확신 0.9 미만은 그 화자가 장면에서 여러 사람에게 말한다는 뜻이라 줄의 청자로 쓰지 않고(미상), 대사 패널에 "장면 추정: 이 장면에서 주로 X에게 (섞인 장면)"로만 보인다. 엑스트라(SWAT 등 인물 목록 밖)는 화자 이름 그대로 쓴다.
   - 청자 선택은 이 장면의 다른 화자(가까운 순, 엑스트라 포함, 사람이 입력한 이름 포함) → 여럿·불특정 다수·혼잣말 → 다른 인물 → 직접 입력 순이다. 1회성 엑스트라는 인물로 등록하지 않는다.
   - 말투 규칙의 청자로 **그 밖의 사람**(others)을 둘 수 있다: 그 화자가 자기 규칙이 없는 상대(엑스트라 등)에게 쓰는 말투. 쌍 규칙이 있으면 쌍 규칙이 이기고, 여럿·불특정 다수·혼잣말에는 쓰지 않는다. 대사 패널은 "(그 밖의 사람 규칙)"이라고 밝힌다.
   - 대본이 길어 나눠 읽으면 부분 결과를 합친다: 이름이나 별칭이 겹치면 같은 인물이고, 관계·규칙의 이름도 그 인물로 맞춘다. 같은 제목의 사건은 합친다.
3. 확인: 자료의 탭(문서·인물·관계·사건·말투 규칙)마다 표 + 우측 상세, 자동 표시(`marks`: #후보 · #AI가 정함 · #근거 없음)·출처·태그 필터. 출처 AI는 "AI"로 표시된다. 상세에서 문장을 고치고, 근거 대사를 열어 보고(스크립트로 이동), 후보는 확정/버리기. 여러 개 골라 한 번에 확정. 근거 키가 대본에 없으면 코드가 표시한다.
4. 다시 분석하면 **이전 분석이 만든**, 사람이 손대지 않은 AI 항목만 바뀐다. 사람이 고치거나 직접 확정한 항목(검토됨), 사람이 만든 항목, 워크플로가 만든 항목은 덮지 않고, 같은 내용은 다시 제안하지 않는다. **버린 항목은 지우지 않고 '버림'으로 남겨** 다시 제안하지 않는다(목록에는 보이지 않는다).
5. 확정된 지식의 쓰임: 말투 규칙 → 번역 문맥(J10). 인물·개요 → 청자 추정의 참고. 프로필·사건은 기본으로 번역 문맥에 넣지 않는다(2.4).
- 1차는 항목 단위 근거만 둔다. 문장 단위 주장(3.3)과 분기 시점 계산(3.2)은 다음 단계.
수용: Orwell 1(약 2,700줄)을 한 번에 분석해 초안이 들어오고, 근거를 눌러 해당 대사로 간다. 작업 중 새로고침·이동해도 진행이 보이고, 실패하면 다시 시도할 수 있다.

**J10. 청자와 말투 규칙** [1차]
1. 청자 채우기: 표준 파일의 `listener`가 있으면 그대로(출처: 가져오기). 없으면 **작품 분석이 1차로** 장면별 청자를 채운다(J9). 그래도 모르거나 확신이 낮은 줄은 워크플로 템플릿 "청자 추정"(AI 노드, 장면 묶음, 출력 형태 "청자", 문맥에 확정 인물·개요)으로 채운다. 이 템플릿은 조건 노드로 **청자를 이미 아는 줄(가져오기·사람·확신도 0.9 이상 AI)과 대화가 아닌 줄을 건너뛰어** 모델에 보내지 않는다. AI 청자는 확신도와 함께 저장되고 0.9 미만은 "미상". 번역·상태는 바꾸지 않는다.
   - 청자는 인물(플레이어 포함, `player` 표시 인물) 또는 특수값 셋 중 하나다: **여럿**(`group`, 그 자리의 여러 사람: 회의·단체 통화), **불특정 다수**(`public`, 방송·공지·연설·게시글), **혼잣말**(`self`, 독백·생각·일기). 말투 규칙의 청자로도 쓴다("Udemwe → 여럿: 해요체"). 판단 못 한 줄은 비어 있다(AI가 보고도 모르면 "모름"). 번역 문맥의 여럿에는 그 장면의 다른 화자를 함께 적는다. 인물 이름은 원문 언어 그대로(이름 없는 플레이어는 게임이 쓰는 역할명).
2. 청자 확인: 스크립트 표 "청자" 열(AI는 흐리게 + 확신도, 미상 강조), 대사 패널에서 바꾸면 출처가 사람이 된다. 화자·청자로 거른다(`speaker`, `listener` URL 파라미터).
3. 자료 › 말투 규칙 탭의 상세는 그 쌍의 대사 목록(청자 기준)과, 번역이 있으면 현재 번역의 말투 분포를 보여 줘 초안을 판단하게 한다. 사람이 직접 추가·수정할 수 있다.
4. 같은 쌍에 규칙이 여럿이면 시작 지점(대사 키)으로 구간을 나눈다. 쌍 패널은 말투를 맨 위에 구간마다 한 줄("처음부터 · 하게체 · 호칭", "“…”부터 · 해체")로 보이고 펼치면 말투·호칭·메모만 고친다. "말투가 바뀌는 지점 추가"는 이 쌍의 대사(청자 기준) 목록에서 바뀌기 시작하는 대사를 눌러 고르면 앞 구간의 말투를 이어받은 새 구간이 생긴다(키를 직접 치지 않는다). 관계는 그 아래 접어 둔다. 근거 대사와 적용 대사 목록은 접힌 채 시작한다. 1차는 대본 순서로 고르고 문맥에 "순서 기준"이라 적는다. 분기를 고려한 선택은 3.2의 지배 관계로 바꾼다.
5. 번역: AI 노드 문맥에 청자(가져오기·사람·확신도 0.9 이상 AI)와 그 쌍의 **확정** 말투 규칙이 줄마다 들어간다(문맥 항목 "청자·말투", 상한 우선순위는 용어 다음). 후보 규칙은 넣지 않는다.
6. 검사: 대사 패널 검사와 함수 "말투 규칙 검사"가 번역 끝 어미로 말투를 추정해 규칙과 다르면 표시한다("추정").
7. 고치고 다시 돌리기: 말투 규칙 상세에 "이 규칙이 적용되는 대사 N개"(그 쌍·그 구간)와 현재 번역의 말투 분포, "번역된 N줄 말투 맞추기"(기존 실행 창, 그 쌍·구간의 번역된 줄만. 번역이 없으면 버튼 대신 "번역할 때 이 규칙이 들어갑니다")을 보인다. 기본 워크플로는 템플릿 "말투만 고치기": 현재 번역의 뜻·표현은 두고 어미·호칭만 확정 규칙에 맞춘다. 청자를 고친 줄도 같은 길로 다시 돌린다. 용어집의 "이 용어가 나오는 대사 · 다시 실행"과 같은 방식이다.
수용: 9,000줄 프로젝트에서 청자 열·필터가 끊기지 않는다. 규칙을 확정하면 AI 문맥 탭 미리보기에 바로 보인다. Back/Forward로 필터·선택이 돌아온다.

**J11. 번역하며 자료 갱신** [1차, 기본 템플릿에서 뺌] — 작품 분석과 책임이 겹쳐(같은 정보를 장면마다 다시 뽑음) 새 프로젝트에 기본으로 만들지 않는다. 자료를 다시 만들 때는 작품 분석을 다시 돌린다. "새 워크플로"에서 템플릿으로는 고를 수 있다. 템플릿 "자료 갱신": 장면을 순서대로 읽으며(AI 노드 출력 "자료 변경", 문맥에 인물 명단·확정 관계·대사별 말투 규칙) 새 인물, 관계 변화(드러나는 대사), 사건(근거 대사), 말투가 바뀌는 지점을 함수 "자료 반영"으로 넣는다. 새 항목은 AI 항목(AI › 사용 방식을 따름, 기본 자동 확정). 정식 항목은 바꾸지 않고 다른 의견은 AI 후보로 옆에 둔다(관계 변화, 사람이 정한 구간의 다른 말투). 같은 내용은 다시 넣지 않아 여러 번 돌려도 된다. 번역·상태는 그대로다. 순서를 건너 번역하면 뒤 장면의 사실이 앞 번역 문맥에 들어갈 수 있다(분기 시점은 3.2).

다음 단계 [계획]: 용어 전역 발견(3.1), 문장 단위 주장(3.3), 분기 시점(3.2).

**J12. AI가 정한 것 확인** [구현 중] — 홈의 '#AI가 정함' 할 일 또는 대사 목록·자료 표·용어집의 #AI가 정함 필터(`marks=ai`) → ✦가 붙은 줄·항목만 남는다 → 훑어보고 고르기 → '확인함'(상태는 그대로, 정한 쪽만 사람; ✦ 사라짐) 또는 고치기(고치면 자동으로 사람). AI › 사용 방식에서 종류별로 후보로만 받게 바꾸면 다음 분석·실행부터 그 종류는 후보로 들어온다. '확인 안 함'(실행 창의 준비 상태)은 후보이거나 AI가 정한 것(`marks=candidate,ai`)이고, '확인 권장'은 앱이 단 태그(`tags`)라 서로 다른 표시다.
- 수용 기준: 실행이 상태를 바꾼 줄은 ✦와 함께 보이고, 사람이 상태를 바꾸거나 번역을 고치면 ✦가 사라진다. '사람만 지정' 상태로 보내는 실행은 그 줄을 검토함 상태에 두고 이유를 남긴다. AI 확정 자료는 ✦, 사람이 올리거나 고친 것은 ✦ 없음. '사람이 확정한 것만'을 켠 노드의 AI 문맥 미리보기에 ✦ 항목이 없다. 필터와 선택은 Back/Forward에서도 유지된다.

## 6. 워크플로 노드 [구현됨]

노드는 다섯 종류다. 행동은 **AI 노드**와 **함수 노드**로 일반화하고, 용도(번역·검수·수정·용어 추출)는 설정 프리셋이다.

| 노드 | 설정 | 출구 |
|---|---|---|
| 진입 | 대상 상태 | out |
| AI | 모델(`ModelPicker`), 온도(고급, 비우면 모델 기본값), 지시문, 출력 형태(번역 후보 / 판정 / 용어 후보 / 자유 JSON 필드), 함께 보낼 것, 문맥, 묶음 | 판정: pass·fail·error / 그 외: out·error |
| 함수 | 함수 레지스트리에서 하나 + 파라미터 | 함수가 선언 (+ error) |
| 조건 | JSON Logic | true·false |
| 종료 | — | — |

함수 레지스트리(`packages/shared/src/functions.ts` 메타 + `apps/server/src/engine/functions` 구현): 형식 검사, 용어 준수 검사,
상태 변경(대표 번역 적용 포함), 용어 후보 추가, HTTP 호출(노드에 전체 주소·요청 템플릿, 키가 필요하면 API 키 선택·응답 경로),
스크립트(사용자 JavaScript, QuickJS WASM 샌드박스, 네트워크·파일 없음, 시간·메모리 제한, 출구 직접 선언). 새 함수 = 메타 1개 + 구현 1개.

노드 간 데이터: 대사마다 `outputs.<노드ID>`에 출력이 쌓이고 현재 후보(`candidate`)와 최근 지적(`issues`)이 이어진다. 조건식·HTTP 템플릿·스크립트가 이를 읽는다.
AI가 추출한 용어는 후보로만 들어가고, 사람이 확정해야 문맥에 쓰인다.
대사 1개 = 실행 항목 1개. AI 호출은 묶음 단위(기본: 장면, 6.1에서 연속 장면 묶음으로 바꿀 예정). 대사별 노드 방문 상한을 넘으면 실패로 끝난다.
System One 연결은 판정 출력에만 쓴다.

### 6.1 대량 실행 처리량 [계획]

목표는 5만 줄 규모를 **모든 연결 방식에서 동등하게** 감당하는 것이다. 연결 방식은 API, pi, 에이전트 CLI(Claude Code, Codex, Antigravity, Grok, opencode)가 있고, 어느 것을 쓸지는 사용자가 고른다. 특정 연결을 기본으로 강요하거나 해결의 중심에 두지 않는다. 최적화는 두 층으로 나눈다. **엔진 공통**은 묶음을 어떻게 만들고 무엇을 보내는지이고, **연결별 실행 전략**은 그 요청을 각 방식으로 어떻게 보내는지다.

**실측 (Orwell 1편 Day 1, 319줄, 2026-10-10)**
- 요청 하나에 우리가 보낸 내용은 1~1.2천 토큰인데, CLI가 보고한 입력은 1.3만~2.9만 토큰이었다.
- 장면 단위로 묶어서 요청당 평균 6줄이었다.
- Grok에 빈 요청을 보내도 일반 입력 약 8.7천 + 캐시 입력 약 1.06만이 붙었다. 우리는 일반 입력만 기록하고 있었다.
- Grok의 시스템 프롬프트를 교체해도 합계는 그대로였고(1.8만), 캐시만 깨졌다.

#### 엔진 공통 (모든 연결)

| 원인 | 지금 | 바꿀 것 |
|---|---|---|
| 요청이 작다 | 장면 경계에서 묶음을 끊음. 짧은 장면은 2~6줄 요청 | **연속 장면을 한 묶음으로.** 줄 수 + 토큰 한도. 장면 경계는 프롬프트 안 구분선으로, 장면 정보와 앞 대사는 장면별로 유지 |
| 누락 처리 | 응답에 없는 줄은 오류 출구로 끝남 | 응답에 이 묶음의 ID와 개수를 명시. 빠지거나 빈 줄만 같은 문맥으로 **자동 재요청**. 그래도 없으면 그 줄만 오류 |
| 공통 문맥 반복 | 장면마다 같은 인물·관계를 다시 넣음 | 묶음 안 줄들이 언급하는 것의 합집합을 한 번만. 고정 부분(지시문 → 명단·규칙)은 앞, 이번 대사는 뒤. JSON 들여쓰기 제거 |
| 중복 분석 | 자료 갱신이 작품 분석과 같은 정보를 장면마다 다시 뽑음. 용어 추출이 별도 호출 | 작품 분석이 1차, 장면별 추출은 고친 곳·불확실한 곳만. 용어는 번역 응답에 함께 |
| 측정 | 입력 토큰 하나만 기록 | 요청마다 일반 입력·캐시 입력·출력·비용(보고될 때)·소요 시간·요청 줄 수·응답 줄 수 |

원칙:
- **줄별 맥락은 줄에, 공통은 묶음에 한 번.** 청자·말투 규칙·앞 대사는 장면을 합쳐도 줄마다 그대로 붙는다. 장면을 합쳐도 서사 경계는 남긴다.
- **번역 묶음끼리는 독립.** 앞 묶음의 요청·응답이 다음 묶음에 쌓이거나 섞이지 않게 한다.
- **원문 재사용은 정상이다.** 검토가 원문을 다시 읽는 것은 품질상 필요하다. 없앨 것은 같은 정보를 다시 분석하는 일이다.
- **청자**는 작품 분석이 1차로 매긴다(확신도 포함). 확신이 낮은 줄, 갈래가 합쳐지는 줄, 규칙과 충돌하는 줄만 장면별 청자 추정을 다시 돌린다.

#### 번역 계획과 흐름 [번역 계획·칸 배분·여러 AI·병렬 갈래 구현됨]

실행이 시작될 때 **번역 계획**을 한 번 만들어 실행 기록에 저장한다. 모든 AI 단계는 이 계획의 묶음 단위로 움직인다.
- **묶는 기준(연관도, 코드로 계산)**: 장면은 쪼개지 않는다. 대사 그래프로 이어진 장면(바로 앞뒤, 갈래가 합쳐지는 곳)과 화자가 겹치는 장면을 같은 묶음에 넣고, 줄 수·토큰 한도까지 채운다. 문서·UI 문자열은 대화와 따로 묶는다.
- 번역·검수·수정이 같은 묶음 단위로 이동한다. 묶음이 단계마다 흩어지지 않고, 단계는 묶음 구성원이 도착하면 보낸다.
- 번역 준비 화면의 예상치(묶음 수·호출 수·토큰)는 이 계획에서 센다. 다시 번역할 때도 같은 묶음을 재현할 수 있다.

**번역 순서에 기대지 않는다.** 품질을 크게 올리는 정보(확정 말투 규칙, 청자, 용어, 인물, 장면 설명)는 번역 전에 정해 두므로 어느 묶음을 먼저 번역해도 같다. 순서에 기대는 것은 둘이다.
- 앞 대사의 기존 번역(`precedingTranslations`): 묶음 안의 대사는 이미 함께 가므로 앞 대사 문맥은 묶음 첫머리에만 붙는다. 실험 E9(Orwell 407줄, GPT 6.1 sol)에서 순서대로 번역해도 앞 번역이 들어간 줄은 6줄이었고 품질 차이가 없었다. 그래서 기본값은 끄고 '순서 보장'은 만들지 않는다. 묶음은 순서와 상관없이 병렬로 돈다.
- 실행 중에 뽑은 용어: 용어를 번역 전에 미리 뽑는 쪽(감사 3단계)으로 옮기면 사라진다.

연관도는 대본 순서·종류·화자 겹침과 대사 그래프의 직접 연결(한 장면의 노드에서 다른 장면의 노드로 가는 간선)을 본다. 허브를 거친 연결은 모든 장면을 이어 버리므로 넣지 않는다. [구현됨]

흐름은 이미 기차처럼 이어진다(첫 번역 묶음이 끝나면 그 줄은 검수로 가고, 다음 번역 묶음이 출발한다). 막히는 원인은 칸 배분이다.
- **칸은 AI 계정(연결)마다 둔다.** 서로 다른 AI는 서로를 기다리지 않고, 같은 계정을 쓰는 실행이 여럿이어도 그 계정 몫 이상 몰리지 않는다. 지금은 실행 하나에 칸 2개를 모든 단계가 나눠 쓴다.
- **단계마다 차례로 칸을 준다.** 한 단계가 칸을 독차지하지 않게 한다.
- **나눠 맡기기**: AI 노드에 모델(연결·모델)을 여러 개 두면 요청마다 칸이 빈 계정으로 보낸다. 번역 노드에서 모델이 서로 다르면 장면마다 문체가 달라질 수 있다고 경고한다. 같은 모델의 다른 계정은 처리량만 늘린다.
- **병렬 갈래**: 출구에서 선을 여러 개 그으면 각 대사가 모든 갈래로 간다(갈래마다 사본). 갈래는 다시 만나면 안 되고, 상태 변경은 한 갈래에만 둘 수 있다. 대사는 모든 갈래가 끝나야 완료로 센다. 모델별로 지시문·묶음을 달리 나누는 '컨테이너'는 필요해지면 추가한다.

진행: 번역 계획, 칸 배분, 여러 AI, 병렬 갈래는 구현됨. 다음은 번역 준비 화면. 전체 순서는 `docs/AUDIT-2026-10.md` 6장.

#### 연결별 실행 전략

엔진이 만든 독립 요청을 각 방식으로 가장 싸고 빠르게 보내는 방법이다. 연결마다 실측으로 고르고, 고른 근거(요청당 고정 토큰, 기동 시간)를 연결 정보에 남긴다.

| 연결 | 비교할 것 |
|---|---|
| API (OpenAI 호환 등) | 공급자 프롬프트 캐시(고정 앞부분), 동시 요청 수 |
| pi | 위와 같음(모델 API 직접 호출, 프로세스 없음) |
| 에이전트 CLI | 아래 전략을 CLI마다 비교 |

CLI는 아래 네 요인을 **따로** 잰다. 요인들은 서로 겹친다. 예를 들어 세션 재사용은 프로세스 재사용 위에서도, 단발 실행에서도 가능하다. 그래서 서로 대체하는 대안으로 취급하지 않는다. 한 요인만 바꾸고 나머지는 고정해서 효과를 분리한 뒤, CLI마다 요인 조합을 고른다.

| 요인 | 바꾸는 것 | 기대 효과 | 위험 |
|---|---|---|---|
| 프로세스 재사용 | 요청마다 기동 ↔ 상주(ACP, serve, app-server, stream-json 입력) | 기동 시간 | 상주 프로세스 관리(죽음·타임아웃·동시성) |
| 세션 재사용 | 요청마다 새 대화 ↔ 같은 대화에 이어서 | 앞부분 재전송·캐시 적중 | 기록 누적으로 입력 증가, 앞 묶음 문맥 오염 |
| 프롬프트 캐싱 | 고정 앞부분의 배치·순서 | 캐시 입력 비율 | CLI가 앞부분을 바꾸면 무효 |
| 프롬프트·도구 축소 | CLI 자체 시스템 프롬프트 교체, 도구·스킬·MCP 끄기 | 요청당 고정 토큰 | 구조화 출력 기능까지 꺼질 수 있음(Grok은 효과 없음) |

측정 요청은 두 가지다. 하나는 고정 비용만 보는 짧은 요청이고, 다른 하나는 **대표 번역 묶음**이다. 대표 묶음은 연속 장면, 줄별 청자·말투 규칙, 갈래 앞 대사를 포함한 실제 크기 묶음이며, 실제 배포 기본값과 같은 구성으로 만든다. 지표는 다음과 같다.
- **비용**: 요청당 일반·캐시 입력, 출력, 첫 응답까지 시간, 총 시간, 실패율
- **구조화 출력의 완전성**: ID별 개수 일치, 누락·중복·빈 값, 스키마 위반
- **번역 품질**: 같은 묶음을 단발 기준선과 비교. 정답 번역이 있는 줄에서 말투 등급 일치, 기준선 대비 판정
- **문맥 오염**: 세션을 재사용할 때 앞 묶음의 인물·용어·문장이 다음 묶음 번역에 새어 들어오는지. 앞 묶음에만 있는 고유명·표현을 심어 두고 확인한다

실제 모델 호출은 측정 목적, 예상 호출 수, 예상 토큰을 먼저 제시하고 사용자가 승인한 경우에만 한다. 그 외의 검증은 목 LLM으로 한다.

검증 도구 [구현됨]:
- 목 LLM 프로필(`MOCK_PROFILE=cli-like|faulty`, `MOCK_*` 환경변수, 요청별 `x-mock-*` 헤더): 요청당 고정 토큰·캐시 토큰·지연과 줄 누락·중복·빈 값·형식 오류·429·잘림을 시드로 재현한다. `GET /__stats`로 요청 수·토큰·요청당 줄 수 분포를 본다.
- 현실형 샘플(`pnpm samples -- --profile realistic --size 9000|50000`): 1~3줄 장면 40%, 허브, 인물·관계·용어·문서·말투 규칙·청자·번역 일부. 규모·비용 확인은 합성 샘플이 아니라 이것으로 한다.
- 목 LLM 응답이 서버 스키마와 어긋나면 테스트가 실패한다(`apps/server/src/engine/mock-llm.test.ts`).

수용 기준:
- 묶음 안 줄이 빠지면 그 줄만 다시 요청되고, 최종적으로 줄마다 결과 하나(또는 그 줄만 오류)가 남는다.
- 장면을 합친 묶음에서도 각 줄의 청자·말투 규칙·앞 대사가 그 줄에 붙는다(테스트로 확인).
- 실행 상세의 AI 호출마다 일반·캐시 입력, 출력, 요청·응답 줄 수가 보인다.
- 비용 수용 기준은 `pnpm budget`이 숫자로 검사한다. 현실형 9천 줄 샘플과 목 LLM(`cli-like`: 요청당 고정 2만 토큰)을 쓰고, 기준선은 `scripts/budget-baseline.json`에 둔다. 기준선은 시나리오마다 기대 종료 상태(`status`)와 남은 줄 수(`unfinishedLines`)도 정한다. 종료 상태가 다르거나(완료 대신 일시정지 등) 처리하지 못한 줄이 늘면 비용을 비교하지 않고 실패한다. 같은 일을 한 실행끼리는 호출 수나 줄당 입력 토큰이 10% 넘게 늘거나 실패 줄 비율이 2%p 넘게 늘면 실패한다. 오류가 섞인 `translate-faulty`는 연속 실패 멈춤을 10회로 올려 돈다: 어느 호출이 실패할지가 묶음 대기 시간에 따라 달라져 기본값 3회로는 네 번에 한 번꼴로 멈췄고, 이 시나리오는 오류의 비용을 재는 것이라 멈춤 장치는 따로 테스트한다. 개선하면 기준선을 갱신한다(`pnpm budget --update`, 리뷰에서 확인).
- 2단계(엔진 공통)의 목표치는 1단계 기준선 대비 다음과 같다.
  - 번역 워크플로의 모델 호출 수 1/5 이하
  - 5줄 이하 호출 비율 10% 이하
  - 결함 주입(`faulty`)에서 최종 실패 줄 1% 이하
- CLI마다 고른 요인 조합과 그 실측(고정 토큰, 시간, 완전성, 품질, 오염 여부)이 문서에 남는다.
- 기존 실행 기록·번역 결과는 그대로 읽히고, 중단·재시작한 실행은 새 묶음 방식으로 이어서 끝난다.

## 7. 에이전트 접점: 채팅·CLI·스킬 [구현됨]

- **채팅 연결 세 가지**: OpenAI 호환 API(AI SDK 도구 호출, 변경 도구는 승인 카드), pi(서버 안의 pi SDK 세션. 로그인은 pi가 관리, 모델은 "공급자/모델"), **에이전트 CLI**(Claude Code·Codex·Grok·agy·opencode).
  - CLI는 자기 세션을 디스크에 두고 매 턴 이어 붙인다(Claude Code·Grok `--session-id`→`--resume`, Codex `exec resume`, agy `--conversation`, opencode `--session`). 세션 id는 대화(chat_sessions.agent_session)에 저장하고, 연결 종류나 모델이 바뀌면 새 세션에 이전 대화 기록을 넘긴다.
  - CLI 자신의 셸·파일·웹 도구는 끈다. Grok은 셸을 한 명령으로 제한할 수 없고(deny가 모든 allow를 이김), agy는 헤드리스에서 권한을 자동 거부하기 때문이다. 대신 작업실 도구(pi·CLI와 같은 카탈로그)를 답 안의 `loca-tools` 블록으로 요청받아 서버가 실행하고(읽기는 바로, 변경은 이 대화의 제안), 결과를 같은 세션에 이어 보낸다(한 메시지에 최대 8번).
  - 스트리밍은 메시지 단위다(CLI가 한 차례 답을 끝내면 그 글과 도구 호출이 한꺼번에 보인다). 다중 턴·도구·스트리밍은 서로 다른 기능이고, CLI는 앞의 둘을 지원한다.
  pi와 CLI에서 온 변경은 바로 실행하지 않고 **제안**(proposals)으로 저장해 채팅 패널에서 수락/거절한다. AI 노드에서도 pi 연결을 쓸 수 있다.
  - 제안 결정은 한 번만 일어난다: 수락은 실행 전에 제안을 '적용 중'(running)으로 잡고, 같은 제안에 겹친 수락·거절(다른 창, 다시 보낸 요청)은 도구를 다시 실행하지 않고 그때의 상태(적용 중 또는 결정된 결과)를 돌려받는다. 적용 중에 서버가 꺼지면 다시 실행하지 않고 '실패: 결과를 알 수 없음, 일부만 반영됐을 수 있음'으로 닫는다.
- **pi 연결 스위치**: pi 사용자의 하네스를 존중한다. 패키지·확장은 기본으로 불러오고 하나씩 끈다. pi 기본 도구(파일·쉘)는 하나씩 켜는 선택이며, 켜면 수락 카드 없이 파일·명령에 닿는다는 경고를 보인다. 스킬·프롬프트 템플릿·AGENTS.md도 선택. 시스템 프롬프트는 항상 작업실 것.
- **에이전트 도구 설정** (설정 › 에이전트): 읽기·변경 제안·워크플로 실행 제안 세 묶음 스위치, 도구별 선택은 접어 둔다. 채팅 패널의 AI(모든 연결 종류)와 `loca tools`·`loca call`에 적용되고, 끈 도구는 보이지 않는다. CLI의 읽기 명령과 워크플로에는 영향이 없다.
- **웹 도구**: 웹 검색, 웹 페이지 읽기(공개 주소만, 이 컴퓨터·내부망 차단). 페이지 글은 데이터로만 다룬다.
- **워크플로 실행 제안**: 에이전트는 실행을 제안할 수 있고 수락해야 시작된다.
- **loca CLI**: 실행 중인 앱의 로컬 API를 부른다(DB를 직접 건드리지 않아 화면이 갱신된다). `context <키>`(AI 노드가 보낼 문맥 미리보기)가 있고, `format schema|check`(표준 파일 규격·검사)와 `workspace new|list|clean`(에이전트 임시 파일을 두는 `.loca/`, 스스로 git에서 빠짐)은 앱 없이 동작한다 [구현됨]. 읽기는 바로 답하고, 쓰기(가져오기·변경 도구)는 **제안 1건**이 된다. 배치 가져오기는 대사별 rev(updatedAt)로 충돌을 검사하고 수락 시점에 다시 확인해 그사이 바뀐 줄은 건너뛴다. 명령은 `README.md`와 `loca --help`.
- CLI와 채팅 도구는 같은 서버 기능(`services/script-query.ts`)을 쓴다. `skills/`는 CLI 명령과 함께 고친다.
- **앱과 같은 규칙, 같은 서버 기능** (CLI가 주 인터페이스이고 웹은 그것을 보여 준다): 화면에 먼저 생긴 규칙은 CLI·도구에도 같은 공유 판정(`packages/shared/src/marks.ts`, `services/preflight.ts`, `term-usage.ts`, `tag-scope.ts`)으로 있다. 새 명령은 읽기 도구(`loca call`로도 부름)를 얇게 감싼 것이다.
  - `loca lines|line|export`와 `find_lines`: 줄마다 `marks`(남은 줄·AI가 정함·청자 미상·메모·같은 원문 다른 번역)를 싣고 사람용 출력은 `#이름`으로 보인다.
  - `loca terms [-q --mark --unreviewed --tag --limit --jsonl]` (`list_terms`): 원문·번역어·상태·정한 쪽·나온 줄·표시·태그. `--mark candidate ai`는 둘 중 하나(앱과 같음). `loca terms usage <원문|id>` (`term_usage`): 용어 창의 사용처와 같은 매칭.
  - `loca knowledge documents|characters|relationships|events|speech-rules [--mark --unreviewed --tag]` (`read_documents`·`list_characters`·`list_events`·`list_speech_rules`): 항목마다 상태·표시·태그. `--unreviewed` = 후보 또는 AI가 정함.
  - `loca tags` (`list_tags`): 프로젝트 태그와 기본 표시의 붙는 곳·종류·색·쓰인 대사/항목 수. 태그를 붙이는 import·저장은 붙는 곳 검사(`attachUnitTags`)를 거치고 거절 이유가 그대로 출력된다.
  - `loca plan <워크플로> [-g --key --mark --tag --ignore-status]` (`plan_run`): 실행 창의 준비 상태·요청 수 추정을 읽기만 한다(`preflight`).
  - 변경 제안 검사: `save_terms`의 이미 있는 원문·한 요청 안 중복은 제안을 올릴 때 거절 이유와 함께 빠지고, `loca call`·`loca import --dry-run`이 빠진 줄과 이유를 모두 보인다.
  - 수정 제안은 보낸 필드만 바꾼다 [구현됨: 2026-10-14]: `save_*`에 id가 있으면 입력은 전부 선택이고 기본값이 없다(넣지 않은 상태·메모·번역은 그대로). 새로 만들 때만 원래 스키마의 필수값·기본값을 쓴다. 용어·자료의 태그는 `tag_items`(붙는 곳이 맞지 않는 태그·앱 태그는 거절, 하나라도 거절되면 아무것도 안 바뀜), 대사는 `propose_changes`. 태그 만들기(`save_status` type tag)는 `scope`(대사·자료·용어집)를 받는다.
- 청자·말투: `loca lines --listener <이름|->`, `loca check speech`, `loca export`의 `listener`·`speechRule`, import 줄의 `listener`(수락하면 사람이 정한 청자). 도구 `list_speech_rules`·`list_events`·`save_speech_rule`·`save_event`, `read_line`의 청자·말투 규칙, `list_characters`의 말투 특징·플레이어·상태·출처. 에이전트가 기존 자료를 고치면 그 항목은 정식이 된다(수락 카드를 거치므로).
