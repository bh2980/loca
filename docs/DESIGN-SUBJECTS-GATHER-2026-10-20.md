# 설계: 워크플로 대상 확장(용어)과 모으기 노드

2026-10-20 · 상태: 승인(D1~D8 권고안), 구현됨(M3-1~M4-2) · 범위: 마일스톤 M3·M4

원칙: 프리셋 노드는 AI 자유 노드로 똑같이 만들 수 있어야 하고, 특정 워크플로만을 위한 숨은 로직·전용 노드는 두지 않는다. 엔진의 동작은 노드 설정과 그래프로 보여야 한다.

## 0. 지금 구조 (출발점)

- 실행 항목 하나 = 대사 하나. `run_items.unit_id`는 필수이고 `units`를 참조한다(`schema.ts` 587). `RunScope`, 실행 계획(`planRun`), 묶음(`batches.ts`: 장면·`seq`·화자), 프롬프트(`PromptLine`), 문맥(`buildContext`), 함수 입력(`FunctionInput.unit`), 조건 데이터(`ConditionData.unit`), 실행 화면(`/runs/:id/items`가 `units` 조인)이 모두 대사 전제다.
- 묶음 전체 답(`scope: 'batch'`)은 요청의 첫 항목에만 실리고(`batchLeader`, `ai-output.ts` 69), 반영 노드는 나머지를 건너뛴다(`apply.ts` 256). 여러 요청의 결과를 다시 모으는 방법은 없다.
- 용어 AI 채우기는 워크플로 밖의 `TermService`(`terms.ts` 187–320)와 `term_jobs` 테이블로 돈다. 숨은 SYSTEM 프롬프트, 100개 고정 묶음, 용례 2줄, 확정 용어 300개, `NOT_A_TERM` 표식, 사람이 그사이 채운 용어는 건너뛰는 쓰기 조건이 코드에 있다.

## 1. 워크플로 대상 (M3)

### 1.1 개념

- 워크플로마다 **대상 종류 하나**: `lines`(대사) 또는 `terms`(용어). 진입 노드가 정한다. 한 워크플로 안에서 섞지 않는다.
- 서버에 대상 어댑터(`SubjectAdapter`)를 둔다: 고르기(범위·진입 조건), 정렬과 묶음 키, 프롬프트 항목, 조건 데이터, 함수 입력, 화면 표시, 삭제 시 정리. 지금은 `lines`, `terms` 두 개만 구현한다. 인물·관계 등은 같은 어댑터로 나중에 붙일 수 있게만 둔다(이번 범위 아님).

### 1.2 데이터

- `runs.subject` (`'lines' | 'terms'`, 기본 `lines`).
- `run_items.unit_id` → `subject_id`(text, FK 없음). 대상 삭제 시 앱에서 그 대상의 열린 항목을 취소한다(대사는 지금의 cascade와 같은 결과).
- `run_steps.unit_ids` → `subject_ids`, `returned_lines` → `returned_items`.
- `RunScope`에 `termIds`, `termMarks`(`candidate`, `ai`, `emptyTarget`, `unused`), `termStatuses` 추가.
- 마이그레이션은 이름 변경과 기본값 채우기만. 하위 호환 없음. `term_jobs` 테이블과 `ai_calls.kind = 'terms'`는 1.8에서 삭제.

### 1.3 진입 노드

```
{ subject: 'lines', statusIds: [...] }
{ subject: 'terms', statuses: ['candidate'], marks: ['emptyTarget'] }
```

- 용어 진입 기본값: 후보 중 표기가 빈 것. 정렬은 등장 수(`lines`) 내림차순, 다음 원문 순. 실행 전에 `fillTermUsage`로 등장 수를 채운다.
- 진입 노드 설정 화면에서 대상 종류를 고르면 아래 조건 입력이 바뀐다. 대상을 바꾸면 그 대상에서 쓸 수 없는 노드가 검증 오류로 표시된다.

### 1.4 묶음

- 용어에는 `unit`(하나씩)과 `count`(고정 개수, 기본 100)만 허용한다. `group`(장면)·`whole`(대본 전체)은 검증 오류.
- 토큰 크기는 원문 + 용례 줄로 추정한다.

### 1.5 AI 노드 입력 (용어)

- 프롬프트 항목: `{ id: 'T1', source, target?, note?, lines, examples: [{ speaker, source, translation }] }`. id는 대사의 `L1`처럼 `T1…`.
- 문맥 옵션(용어에서 쓸 수 있는 것만 보인다): 용어집(확정), 인물(용례에 나온 인물), 인물 명단, 문서, **용례 수**(새 옵션, 기본 2). 앞 대사·청자·말투·장면은 숨긴다.
- 출력 형태는 대사와 같다(`text`/`verdict`/`choice`/`json`, 항목마다 또는 묶음 전체). `text`는 그 용어의 표기 후보가 된다(`item.data.candidateText`).

### 1.6 노드 적용 범위

`FUNCTIONS`와 `APPLY_TARGETS`에 `subjects`를 둔다. 팔레트는 워크플로 대상에 맞는 것만 보이고, 검증이 어긋난 노드를 잡는다.

| 노드 | 대사 | 용어 |
|---|---|---|
| AI, 조건, 스크립트, HTTP, 끝 | ✓ | ✓ |
| 상태 변경, 형식 검사, 용어 검사, 번역 후보 기록, 청자 설정, 태그 붙이기 | ✓ | — |
| 지식 반영(용어·인물·관계·말투·사건·문서·장면 청자 저장) | ✓ | ✓ |
| **용어 표기 저장**(새, 이 용어의 표기·메모. 제안/직접, "비어 있을 때만" 옵션 기본 켬) | — | ✓ |
| **용어 상태 변경**(새, 후보·확정·거절) | — | ✓ |

- 조건 데이터: 용어는 `term: { status, statusBy, hasTarget, lines, marks, tagIds }`(대사의 `unit` 자리).
- 스크립트·HTTP가 보는 값도 대상별(`termView`).

### 1.7 실행 화면·CLI·skills

- 실행 상세: 대상이 용어면 열은 원문·표기·등장·결과, 오른쪽 패널은 용어 패널(`TermPane`). "대사/줄" 문구는 대상 이름으로.
- 실행 목록 진행 단위도 대상 이름.
- 용어집 화면: "AI로 채우기"와 진행 표시를 지우고, 선택한 용어(또는 현재 필터)로 워크플로를 실행하는 `RunDialog`를 둔다. 용어 패널의 "실행 · N줄"(등장 대사로 대사 워크플로 실행)은 그대로.
- CLI: `loca runs plan|start --terms [--term-mark …] [--term-id …]`, `runs list|show` 문구. skills: `loca-workflows`(대상), `loca-glossary`(채우기는 용어 번역 워크플로로).
- SSE: 용어 대상 실행은 `units` 대신 `terms`를 알린다.

### 1.8 용어 AI 채우기 이전

- 프리셋 `termTranslate`(AI 용어 번역): 지금 SYSTEM 프롬프트를 지시문으로 옮긴다. 출력 `json`·항목마다: `isTerm`(필수), `target`, `note`.
- 템플릿 "용어 번역": `진입(용어: 후보·표기 없음) → AI 용어 번역(count 100) → 조건(isTerm) → 참: 용어 표기 저장(제안) / 거짓: 용어 상태 변경(거절)`.
- 일반어 판정은 `NOT_A_TERM` 메모 대신 **AI가 거절한 후보**(`status: rejected`, `statusBy: ai`)로 남긴다. 거절된 용어는 다시 제안되지 않고, "AI 결정" 표시로 사람이 되돌릴 수 있다. 기존 `NOT_A_TERM` 메모 행은 마이그레이션으로 거절 처리.
- 삭제: `TermService`의 채우기 부분, `/terms/suggest*` 라우트, `FillDialog`, `term_jobs`, 실행 목록·알림의 용어 작업 항목.

## 2. 모으기 노드 (M4)

### 2.1 동작

- 새 노드 종류 `gather`(모으기). 설정: `{ from: <노드 id>, fields: [<경로>…] }`.
- **실행 전체 기준의 장벽**: 모으기로 갈 수 있는 앞쪽 노드에 실행의 열린 항목(대기·처리 중)이 하나도 없을 때 닫힌다(러너의 `openByNode` 판단을 그대로 쓴다). 그 전까지 도착한 항목은 모으기에서 기다린다.
- 닫히면 도착한 항목들의 `outputs[from]`을 모은다. `from`이 묶음 전체 답이면 묶음 대표 항목만, 항목마다 답이면 모든 항목(대상 id 포함).
- 결과 `outputs[gather] = { parts: [...], count, failed }`. `fields`가 있으면 각 part에서 그 경로만 남긴다(예: `characters[].name`, `characters[].aliases`, `overview`).
- **대표 항목 하나만 `out`으로 나간다**(대상 순서상 첫 항목, `batchLeader: true`). 나머지는 모으기에서 끝난다(`done`, 경로에 "모으기에서 합쳐짐").
- 앞에서 실패한 항목은 도착하지 않는다. `failed`에 그 수가 남아 조건 노드로 갈래를 나눌 수 있다. 도착이 0이면 아무것도 나가지 않는다.
- 실행 이어하기로 다시 들어온 항목이 이미 닫힌 모으기에 도착하면 두 번째 모음을 만든다(새 대표 항목).

### 2.2 검증

- 모으기 뒤에는 대상을 바꾸는 노드(상태 변경, 번역 후보 기록, 청자 설정, 태그, 용어 표기 저장, 용어 상태 변경)를 둘 수 없다. 모으기 뒤의 흐름은 "합친 결과 하나"이기 때문이다.
- 모으기 뒤의 AI 노드는 입력을 "앞 노드 결과만"(2.3)으로 둬야 한다.
- 반복 안의 모으기, 갈래가 만나는 지점으로서의 모으기는 v1에서 허용하지 않는다.

### 2.3 AI 노드 입력 (M1 PR 5와 같은 설계)

```
input: { lines: true | false, from?: <노드 id>, fields?: [<경로>…] }
```

- `lines: true` + `from`: 대상(대사·용어)과 함께 그 항목의 `outputs[from]`을 넣는다(예: 청자 추정 결과를 번역에).
- `lines: false` + `from`: 대상 없이 앞 노드 결과만 넣는다. 묶음 전체 답 전용. 모으기 뒤에서 쓴다.
- 서버가 붙이는 입력 설명은 "앞 노드 결과가 `previous`에 있다" 한 줄(형식 문장과 같은 성격).
- 정정: 수정 노드가 받는 "검수 지적"(`include.issues`)은 특정 노드의 출력이 아니라 대상의 현재 상태(가장 최근 실패한 검수·검사의 지적, 새 후보가 생기면 지워짐)라서 이 기능으로 대체하지 않고 그대로 둔다.

### 2.4 크기

- 모은 결과가 다음 AI 노드의 예산을 넘으면 그 노드가 `too-long` 오류로 `오류` 출구에 나간다(M1 PR 2의 실패 처리 방식). 숨은 자동 분할은 없다.
- v1은 한 번에 합친다. 여러 번에 나눠 합치기는 실제로 필요해지면 "모으기 단위: 실행 전체 / 실행 계획 묶음별" 옵션으로 확장한다(이번 범위 아님).

### 2.5 화면

- 편집기: 팔레트에 "모으기", 설정은 가져올 노드와 남길 필드(출력 필드 목록에서 고르기).
- 실행 중: `도착 37 · 기다리는 중`, 닫힌 뒤 `모음 3개`. 실행 상세에서 모은 결과를 볼 수 있다.

### 2.6 작품 분석 템플릿

```
진입 → AI 작품 분석(대본 전체)
  ├ 관계 저장 → 말투 규칙 저장 → 사건 저장 → 용어 저장 → 장면 청자 저장     (조각마다, 지금처럼)
  └ 모으기(fields: characters[이름·별칭·소개·플레이어·성별·나이대·비중], overviewTitle, overview)
       → AI 결과 합치기(입력: 앞 노드 결과만, json·묶음 전체: characters, overviewTitle, overview)
       → 인물 저장 → 문서 저장
```

- 결과 합치기 지시문(프리셋 `analysisMerge`): 같은 인물(이름·별칭·소개가 가리키는 사람)을 하나로 합치고 별칭을 모으며, 조각별 개요를 하나의 개요로 다시 쓴다. 근거는 조각 결과에 없으므로 인물 근거는 빈다(관계·사건 등 나머지는 조각마다 근거를 유지).
- 대본이 한 조각이면 합치기는 결과 하나를 다시 정리하는 작은 호출이 된다(인물 목록 + 개요 크기). 비용이 작아 갈래를 나누지 않는다.

## 5. 검증

- 단위 테스트: 대상별 고르기·묶음·프롬프트, 노드 적용 범위 검증, 모으기 장벽(지연 항목, 실패 항목, 이어하기, 빈 모음), 마이그레이션.
- 격리 `WORKBENCH_DATA_DIR` + `pnpm mock-llm`(기본·`cli-like`·`faulty`) + `samples/realistic-9k.json`으로 브라우저 전체 여정:
  - 용어집 → 후보 선택 → 용어 번역 실행 → 제안 수락 → 거절된 일반어 확인 → 실행 상세(용어 열) → 뒤로/앞으로.
  - 작품 분석을 작은 묶음 예산으로 여러 조각이 나게 실행 → 모으기 대기·닫힘 표시 → 합친 인물·개요 제안 확인.
  - 기존 대사 워크플로(번역·검수·수정)가 M3-1 뒤에도 같은 결과인지 비교.
- 실제 AI 호출 없음.
