# 출구 동작: 태그·상태 노드를 없애고 출구에 붙이기

2026-11-03 · 상태: 승인, 구현(브랜치 `claude/exit-actions`). §11의 정할 것은 모두 권장대로.

## 1. 한 줄 요약

태그 붙이기·떼기(`tagLines`)와 상태 바꾸기(`setStatus`) 노드를 없앤다. 그 일은 **노드의 출구에 붙는 동작**(출구 동작)이 된다. 대사가 그 출구를 떠날 때, 선이 갈라지기 전에 한 번 적용된다. 화면에서는 출구마다 표지 하나로 선 위에 보이고, 데이터와 CLI·에이전트도 같은 구조를 본다.

노드는 일(AI·검사·조건·반영·HTTP·모으기·부르기)만 하고, 대사에 표시를 남기는 일은 출구가 한다.

## 2. 무엇이 출구 동작이 되나

| 지금의 노드 | 출구 동작 | 비고 |
|---|---|---|
| 태그 붙이기 (정해 둔 태그) | `tag` add | |
| 태그 떼기 (정해 둔 태그) | `tag` remove | |
| 태그 붙이기 (앞 결과의 필드에서 이름 읽기, 예: 검수의 `categories`) | `tag` add + `fromField` | 출구는 자기를 떠나는 노드의 결과를 안다(§4.3) |
| 상태 바꾸기 (+ 그 노드의 태그 붙이기·떼기) | `status` (+ `tag`들) | 한 노드가 하던 일이 동작 여럿으로 나뉜다 |

**노드로 남는 것: 반영 노드**(번역 저장, 청자 기록, 용어·인물·사건 저장). 구조로는 이것들도 "쓰고 지나가는" 노드지만, AI 결과를 필드에 잇는 설정이 있고 워크플로의 목적 그 자체라 사람이 단계로 읽는다. 이번에는 옮기지 않는다.

## 3. 데이터 형식

동작은 **출구를 가진 노드**에 저장한다. 선을 다시 잇거나 지워도 동작이 남고, 같은 출구의 선 여럿이 동작을 나눠 갖는 일이 없다.

```ts
// packages/shared/src/workflow.ts
const exitActionSchema = z.discriminatedUnion('type', [
  z.object({
    type: z.literal('tag'),
    action: z.enum(['add', 'remove']),
    tagIds: z.array(z.string()).default([]),       // 정해 둔 태그
    fromField: z.string().optional(),              // 앞 결과의 이 필드 값을 태그 이름으로(예: 'categories')
    categoryTags: z.record(z.string(), z.string()).default({}), // 필드 값 → 태그 id (지금 tagLines와 같음)
  }),
  z.object({ type: z.literal('status'), statusId: z.string() }),
]);
// 모든 노드(진입 포함)에: 출구 id → 적힌 순서대로의 동작
node.exits?: Record<string, ExitAction[]>
```

- 출구 id는 지금의 포트(`out`, `error`, `pass`/`fail`, `true`/`false`, 조건의 갈래…) 그대로다.
- 노드의 포트가 사라지면(예: 조건 갈래를 지움) 그 출구의 동작도 지운다. 화면에서 지울 때 안내한다.
- `fn: 'tagLines' | 'setStatus'`는 함수 목록·팔레트·스키마에서 없앤다. 호환 별칭은 두지 않는다.

## 4. 실행 규칙

### 4.1 언제, 어디서

`Runner.route()`(`apps/server/src/engine/runner.ts`)가 한 대사를 출구로 내보낼 때 적용한다. 순서는 이렇다.

1. 오류 출구면 먼저 재시도 규칙을 본다. 다시 보내면 동작을 적용하지 않는다. 아직 출구를 떠난 게 아니기 때문이다.
2. **출구 동작을 적힌 순서대로 적용한다**(새 `engine/exit-actions.ts`). 같은 트랜잭션 안에서 다음 노드로 옮기기 전에 한다.
3. 선을 따라 다음 노드로 옮긴다. 선이 여럿이면 대사를 복제한다(지금과 같음). 동작은 이미 한 번 적용됐다.

동작을 적용한 출구는 대사가 지니고 온 실패를 처리한 것으로 본다. 지금 오류 출구 뒤의 태그·상태 노드가 실패를 지우던 것과 같다. 그래서 오류 출구에 동작이 있고 선이 없으면 대사는 **완료**로 끝난다(예: AI 노드의 오류 출구 → 상태 `검토 필요`).

그래서 다음이 따라온다.
- **진입 노드의 출구**에 붙은 동작은 실행에 들어온 모든 대사에 적용된다.
- **선이 없는 출구**는 동작을 적용한 뒤 대사를 끝낸다(동작이 실패를 처리하므로 완료). 검증은 상태를 바꾸는 출구만 선 없이 두게 한다. 태그만 바꾸는 출구에 선이 없으면 지금처럼 "출구가 연결되지 않았습니다" 오류다(검사 뒤 선을 잊은 경우가 훨씬 많다). 오류 출구는 지금처럼 선 없이 둘 수 있다.
- **끝으로 가는 출구**에 상태 동작을 붙이면 지금의 '검토 필요로 끝'이 된다.
- **방문 횟수**: 동작은 노드가 아니라서 방문으로 세지 않는다. 지금은 수정 루프를 돌 때마다 태그 노드 방문이 노드 방문 상한을 깎는다.
- **되돌아가는 선**: 지날 때마다 다시 적용한다. 태그 붙이기·떼기와 상태 바꾸기는 여러 번 해도 결과가 같다.

### 4.2 지금 노드가 하던 보호는 그대로

`setStatus`·`runTags`(`engine/functions/index.ts`, `functions/apply.ts`)가 하던 일을 옮기며 그대로 지킨다.
- **사람이 쓴 번역 보호**(`personOwns`): 상태로 고른 실행에서는 사람이 정한 대사의 상태를 바꾸지 않고 알림만 남긴다.
- **태그가 붙을 수 없는 곳**(태그 범위가 좁아짐): 붙이지 않고 알림을 남긴다(`onMisplaced: 'skip'`).
- **용어 워크플로**: 상태는 후보·확정·버림 중 하나이고, 태그는 용어 태그다.
- 상태를 바꾼 대사에는 지금처럼 `statusBy: 'ai'`와 `statusRunId`가 남는다.

### 4.3 앞 결과에서 태그 이름 읽기

`fromField`가 있으면 **지금 떠나는 노드의 결과**에서 이름을 읽는다. 그 노드가 결과를 내지 않으면(조건 노드처럼) 경로를 거슬러 가장 가까운 결과를 읽는다. 지금의 `previousStepId`를 그대로 쓰고, 지금 노드를 경로 끝에 넣어 부른다. 검증도 지금처럼 결과를 내는 노드 뒤에서만 허락한다(`applyIssues`).

### 4.4 실패와 '안 붙음'

- **정해 둔 태그·상태**: 지워진 것은 지금처럼 실행 전 검증이 막는다. 대사마다 '안 붙음'을 남기지 않는다.
- **실행 중에 태그가 지워졌으면**: 실행은 시작할 때 쓰는 태그의 이름·색·범위를 갖고 있다가(`runs`에 스냅샷), 태그가 없으면 같은 이름으로 다시 만들어 붙인다.
- **실행 중에 상태가 지워졌으면**: (정할 것 §11-2) 권장은 바꾸지 않고 실행 알림으로 한 번 모아 보여 주는 것이다. 상태 목록은 사람이 정한 체계라 실행이 되살리지 않는다.
- **AI가 말한 이름의 태그가 없으면**: (정할 것 §11-1) 권장은 (가) 붙이지 않고, 실행 상세에 "없는 태그 이름 3종 · 12줄"처럼 이름별로 한 번만 모아 보여 주는 것이다.
- **DB 오류처럼 진짜 실패**: 그 대사는 실패로 끝나고, 오류에는 "‘AI 검수’ 실패 출구의 동작" 처럼 출구가 적힌다. 오류 출구로 다시 보내지 않는다. 동작 실패가 오류 출구의 동작을 또 부르는 고리를 막기 위해서다.

## 5. 기록과 실행 상세

- **대사 이력**: 형식을 바꾸지 않는다. 지금도 `statusRunId`가 있어 "번역 워크플로(실행 11월 3일 00:07)"로 보여 줄 수 있다. 어느 출구였는지는 이력에 남기지 않는다.
- **실행 상세·실행 그래프**: 출구별로 **지나간 수**와 **알림**을 센다. 새 표는 두지 않는다.
  - 지나간 수: 노드별 '지나감'처럼 대사의 경로(`data.path`의 `{nodeId, port}`)에서 센다(`runProgress().exits['노드:출구'].passed`).
  - 알림: 동작이 하지 못한 일을 대사의 `data.exitNotes: [{at: '노드:출구', note}]`에 남기고, 출구·알림별 대사 수로 모은다(`exits[…].notes`). 사람이 쓴 번역이라 상태를 안 바꿈, `없는 태그 이름: …`, 붙을 수 없는 태그.
  - 실행 화면의 실행 정보 패널에 '출구 동작 알림'으로 보인다.
- **실행 그래프**: 편집기와 같은 표지를 그린다. 출구로 나간 줄 수는 적지 않는다(노드의 '지나감'이 이미 보여 준다).

## 6. 검증 (`validateWorkflow`)

- 지워진 태그·상태: 오류(지금과 같음).
- 입력 종류에 맞지 않는 동작: 오류. 용어 워크플로에 대사 상태를 붙이는 경우 같은 것이다.
- `fromField` 동작이 결과 없는 자리에 있음: 오류(지금의 `applyIssues`와 같은 말).
- 한 출구에 상태 동작이 둘 이상: 경고("마지막 것만 남습니다").
- 같은 태그를 붙이고 떼는 동작이 한 출구에: 경고.
- 없는 포트에 붙은 동작: 오류. 정의 파일을 손으로 고친 경우에 생긴다.

## 7. 마이그레이션 0122

`db/index.ts`에 SQL 함수 `exit_actions(definition)`을 두고, 0121처럼 워크플로와 실행 정의를 모두 다시 쓴다. 지울 노드(`tagLines`·`setStatus`) N마다 다음을 한다.

1. N이 할 일을 동작 목록으로 만든다. `setStatus`는 `status` 하나와 태그 붙이기·떼기 동작으로 나눈다.
2. N으로 들어오는 선(보내는 노드 S, 출구 H)마다 N의 동작을 **S의 출구 H**에 덧붙인다.
3. 그 선이 N 대신 **N의 `out` 출구가 가던 곳**으로 바로 가게 잇는다. N의 `out`에 선이 여럿이면 선을 그만큼 만들고, 없으면 그 선을 지운다(출구에서 끝).
4. N의 오류 출구 선은 버린다(§4.4).
5. N을 프레임(`groups[].nodeIds`)에서 뺀다.
6. 태그 노드가 줄지어 있으면(N1 → N2) N2가 옮겨진 뒤 N1의 동작에 이어 붙는다. 지울 노드가 남지 않을 때까지 되풀이한다.

주의할 점이 둘 있다.
- **갈라지는 출구**: S의 출구 H에 N 말고 다른 곳으로 가는 선도 있었으면, N의 동작이 이제 그 선으로 가는 대사에도 적용된다. 새 규칙(출구에 붙음) 때문에 생기는 차이다. 기본 템플릿에는 이런 곳이 없다. 마이그레이션이 그런 출구를 찾으면 검증 경고("이 출구의 동작은 모든 갈래에 적용됩니다")가 뜨게 둔다.
- **끝나지 않은 실행**: 정의를 같은 방식으로 고친다. 지울 노드에 대기 중인 대사는 그 노드의 `out`이 가던 곳으로 옮긴다(0121의 `retry_node_origin`과 같은 방식). 그 대사들에는 그 동작이 적용되지 않는다. 즉시 실행되는 노드라 이런 대사는 멈춘 실행에만 몇 줄 있다.

테스트: 0121처럼 옛 형식 DB를 만들어 마이그레이션을 돌리고 확인한다(`db/exit-actions-migration.test.ts`). 확인할 것은 기본 템플릿 다섯 개, 줄지은 태그 노드, 갈라지는 출구, 멈춘 실행의 대기 대사다.

## 8. 화면

- **출구 표지**(`ExitTag`): 캔버스에는 흐름을 읽는 데 필요한 것만 둔다. 출구 하나에 표지 하나: 상태는 이름까지(`→ ✓ 완료`), 태그는 아이콘과 개수만 흐리게(`🏷 −7`). 앞 단계 결과에 따라 붙는 태그는 그 동작에 값마다 정해 둔 태그 수로 `🏷 +최대 6`(정해 둔 태그가 없으면 `+?`)이고, 이름을 지어 부르지 않는다. 어떤 태그인지는 표지에 마우스를 올리면 뜨는 목록(추가할 태그·제거할 태그로 묶고, 결과에 따른 태그는 'AI 검수 결과에 따라' 아래)과 출구 패널에서 본다.
- **출구 패널**의 태그 동작: 추가할 태그·제거할 태그 중 하나로 만든다. 직접 고른 태그만 칩으로 보이고 목록에서 더 고른다. '○○ 결과에 따라'는 결과의 어느 값을 쓸지(필드가 스스로 말하는 설명으로)와, 값마다 태그 표(동작에 저장된 짝만, 값은 더하고 뺄 수 있음)다.
- **표지 자리**: 표지는 자기 선의 가장 긴 구간에(포트에서 나온 첫 구간은 피하고, 프레임 사이로 가는 선이면 프레임 밖 구간에), 노드·다른 표지와 겹치지 않게, 다른 선과 함께 쓰는 줄기(같은 입력으로 합쳐지는 끝)는 피해서 둔다. 선이 없는 출구(상태로 끝나는 출구)는 출구 색의 짧은 선(28px)을 긋고 그 끝에 표지를 둔다. 자동 정렬은 그 자리를 노드 여백으로 비워 두고, 프레임은 그만큼 커진다.
- **선을 옮길 때**: 노드 설정을 바꿔도 선의 경로는 그대로다. 노드나 프레임을 끌면 그 끝만 따라오고(프레임 안의 선은 통째로), 나머지 경로와는 짧은 계단으로 이어진다(`route-shift.ts`). 다시 정렬하는 것은 `자동 정렬`뿐이다.
- **출구 패널**: 선이나 칩을 누르면 오른쪽에 열린다. 노드·프레임 패널과 같은 자리다.
  - 머리: `AI 검수 · 실패 출구 → 수정`
  - 동작 목록: 추가(태그 붙이기 / 태그 떼기 / 상태 바꾸기), 순서 바꾸기, 삭제. 태그 이름을 결과에서 읽는 설정은 지금 태그 노드 패널의 것을 옮긴다.
  - 받는 노드: 바꾸거나 선을 삭제한다.
  - 주소: `?exit=<nodeId>:<port>`. 뒤로/앞으로 가기가 된다.
- **노드 패널**: '나가는 출구' 목록에 각 출구의 동작을 글로 보여 주고(없으면 '출구 동작 추가'), 누르면 출구 패널로 간다.
- **선 누르기**: 선을 누르면 그 출구의 패널이 열린다.
- **'＋ 노드' 목록**: '태그 붙이기 / 태그 떼기 / 상태 바꾸기'를 '출구 동작' 묶음으로 남긴다. 선 위에 끌어 놓으면 그 출구에 붙고, 누르면 "동작을 붙일 선을 고르세요" 상태가 된다(Esc 취소).
- **실행 그래프**: §5의 수를 보여 준다.
- **접기 코드 정리**(`fold.ts`): 지나가는 노드 접기(규칙 2)와 `lineMarks`를 없앤다. 여러 출구가 모이는 끝 노드를 칩으로 접는 규칙 3은 남는다. 상태를 바꾸지 않는 끝도 있기 때문이다. '접힌 노드 펼치기'는 그 끝 칩만 다룬다.

## 9. CLI · 에이전트 · 스킬

- 정의 파일에 `nodes[].exits`가 생긴다. `loca workflows save`·`reference`가 읽고 쓴다.
- `loca workflows show`가 출구마다 동작을 적는다. 예: `AI 검수 실패 → 수정  [+#형식 오류, +#검수 지적]`
- 에이전트 도구 설명(`services/agent-tools.ts`의 `definitionShape`, `tagNode` 안내)을 새 형식으로 바꾼다.
- `.claude/skills/loca-workflows`: 태그·상태는 출구 동작이라는 것, 갈라지는 출구에서 적용되는 방식, 예시를 적는다. `skills.test.ts`가 확인한다.

## 10. 바뀌는 곳과 순서

1. **shared**: 스키마(`exitActionSchema`, `node.exits`), 함수 목록에서 `tagLines`·`setStatus` 제거, 검증, 템플릿(`defaults.ts`: 태그·상태 노드 모두가 출구 동작으로), `ITEM_CHANGING_FUNCTIONS` 정리
2. **server**: `engine/exit-actions.ts`(옮겨 온 보호 규칙), `route()`, 태그 스냅샷, `run_exits`와 트리거, 마이그레이션 0122와 테스트, 실행 상세, 에이전트 도구
3. **web**: 출구 패널, 선 위 칩(출구 줄기), 노드 패널의 출구 칩, 팔레트의 출구 동작, 실행 그래프 수, `fold.ts` 정리, 자동 정렬 확인
4. **CLI·스킬·문서**: `workflows show`, 스킬, 계획 문서, DESIGN-SYSTEM

테스트: 실행 엔진 테스트(출구 동작 순서, 갈라지기 전 한 번, 되돌아가는 선, 사람 번역 보호, 없는 태그 이름 모으기, 실행 중 지운 태그 다시 만들기, 방문 안 셈), 마이그레이션, 검증, 화면(접기·칩·패널). 브라우저에서는 격리 데이터와 목 LLM으로 전체 흐름을 확인한다.

## 11. 정할 것

1. **AI가 말한 없는 태그 이름**: (가) 붙이지 않고 실행 상세에 모아 보여 줌(권장) / (나) 같은 이름으로 새로 만들어 붙임.
2. **실행 중에 지워진 상태**: 바꾸지 않고 알림(권장) / 다시 만듦.
3. **갈라지는 출구를 마이그레이션할 때**: 그대로 옮기고 경고(권장) / 옮기지 않고 그 워크플로를 '고쳐야 함'으로 표시.
