# loca 시각 언어 재설계 — 토큰 감사와 세 가지 방향

작성: 2026-10-18 (KST) · `PROPOSAL.md`(구조)의 짝 문서. 이번에는 구조만이 아니라 **글꼴·선·색까지 바꾼다**는 주인의 요청을 반영했다.
목업: `directions/*.html` → `directions/*.png`(1440×900, `/tmp/pp/directions.mjs`로 렌더). 토큰은 `directions/src/{a-slate,b-manuscript,c-night}.css`, 공통 배치는 `directions/src/base.css`, 생성기는 `directions/src/gen.py`다.

## 1. 지금 토큰 감사 (`apps/web/src/index.css`, `packages/ui`, `packages/shared/src/defaults.ts`)

측정값은 index.css의 OKLCH 값을 sRGB로 바꿔 WCAG 대비로 계산했다. 사용 횟수는 `apps/web/src`와 `packages/ui/src`에서 grep으로 셌다.

### 1.1 글꼴
| 항목 | 지금 | 문제 |
|---|---|---|
| 글꼴 지정 | `"Pretendard Variable", Pretendard, -apple-system, "Segoe UI", Roboto` | **Pretendard를 앱이 싣지 않는다.** 저장소에는 글꼴 파일도 `@font-face`도 import도 없다. 이 박스는 시스템에 Pretendard가 깔려 있어서 스크린숏이 멀쩡해 보였을 뿐이다. 주 대상인 Windows(DESIGN §1 "Windows 로컬 작업실")에 Pretendard가 없으면 한글은 Segoe UI를 거쳐 **맑은 고딕**으로, 라틴은 Segoe UI로 떨어진다. 주인이 본 "글꼴이 이상하다"의 가장 큰 원인일 가능성이 높다. impeccable typeset의 Stress·Delivery 항목(폴백 확인, 쓰는 자산을 직접 싣기)을 어긴다 |
| 크기 단계 | 11.5 / 13 / 14 / 15 / 17 / 19px | 13→14→15가 **1.07배 간격**이라 크기로는 역할이 갈리지 않는다. impeccable Operate 권장은 1.125~1.2다. 본문(14)과 강조 본문(15), 제목(17)과 페이지 제목(19)이 눈으로 구분되지 않는다 |
| 굵기 | `font-medium` 111회, `font-semibold` 43회, `font-bold` 1회 | 위계를 거의 500 하나로 만든다. 섹션 머리(인스펙터 '내용')는 13px 회색 500이라 본문보다 약하다 |
| 회색 글자 | `text-muted-foreground` **477회**, 한 단계(L 0.48) | 대비는 6.4:1로 충분하다. 그런데 보조 글자가 **회색 한 가지**뿐이라 라벨, 메타, 도움말, 빈 값이 모두 같은 회색이다. "흐릿하다"는 인상은 대비가 아니라 **단계가 없다**는 데서 온다 |
| 아이콘 | Lucide `stroke-width 1.5`, 13px | 14px 500 글자 옆의 1.5px 획은 가늘어서 버튼이 비어 보인다 |
| 자간 | 15px 이상 -0.011em | 문제 없음 |

### 1.2 선과 면
| 항목 | 지금 | 문제 |
|---|---|---|
| 선 색 | `--border` L 0.915, 바탕 대비 **1.26:1**. `border-border/80` 54회, `/60` 9회로 더 옅게 쓴다. `--border-subtle` 1.15:1 | 거의 보이지 않는 선을 **아주 많이** 쓴다(`border` 계열 519회). 표의 행마다, 원문과 번역 사이, 그룹 머리, 패널 경계, 입력, 배지(StatusBadge는 선 + `shadow-2xs`)에 다 있다. 하나하나는 흐린데 화면 전체로는 격자무늬가 된다. 입력의 경계 1.26:1은 WCAG 1.4.11(비텍스트 3:1)에도 한참 못 미친다 |

**impeccable 기계 검사**(`impeccable detect --scope type apps/web/src packages/ui/src`)는 아무것도 찾지 못했다(`[]`). 위 문제는 모두 값과 렌더를 직접 보고 찾은 것이다. craft-floor의 "A clean scan is a floor, not proof"와 같다.

### 1.4 레퍼런스와 비교
- **Linear:** 면 단계(사이드바가 본문보다 한 단계 어둡고 차갑다)로 영역을 나눈다. 목록 행에는 선이 없고 hover 면만 있다. 상태는 **모양**(빈 원, 반원, 채운 원+체크)으로 구분한다. 강조색은 하나다.
- **Figma UI3:** 입력에 **바탕색**을 넣고 드롭다운에 테두리를 둬서 "어디가 조작부인지"를 선보다 면으로 말한다. 아이콘을 굵게 다시 그렸다.
- **Crowdin·Phrase:** 번역 격자의 행 구분은 얇은 선 하나이고, 상태는 행 왼쪽의 작은 표시 하나다. 칩은 드물게만 쓴다.
- **ComfyUI·Arcweave·Unreal:** 어두운 면 단계, 노드 종류마다 머리 색, 선은 거의 없다.

loca는 이들과 달리 **면 대신 선**, **모양 대신 색 점**, **강조 하나 대신 둘**, **글꼴을 싣지 않음**이다.

## 2. 세 가지 방향

impeccable Operate 규칙에 따라 방향은 **글꼴, 팔레트, 밀도, 대표 표현(signature move)** 네 가지만 바꾼다. 배치, 내비게이션, 조작부는 세 방향 모두 `PROPOSAL.md` 4장 그대로다. 그래서 목업 6장은 같은 HTML 구조에 토큰 파일만 다르다.

공통으로 고치는 것(어느 방향이든):
- 글꼴 파일을 **앱에 싣는다**(`@fontsource` 또는 `packages/ui/fonts`, `font-display: swap`, 한글은 분할 subset). 로컬 앱이라 용량 부담이 적다.
- 강조색은 **하나**로 한다(주 버튼 = 선택 = 포커스).
- 'AI가 정함'은 보라 칩 대신 **작은 아이콘 + 모델 이름**(회색)으로 표시한다. 칩은 인스펙터 머리에만 둔다.
- 상태는 **모양 + 색**으로 표시한다. 미번역은 빈 원, 초벌은 반쯤 찬 원, 확인 필요는 채운 원 + 느낌표, 확정은 채운 원 + 체크다. 상태 이름 글자에는 4.5:1 이상인 '잉크' 색을 따로 둔다.
- 호박색은 **'확인 필요' 상태에만** 쓴다. 경고는 주황 잉크, 이슈 유형은 아이콘 + 글자로 표시한다(색 점을 쓰지 않는다).
- 사용자 지정 상태색 팔레트(`STATUS_COLORS` 20색)는 방향마다 밝기를 맞춘 12색 팔레트로 바꾼다.
- 행 구분선을 없앤다. 영역은 면 단계로, 행은 간격과 hover 면으로 나눈다. 선택한 줄은 면 + 입력 링으로 표시하고, 왼쪽 색 막대는 쓰지 않는다(craft-floor 금지 항목).
- 반지름은 방향마다 **두 값**만 쓴다(조작부 / 패널).
- 아이콘은 Lucide를 쓰되 획을 1.75~1.9로 올린다.

| Operate 적합성(익숙함·훑어보기) | 가장 높다. Linear·Figma 사용자는 바로 안다 | 중간. 편집기는 좋지만 설정·표·연결 화면에서 세리프와 종이 톤이 쓰임새를 잃는다 | 높다. 게임 에디터 사용자에게 익숙하다 |
| 번역 품질 작업(긴 대사 읽기) | 좋다 | **가장 좋다.** 세리프·행간·화자 열로 대본처럼 읽힌다 | 좋다. 어두운 바탕에서 긴 한글은 피로도가 사람마다 다르다 |
| 밀도(1440에서 대사 줄 수) | 7~8 | 6 | 7~8 |
| 선 줄이기 | 영역 경계만 | 거의 없음 | 없음 |
| 상태 구분(색각 이상) | 모양 + 색 | 모양 + 색(채도 낮음, 확인 필요와 미번역 차이가 작다) | 모양 + 색(가장 선명) |
| 대비 | 본문·잉크 4.6:1 이상. 상태 아이콘 3:1 안팎(확인 필요 3.0) | 4.7:1 이상, 상태 3.3:1 이상 | 4.9:1 이상, 상태 4.5:1 이상 |
| Windows 렌더링 | Wanted Sans는 ClearType에서 획이 고르다 | Noto Serif KR 15~16px는 Windows에서 가는 획이 흐려질 수 있다(실기 확인 필요) | SUIT는 어두운 바탕에서 무게가 안정적이다 |
| 다른 화면으로 넓히기 | 쉽다. 표, 설정, 폼이 모두 자연스럽다 | 어렵다. 대본 밖 화면에는 '원고'가 없다 | 중간. 표·폼은 되지만 설정 화면은 어둡게 무겁다 |
| 다크 모드 | C의 값으로 같은 구조의 다크 테마를 만들 수 있다 | 어두운 종이를 따로 설계해야 한다 | 라이트가 없어 따로 필요하다 |
| 구현 비용 | 낮다. 토큰 교체 + 선 삭제 + 상태 아이콘 | 중간. 글꼴 2벌, 편집기 격자 재배치 | 중간. 모든 의미색을 어두운 바탕용으로 다시 검증해야 한다 |

## 4. 추천

**A 슬레이트를 기본 방향으로 한다.**

1. 주인의 세 가지 불만에 바로 답한다.
   - 글꼴: Wanted Sans를 실제로 싣고, 굵기 세 단계를 둔다.
   - 선: 영역 경계를 빼고 모두 없앤다.
   - 색: 차가운 슬레이트 + 강조 하나 + 모양으로 나뉜 상태로 바꾼다.

   이게 화면 전체에 같은 방식으로 적용된다.
2. loca는 편집기만이 아니라 표, 설정, 그래프, 실행 기록까지 있는 **Operate 도구**다. impeccable 기준으로 "category-fluent user가 바로 믿을 수 있는" 쪽이 A다.
3. 토큰 구조(크롬·본문·패널 세 면, 글자 세 단계, 강조 하나, 상태 잉크)가 C와 같다. **다크 테마를 C 값으로 나중에 만들 수 있다**(Linear처럼 base·accent·contrast 세 변수로 생성). B는 두 테마 모두 따로 설계해야 한다.

B의 시나리오 조판은 PROPOSAL.md 4.3의 **'집중' 보기 안에서만** 쓰는 것을 고려할 수 있다. 대사를 읽고 고치는 화면 하나라서 역할이 분명하다. 기본 격자에 세리프와 종이 톤을 섞으면 impeccable이 금하는 "중간 타협"이 되므로 섞지 않는다. 이건 결정이 필요한 선택 사항이다.

**결정이 필요한 것**
- A로 갈지, 아니면 C를 기본으로 하고 라이트를 나중에 만들지. 작업 환경(밤에 게임과 같이 켜 두는지)에 따라 달라진다. impeccable은 "라이트·다크를 범주가 아니라 쓰는 장면으로 고르라"고 한다.
- Wanted Sans(A)와 SUIT(C) 중 하나. 둘 다 OFL이고 한글·라틴 가변 글꼴이다. Windows 실기 렌더 비교가 필요하다(이 박스는 Linux라 확인하지 못했다).
- 사용자 지정 상태색 팔레트를 12색으로 줄이는 데 대한 동의. 기존 프로젝트의 상태색은 가장 가까운 색으로 옮긴다.

**구현(PROPOSAL.md 5장에 끼우는 순서)**
- **P0.5 토큰:**
  - `packages/ui/src/tokens/theme.css`를 새로 만든다(A 값). index.css의 `:root`는 지운다.
  - 글꼴을 `packages/ui/fonts`에 싣는다.
  - `--radius` 두 값만 둔다.
  - `ui-rules`에 `border-border/NN`, `rounded-lg|xl|2xl`, `text-muted-foreground/NN`, Tailwind 색 이름(`amber-50` 등) 금지 규칙을 넣는다.
- **P1 셸**(PROPOSAL)과 같이 하는 것:
  - 면 단계(크롬·본문·패널)를 적용한다.
  - 사이드바·상태 막대는 크롬 면, 도크는 패널 면으로 한다.
- **P2~P3**과 같이 하는 것:
  - `StatusIcon`(모양 4종)을 만들어 `StatusDot`을 대체한다.
  - 'AI가 정함' 칩을 아이콘으로 바꾼다.
  - 이슈 유형은 아이콘 + 글자로 한다.
  - 행 구분선을 지운다.
- **검증:** 1280/1440/1920, Windows 실기(가능하면 사용자 PC), 색각 시뮬레이션(Chrome DevTools의 deuteranopia 렌더링).
