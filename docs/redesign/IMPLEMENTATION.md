# loca UI 개편 실행 문서

2026-10-18 · 기준: 이슈 #112, `PROPOSAL.md`, `VISUAL.md`, `mockups/a-slate-{editor,workflow}.png`, `mockups/c-night-{editor,workflow}.png`.

## 목표와 우선순위

첨부 A(라이트)·C(다크) 화면을 실제로 작동하는 제품으로 완성한다. 디자인 시스템은 이를 재현하는 수단이다. 컴포넌트 교체 개수나 빌드 통과를 디자인 완성으로 취급하지 않는다.

사용자 지시 > A·C 시안과 제안서 > 현재 구현·과거 문서. 과거 AGENTS/DESIGN의 가로 워크플로, 상세 모달 금지 등은 시안의 반대 근거로 쓰지 않는다. 기능적 제약이나 실제 사용성 문제 때문에 목표에서 벗어날 때만 문제·근거·대안을 제시하고 명시적 허락을 받는다.

반드시 **공통 컴포넌트 작성 → `@loca/ui` export 등록 → 화면에서 사용 → A/C 비교** 순서를 따른다. 화면 전용으로 같은 표현을 재작성하거나 className 덮어쓰기로 우회하지 않는다. 데이터 조회·저장·라우팅은 앱, 표현·상호작용은 UI 패키지가 담당한다.

## 화면 계약

- 1440×900 기준 앱 탐색 약 208px, 보조 탐색 약 200~216px, 오른쪽 도크 약 360px, 상단 48px. 중앙 작업 공간을 우선한다. 좁은 폭에서는 보조 탐색을 접고 오른쪽은 속성/에이전트 탭으로 교대한다.
- 앱 탐색·페이지 머리·상태 막대는 한 벌. 오른쪽 가장자리에도 도크 한 벌. 페이지별 상세 패널과 채팅이 중첩돼 본문을 줄이지 않는다.
- 페이지 머리: 현재 위치, 보기 전환, 주 동작 하나, 더보기. 필터 막대: 검색·필터·칩·개수. 선택 동작은 선택한 행/노드 가까이에 둔다.
- A: 차가운 슬레이트 면, 코발트 주 동작, 경계선 최소화, 청록 서식 토큰. C: 흑연 면 단계, 청록 주 동작, 중성 선택 면, 자주색 서식 토큰, 화자 이니셜, 종류별 노드 머리색.
- 글꼴은 포함된 Wanted Sans + Geist Mono를 사용한다. 글자 역할은 본문/조작부/메타, 굵기와 간격으로 위계를 만든다. 테마 값과 타입·치수·면 역할은 UI 패키지에서 관리한다.
- 대사: 장면 목록과 보기 프리셋 분리. 화자→청자 / 원문과 상태 / 번역을 정렬한다. 선택한 줄의 동작은 확정하고 다음·AI·더보기. 상세는 문맥·후보·검사·용어·이력. 후보는 출처/모델/시간과 적용 동작을 가진다.
- 워크플로: 라이브러리 / 세로 흐름 캔버스 / 속성. 노드는 제목·모델/요약·경고로 압축하고 선택 도구상자와 하단 캔버스 도구를 제공한다. 설정/입출력/오류, 기본/지시문/출력/고급. 자동 저장은 실제 저장 성공과 일치하고 실패·충돌을 숨기지 않는다.
- 실제 사용자 정의 상태와 실제 그래프/후보/실행 데이터를 쓴다. 시안의 숫자나 관계를 제품에 하드코딩하지 않는다.

## 사용자 여정과 수용 기준

1. 대사 선택 → 행에서 번역 → 속성에서 앞뒤 문맥·청자·후보 확인 → 적용/확정 후 다음 줄. 도크 탭·화면을 바꿔도 선택과 초안이 유지된다. 초안 보존과 서버 저장은 구분해 표시한다.
2. 워크플로 열기 → 라이브러리에서 노드 추가 → 노드 선택 → 속성 수정 → 자동 저장 결과 확인 → 실행 범위 확인 → mock 실행. 오류/충돌 시 저장되지 않은 편집을 보존하고 실행 가능한 버전을 명확히 한다.
3. 속성↔에이전트 전환은 같은 도크를 사용한다. 채팅 스트림·제안과 현재 선택 문맥을 보존한다. 여러 상세 패널이 필요한 중첩 화면에서는 가장 구체적인 선택이 도크를 차지한다.
4. URL은 선택·필터·보기·상세 탭의 기준이다. 초안과 뷰포트는 기존 보존 계약을 유지한다. SSE 갱신·팬·줌은 history를 추가하지 않는다. Back/Forward·새로고침으로 복원된다.
5. 1440×900 A/C 비교를 기본으로 1280·1920도 확인한다. 실제 폰트 로드, 긴 한글/영문, 빈/로딩/오류/선택/편집 상태를 포함한다. 9천 줄에서 전체 DOM을 쌓지 않는다.

| 계층 | 공통 부품 | 책임 |

| Navigation | Sidebar, NavigationPane | 앱/장면/라이브러리 밀도 |

| Editor | SpeakerIdentity, TranslationRow, InlineEditorActions, CandidateCard, ContextLine, EditorToolbar | 화자·대사 격자·선택 행 동작·후보·문맥·도구 슬롯 |

## 상호작용·밀도 계약 보강 — 사용자 피드백 2026-10-18

현재 공통화는 슬롯과 스타일 재사용에 머문 부분이 있다. 아래 항목은 **구현해야 할 기준**이며 완료 표시가 아니다. 사용자 제공 7개 캡처와 9개 지적을 반영한다. 세부 근거는 감사 문서의 ‘공통 컴포넌트와 실제 상호작용 재검토’에 있다.

1. **닫힌 오른쪽 패널:** 본문 헤더에는 다시 열기 동작 하나를 둔다. 속성/에이전트 전환은 열린 도크 안에 둔다. 다시 열 때 이전 모드를 복원한다. 검색은 별도 전역 동작으로 취급한다. 선택한 항목을 편집하는 행위를 패널을 수동으로 여는 요령에 의존시키지 않는다.
2. **아이콘:** 공통 부품이 역할에 따른 크기·선 굵기·색을 소유한다. 탐색 아이콘은 16px, 작은 조작 아이콘은 14px, 상태 표시 도형은 최소 12px를 기준으로 A/C에서 확인한다. 주 동작에는 버튼 전경색의 동작 아이콘을 사용하고, 목록의 상태 표시 색을 그대로 가져와 대비가 무너지지 않게 한다. 화면에서 6px로 축소하거나 래퍼 때문에 크기 규칙을 우회하지 않는다.
3. **하단 설정:** 설정 트리거는 맨 아래의 같은 위치를 유지하고 하위 항목은 위쪽으로 펼친다. 짧은 창에서도 항목이 잘리지 않도록 내부 스크롤을 제공한다. 현재 설정 페이지에 있다는 이유로 사용자의 접기 동작을 무시하지 않는다.
4. **행 AI 동작:** 모델 유무와 무관하게 아이콘+‘AI 번역’ 진입점을 표시한다. 모델이 없으면 설정 필요 안내와 편집기 모델 설정으로 가는 동작을 보여 준다. 초안을 유지한다. 최초 요청은 ‘AI 번역’, 재요청은 ‘AI 다시’로 구별한다. 설정 후에도 모델 확인·변경 경로를 남긴다. 숨겨진 단일 설정 항목을 찾아야 하는 구조를 없앤다.
5. **선택 메뉴의 그룹 제목:** 공통 Select의 제목/설명/옵션 위계를 구분한다. ‘장면 인물’ 같은 짧은 제목, ‘가까운 순’ 같은 보조 설명, 실제 옵션을 같은 행처럼 보이게 하지 않는다. 제목은 hover/선택/포커스 대상으로 표현하지 않는다. 개별 청자와 일괄 청자 지정 모두 같은 규칙을 쓴다.
6. **청자 필터:** 알려진 청자와 ‘청자 미상’을 같은 탐색 경로에서 제공한다. 청자 목록은 화자 목록을 재사용하지 않고 청자 데이터에 기반한다. 미상은 기존의 미지정/불확실 추정 의미와 일치시킨다. 기존 태그 경로도 동일 조건을 가리키며 중복 조건·모순된 칩을 만들지 않는다. ‘이름 없음’과 ‘검색 결과 없음’을 구별하고 화자 검색어가 청자 검색을 몰래 제한하지 않는다.
7. **오버레이:** 공통 DropdownMenu의 하위 메뉴는 스크롤/overflow 부모 바깥에 표시해야 한다. DOM의 open 상태만으로 통과시키지 않고 화면에서 메뉴가 보이며 클릭·키보드 선택이 되는지 확인한다.
8. **설정 컨테이너:** Page/SettingsSection을 확장해 좌우 여백·본문 너비·첫 섹션 간격·스크롤 책임을 한 곳에서 정한다. 프로젝트/편집기 AI/도구와 권한은 같은 시작선을 쓴다. 설정 안의 표는 같은 바깥 여백을 가지는 넓은 콘텐츠 영역에 배치한다. 표 자체의 padding으로 보정하지 않는다. 편집기/캔버스의 전체 폭 배치는 명시적 변형으로 유지한다.
9. **저장 상태:** 자동 저장, 로컬 초안 보관, 서버 저장 성공을 구별한다. 저장이 필요한 dirty 상태에는 직접 찾을 수 있는 저장 동작을 제공한다. 모델 미설정·확정 상태·자료 없음도 정상적인 화면 상태로 다룬다.

수정 순서: 하위 메뉴 잘림·청자 필터 → 아이콘·도크·설정 탐색 → AI 진입점·저장 → 설정 컨테이너·선택 메뉴 위계. 기존 빈 번역 확정(F3)과 필터 유실(F2)도 기능 결함으로 함께 우선 처리한다. 공통 부품 계약을 먼저 고친 다음 모든 해당 소비 화면을 이관한다.

수용 확인은 ‘컴포넌트 사용 여부’가 아니라 A/C 각각에서 열린/닫힌 패널, 모델 있음/없음, 청자 있음/미상, 수정 전/후, 설정 폼/표, 긴 목록/빈 검색을 비교한다. 1280·1440·1920에서 메뉴가 실제로 보이는지와 아이콘의 렌더 크기를 확인한다. 이번 재분석은 이 전체 조합을 통과했다는 의미가 아니다.

## 실행 단계

| 단계 | 상태 | 산출물 / 완료 조건 |
|---|---|---|
| R0 | 완료 | 이 문서와 우선순위·화면 계약 |
| R1 | 구현·핵심 시각 검증 | 공통 셸·단일 도크·A/C 기반. 기존 상세 화면도 도크를 공유 |
| R2 | 구현·핵심 시각 검증 | 대사 화면과 문맥 Inspector, 장면/보기 분리, 후보·행 도구 |
| R3 | 구현·핵심 시각 검증 | 세로 워크플로·라이브러리·노드·설정 재배치·자동 저장 |
| R4 | 공유 셸 적용 · 소스 호환 확인 | 그래프·자료·설정·홈·채팅. 전체 화면별 시각 디자인은 미검증 |
| R5 | 진행 중 | 두 테마·화면 크기·키보드·Back/Forward·mock·9천 줄 검증 |

각 단계에서 공통 부품을 먼저 등록한다. 조사 기준 커밋은 `aa2bda5`(P3 이관 완료)다. 기존 P1~P3 완료 표시는 디자인 완성을 뜻하지 않는다.

## 검증과 작업 기록

- 실사용 `.workbench`와 실행 중인 서버를 건드리지 않는다. 독립 포트와 `WORKBENCH_DATA_DIR`, mock LLM을 사용한다.
- 기능 검사: typecheck, ui-rules, test, build. 시각 검사는 별도로 브라우저에서 수행한다.
- 계획에서 벗어난 부분·미완료·검증 한계는 아래에 기록한다. 미검증을 완료로 표시하지 않는다.
- 2026-10-18: R0 작성. 작업 분담: 주 에이전트는 셸/도크와 상태 통합, GPT-6 Luna는 공통 시각 부품·범위가 명확한 이관 작업.
- 2026-10-18: Mock LLM 검증은 13/13 성공, 6회 호출·실패 0회이며 검토 대기 2건이 남았다. 9천 줄 데이터에서는 브라우저에서 100행을 확인했고 Back/Forward 뒤에도 초안이 유지됐다. 워크플로 자동 저장과 URL 탭 상태도 확인했다. A/C 대사·워크플로는 1440×900 논리 뷰포트에서 비교했고, 1280 실화면과 1920 워크플로도 점검했다. 전체 화면/상태 조합의 검증 완료를 뜻하지 않는다.
- 2026-10-18: 최근 전체 테스트는 89개 파일·599개 테스트 중 598개 통과, 1개 실패다. 기존 `proposal-undo`의 같은 밀리초 `updatedAt` 충돌이며, 격리 실행에서 20회 중 8회 재현됐다. 테스트나 제품 코드는 이 이유로 수정하지 않았다.
- 2026-10-18: `pnpm budget` 6개 시나리오는 통과했고 검토 harness import 오류를 수정했다. UI typecheck와 ui-rules도 통과했다.

SceneSectionHeader는 대사 체크박스와 같은 열에 선택 슬롯을 제공한다. LineList가 현재 검색/필터 결과 전체의 ID를 묶음별로 모아 전체/일부/미선택을 계산하고, 묶음 선택은 기존 일괄 선택 저장소에 합치거나 해당 ID만 제거한다. 렌더링된 100줄을 장면 전체로 오해하지 않는다. 페이지 밖에서 선택되는 대사의 AI 출처와 태그도 일괄 동작에 반영하며, 선택을 위해 실제 번역이나 상태를 변경하지 않는다.

수용: 현실형 전체 대사에서 장면 선택→한 줄 해제→중간 상태→다시 전체 선택→장면 해제, 두 장면 선택 후 하나만 해제, 검색/필터 적용 후 일치 결과만 선택, 페이지에 걸친 장면 선택, 키보드 Space 조작, UI/문서의 같은 묶음 부품을 확인한다.

### 챕터 탐색과 원문 메뉴의 역할 분리

NavigationBranch는 앞쪽 펼침 버튼과 범위 선택 링크를 형제 요소로 배치하며 접힘 상태를 제어한다. 챕터 선택에 결합된 자동 펼침 효과를 제거해 화살표와 이름의 역할을 분리한다. 장면 직접 이동의 부모 드러내기는 유지한다. 원문 단위/묶음의 공통 명칭을 labels에 등록하고 메뉴·빈 상태·편집기에 적용한다. 메뉴의 추가/편집/탐색/AI는 공통 DropdownMenu의 그룹·제목·구분선으로 표현한다.

수용: 접힌 Chapter 클릭은 646줄 범위를 열되 자식은 접힌 채 유지한다. 화살표 클릭은 URL과 가운데 범위를 유지하며 자식만 표시한다. 키보드로도 각각 조작할 수 있고 Back/Forward에서 범위가 복원된다. 추가 메뉴에서 대사/UI 문자열/문서 원문/현재 종류 묶음을 열어 제목과 입력이 일치하는지 확인한다.

### 경로 대본으로 목적 재정의 (2026-10-18)

사용자 지적대로 경로는 구조 축약 그래프가 아니라 시작 대사부터 끝 대사까지 이야기 흐름 하나를 읽고 번역하는 화면이다. 배타 선택 갈림길은 한 연결을 고르고, 병렬 구간은 모든 arm이 함께 수행되는 하나의 복합 단계다. 같은 병렬 단계 안의 대사는 원문 순서로 표시할 수 있으나 이를 실행 순서라고 주장하지 않는다. 읽기 전용 reading-route 서비스는 두 끝점 사이의 유한한 실제 흐름을 찾고, 선택하지 않은 배타 갈래는 포함하지 않는다. 필수 병렬 arm이나 순환을 조용히 버려 성공으로 표시하지 않는다. 조건을 판정하거나 연결을 발명하지 않으며 합류 대사는 한 번만 포함한다. 시작점과 끝점은 URL에 두고 임시 선택은 명시적으로 찾기 전까지 적용하지 않는다.

PathMode는 공통 GraphScriptSplit으로 경로 그래프와 RouteList를 나란히 구성한다. 시작/끝은 원본 그래프에서 직접 클릭해 고르고 명시적으로 경로 만들기를 눌러 적용한다. 검색과 구역 선택은 그래프에서 대사를 찾는 보조 수단이다. 끝점을 고르는 검색 드롭다운은 제거한다. 그래프는 넓이를 조절할 수 있고 기본 100% 배율이며 대본 선택과 동기화한다. 선택한 흐름의 실제 연결을 그래프에 표시한다. 병렬 구간은 한 세로 단계 안에 모든 arm을 표시하고 합류 단계는 한 번만 표시한다. 본문은 공통 ScriptReadingRow, 같은 TranslationEditor, 40줄 단위 조회·가상화를 사용한다. 조건 제어 노드/이어짐/구간/이음새 지도·자동 접기와 클릭에 따라 바뀌는 창은 제거한다. 새 경로 및 번역 갱신은 units query로, graph 변경도 IMPLIES에서 units를 갱신해 폴링 없이 동기화한다.

캔버스는 graph-canvas/graph-node/graph-node-line 토큰을 실제 렌더러까지 연결한다. 기본 진입은 읽을 수 있는 배율, 전체 맞춤은 명시 동작이며 기존 뷰포트는 유지한다. 회색 배경과 흰 노드 및 다크 표면 대비는 공통 토큰의 책임이다.

대규모 경로 그래프는 ELK의 기존 워커를 재사용하고, 연결이 밀집한 노드의 추가 연결은 별도로 보존해 선택 시 그린다. 실제 연속 대사 연결은 허브 처리에서도 유지하여 노드가 연결 없는 격자로 배치되지 않도록 한다. 공통 캔버스는 최신 렌더 함수를 참조하고 크기 변경 시 중심과 배율을 유지한다. 이를 통해 폭 조절 후 확대·축소 잔상을 제거한다.


## 그래프 방향과 연결점 보완 — 2026-10-18

사용자가 가로/세로 배치 선택을 요청했다. 기존 시안의 세로 배치를 기본으로 유지하고 공통 CanvasDirectionControl을 통해 양 방향을 지원한다. NodeCard의 출력 라벨을 항상 보이게 만들고 검수 실패와 실행 오류의 표시를 구분한다. ELK 배치 방향과 React Flow 연결점 방향을 함께 바꾸며 원문 그래프의 방향별 배치는 서버 워커와 기존 캐시/SSE 경로를 사용한다. 경로 대본은 방향만 바꾸며 이야기 순서·병렬 묶음·선택·초안은 유지한다.

### 노드 종류 식별 — 2026-10-18

라이트 테마에서 종류별 헤더가 빠진 원인은 NodeCard가 `dark:`에만 색을 적용했기 때문이다. 아이콘만 다른 동일한 흰 직사각형으로는 역할을 구분하기 어렵다. 공통 NodeCard가 양 테마의 종류별 헤더 토큰, 아이콘, 유형 이름을 소유한다. AI·검사/작업·조건·상태 변경을 구분하고 진입/종료는 종단 형태로 표현한다. 선택 강조는 종류 색과 별개로 유지하며 출력 이름과 간선은 실제 동작을 표시한다. 노드 크기 변경 후 실제 측정 크기로 재배치하여 간격과 연결점도 함께 검증한다.

워크플로 배치는 노드 위치와 방향을 함께 저장한다. 다른 창에서 저장한 배치를 받은 깨끗한 창은 URL 방향도 replace로 맞추며 다시 자동 저장하지 않는다. 로컬 변경 중에는 기존 버전 충돌 처리를 유지한다. 사용자 가로/세로 선택과 Back/Forward만 새 배치를 요청한다. 배치 후 화면 중심은 이전 React Flow 좌표가 아니라 방금 계산한 좌표로 정한다.


### 그래프에서 경로 선택 및 채팅 연결 — 2026-10-18

원인은 그래프 작업을 일반 검색 폼으로 구현해 사용자가 선택하려는 흐름을 가린 것이다. 선택 단계에는 기존 원본 GraphCanvas와 서버 배치를 재사용하며, 공통 경로 선택 바가 시작·끝·현재 선택 역할을 표시한다. 접힌 연속 구간에서는 실제 구성 노드를 펼쳐 클릭하고 제어 노드는 끝점으로 사용하지 않는다. 현실형 데이터의 첫 화면은 읽을 수 있는 크기로 실제 대사에 초점을 둔다.

URL의 임시 시작·끝과 선택 단계는 적용된 경로의 끝점과 분리한다. 경로 만들기 전까지 기존 결과를 덮지 않으며, 실패 시 원본 그래프에서 수정한다. 채팅은 읽기 전용 find_reading_route 도구를 통해 같은 projectReadingRoute를 호출하고 두 끝점·줄 수·열기 버튼을 반환한다. 전체 대본을 도구 결과에 복제하지 않는다. 끝점이 가리키는 단위는 대사를 포함한 원본 노드이며, 여러 줄 노드도 브라우저와 채팅의 범위가 일치한다.
