## 공통 컴포넌트와 실제 상호작용 재검토

사용자가 제공한 7개 캡처/9개 지적을 기준으로, 동일 격리 환경에서 화면·DOM 치수·소스 원인을 대조했다. 이번 단계는 분석과 계약 보강이며 제품 코드는 수정하지 않았다. 주 에이전트가 실제 브라우저를 조작하고 Luna 6 작업자 두 명은 편집기/필터와 셸/설정을 나누어 소스만 읽었다. 자동 검사 점수를 디자인 품질의 증거로 사용하지 않았다.

### 결론: 공통화의 수준이 부족함

- `InlineEditorActions`는 ReactNode 슬롯을 나란히 놓을 뿐 버튼의 아이콘·상태·미설정 동작을 소유하지 않는다. 화면은 공통 부품을 사용하면서도 6px 아이콘을 전달할 수 있다.
- `SidebarMenuButton`은 직접 자식 SVG에만 크기를 강제한다. 소비 화면이 span으로 감싸면 탐색 아이콘 크기 규칙이 사라진다.
- `Page`는 기본 padding, 소비 화면은 추가 padding, `SettingsSection`은 첫 섹션 padding을 각각 정한다. 화면 컨테이너의 최종 여백을 책임지는 부품이 없다.
- `DropdownMenuContent`는 portal을 쓰지만 `DropdownMenuSubContent`는 쓰지 않는다. 같은 메뉴 계열 안에서도 clipping에 대한 계약이 일치하지 않는다.
- 따라서 문제는 단순히 컴포넌트를 더 만드는 것이 아니다. 기존 공통 부품이 용도·크기·빈 상태·열림 상태·레이아웃 경계를 통제하도록 고치고 소비 화면의 임의 조합을 줄여야 한다.

### P1 · 청자 하위 메뉴 잘림: 데이터가 없다는 추측과 구별

1. 현실형 Scene 351에서 화자 필터를 열고 ‘청자’를 클릭했다.
2. 접근성 트리에는 `expanded`와 MIRA/JONAS 등 19개 이름이 나타났다. 그러나 스크린샷에는 하위 메뉴가 보이지 않았다.
3. DOM 실측: 부모 메뉴 x=513,y=84,w=224,h=611, overflow=`hidden auto`. 하위 메뉴 x=722,y=662,w=224,h=574이며 부모 메뉴의 DOM 자손이었다. 부모의 오른쪽 경계737px 밖으로 대부분 나간다.
4. 공통 `dropdown-menu.tsx:234-249`의 SubContent에는 Portal이 없으며 부모 Content는 overflow-hidden, 이 화면에서는 overflow-y-auto까지 적용한다. 화면에 없는 것처럼 보이는 원인과 코드 구조가 일치한다. **호버 이벤트 자체가 실패했다고 단정하지 않는다. 클릭으로 열린 상태가 시각적으로 잘리는 것을 재현했다.**
5. 태그→청자 미상은 실제로 동작했다. Scene 351 20줄에서 14줄로 줄고 URL에 `marks=["unknownListener"]`, 제거 가능한 칩이 생겼다. 따라서 필터 엔진 자체가 없는 것은 아니다. 청자 메뉴에서 발견할 수 없다는 문제이며, 기존 조건은 미지정뿐 아니라 불확실 추정을 포함한다.

증거: `audit-feedback-listener-clipped.png`. 메뉴의 DOM 존재/ARIA open 확인만으로 사용자에게 보인다고 판단한 검증 방식도 수정해야 한다.

### 같은 기준으로 추가 발견한 불일치

- **설정 페이지에서는 설정 메뉴를 접을 수 없음.** 프로젝트 설정에서 설정 트리거를 눌렀지만 expanded가 유지됐다. `app-sidebar.tsx:58`의 `settingsOpen || current.group.id === 'settings'`가 사용자의 접기를 무시한다. 열린 항목을 강조하는 것과 메뉴를 강제로 펼치는 것을 분리해야 한다.
- **홈과 실제 현재 페이지가 동시에 현재 페이지로 선언됨.** 대사 화면 DOM에서 홈은 `data-active=false`인데 `aria-current=page`, 대사는 둘 다 활성이다. Link의 경로 활성 판정과 앱의 메뉴 활성 판정이 어긋나 있다. 시각적 활성과 접근성 상태가 같은 한 항목을 가리키도록 맞춰야 한다.
- **모델 설정 후에는 편집기의 모델 설정 경로가 사라짐.** 설정 링크 조건이 `!assistModel`이므로 설정 완료/모델 변경 상태를 고려하지 않았다. 구성된 경우 동작 이름도 초역 여부와 무관하게 ‘AI 다시’다. 최초 사용·재요청·설정 변경의 일관된 계약이 필요하다.
- **화자 검색어가 청자 메뉴도 제한함.** 하나의 needle/shown을 공유하므로 화자를 검색하다 청자 메뉴를 열면 같은 검색이 몰래 적용된다. 데이터도 화자 집계이므로 청자로만 등장하는 이름이나 특수 청자를 제대로 표현하지 못한다.
- **닫힌 도크 문제는 용어집뿐 아니라 설정 편집에도 영향.** 상태·태그에서 ‘확정’ 행을 선택하면 URL의 status는 바뀌지만 편집 폼은 닫힌 채다. 행 선택→편집 의도가 공통 셸에서 처리되지 않는다(J1의 범위 확장).
- **설정의 저장 방식도 통일된 안내가 없음.** 프로젝트에는 저장 버튼, 편집기 AI에는 변경 즉시 요청이 있지만 화면에 저장 중/성공 표시를 렌더하지 않는다(`settings/editor-ai.tsx:24-38`). 이 항목은 소스로 확인했으며 이번에는 설정값을 변경해 실패/롤백까지 재현하지 않았다. 서버에 저장됐는지 알 수 있는 공통 피드백이 필요하다.

## 후속 수정 검증 — 시작·끝 사이 한 줄 이야기 경로

- 원인: 경로를 실행 가능한 모든 분기의 그래프로 해석해 대본 읽기 목적을 놓쳤다. 그래프를 제거하거나 병렬 가지를 옆으로 펼치는 중간 구현은 사용자 요구를 충족하지 않아 폐기했다. 이전 branching/ELK 화면 증거는 현재 완료 근거가 아니다.
