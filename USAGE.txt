Translation Workbench 사용 안내 · v0.2 개편
2026-10-09 (Asia/Seoul)

실행과 작업 공간
  Node.js 24 이상. 개발·검증 환경은 Windows / Node.js 26.8.2입니다.
  PowerShell에서 .\start.ps1 → http://127.0.0.1:4317.
  첫 실행은 의존성 설치와 UI 빌드 후 서버를 시작합니다. 종료는 터미널 Ctrl+C.
  개발: npm install → npm run dev (UI 4318 / API 4317).
  검사: npm run typecheck / npm test / npm run build.
  왼쪽 위 작업 공간에서 기존 작업과 '3장면 데모 · 별도 저장'을 전환합니다.
  데모 직접 열기: http://127.0.0.1:4317/?workspace=demo
  데모는 .workbench/demo-three-scenes의 별도 DB·설정에 저장됩니다.
  24개의 가상 원문과 저장된 모의 응답을 사용하며 실제 AI 품질 시험이 아닙니다.

1. 원문 찾기와 읽기
  장면 지도에서 노드를 선택하고 상세의 읽기/대사 흐름으로 이동합니다.
  작품 전체 대사와 선택 장면의 대사 범위는 별도 진입점입니다.
  원문·번역·화자·ID를 검색하면 화면 밖 원문과 연결 없는 원문도 찾을 수 있습니다.
  검색 결과는 페이지로 읽지만 그래프 전체를 임의 개수로 잘라 표시하지 않습니다.
  작은 그래프와 큰 그래프 모두 D3 + Canvas입니다. 전체 맞춤, 확대/이동,
  미니맵, 선택 상세와 키보드 검색을 사용합니다. 선택 주변 보기에는 범위가 표시됩니다.
  조건/분기, 대기, 이벤트, 연결·합류와 미확인 원형식을 구별합니다.
  Back/Forward와 새로고침은 범위·검색 페이지·선택·그래프 위치·미저장 초안을 복원합니다.
  원문 조건은 보존된 추출 근거입니다. 작업 프로세스의 실행 조건과 다르며,
  review order가 실제 사건 순서나 인물의 지식을 뜻하지 않습니다.

2. 채팅으로 작품 자료 준비
  프로젝트 채팅에서 새 세션을 만들고 지원하는 AI 프로필을 고릅니다.
  선택 장면/원문을 첨부하거나 채팅의 원문 첨부 검색을 사용합니다.
  새 세션은 별도 대화 기록을 가지며 같은 프로젝트의 저장 자료를 조회합니다.
  다른 프로젝트의 원문 ID·세션·제안을 섞지 않습니다.
  자료 생성/수정을 요청하면 AI가 읽기·조사를 수행하고 변경 제안을 만듭니다.
  제안에서 내용·근거·영향을 확인한 뒤 수락, 거절, 피드백, 직접 편집을 선택합니다.
  수락은 검토한 제안 버전을 한 번만 적용합니다. 피드백/직접 편집은 승인 대기
  초안을 바꾸며, 다시 수락하기 전에는 본문이나 번역 문맥에 반영되지 않습니다.
  원문·번역·용어·자료가 중간에 바뀌면 오래된 제안의 적용이 차단됩니다.
  Ctrl+Enter로 전송하며 중지 버튼으로 새 도구/모델 호출을 멈춥니다.
  대화 설정에서 최대 AI 호출·도구 호출을 정합니다. 완료한 기록은 보존합니다.

  채팅 지원: OpenAI 호환 Chat Completions 또는 Responses의 도구 호출 어댑터.
  채팅 미지원: Codex, Grok, Antigravity, Claude CLI / System One / 모의 연결 종류.
  이 연결들은 기존 구조화 작업과 채팅에서 서로 다른 능력으로 취급합니다.
  호환 API라도 서버·모델의 도구 호출 지원과 인증은 실제 요청에서 확인합니다.
  AI 응답은 SSE로 같은 카드에 부분 텍스트를 표시합니다. 중지하면 미완료 표시와
  부분 응답이 보존되며, 다음 요청의 확정 대화 문맥에는 미완료 응답을 넣지 않습니다.
  완료된 메시지·도구 기록을 조회하고 후속 요청을 보낼 수 있습니다.

  웹 검색은 별도 서비스가 필요합니다. AI 모델 연결만으로 검색을 제공하지 않습니다.
  도구 연결 설정에서 SearXNG 검색 API 주소와 필요 시 해당 도구의 인증을 설정합니다.
  세션 웹 OFF에서는 새 검색/URL 읽기를 서버에서도 차단합니다. 이전에 저장한
  웹 근거는 출처와 함께 로컬 자료로 읽을 수 있습니다.
  ON에서도 검색/페이지/도구/토큰 한도가 적용됩니다. 외부 SearXNG 배포와 실제
  유료 검색 서비스는 이번 모의 검증 범위에 포함되지 않습니다.

3. 작품 자료·인물·관계·용어
  작품 자료는 제목/종류/근거를 목록에서 비교하고 본문·수정 이력을 읽습니다.
  수정·복원으로 실제 소비 자료가 바뀌면 관련 번역에 갱신 필요를 표시합니다.
  인물·관계 Canvas는 저장된 인물과 관계만 표시합니다. 인물에서 프로필·별칭,
  관계에서 방향·설명·적용 분기·근거를 열고 원문을 다녀온 뒤 돌아올 수 있습니다.
  함께 등장한 이유만으로 관계나 사건 순서를 자동 생성하지 않습니다.
  용어집은 권장 번역, 대체 후보, 사용 방향, 근거와 실제 candidateId/버전 사용을
  구별합니다. 후보 변경/제거 시 관련 번역을 지우지 않고 갱신 필요로 표시합니다.
  채팅에서 수락한 용어/자료 변경은 숨은 AI 재검토를 시작하지 않습니다.
  기존 작업별 용어 재검토 흐름과 사용자가 시작한 프로세스는 따로 실행합니다.

4. AI 연결과 재사용 프로필
  AI 설정의 연결에서 계정/API를 관리하고 프로필에서 이름 있는 AI 설정을 생성합니다.
  연결·모델·추론·지시문·출력/시간/시도 한도와 대체 AI를 저장합니다.
  프로세스 노드와 채팅에서 같은 저장 프로필을 선택할 수 있습니다.
  저장한 프로필을 선택해 복제하거나 JSON 내보내기로 옮길 수 있습니다.
  JSON 가져오기는 새 초안을 만듭니다. 미연결 기본/대체 경로의 연결을 선택하고
  이름·모델·지시문·맥락/도구 정책을 검토한 뒤 프로필 저장을 누릅니다.
  가져오기만으로 저장·시험·모델 실행하지 않으며 파일에 API 키·엔드포인트를 넣지 않습니다.
  프로필 시험은 별도 결과를 보여 주며 번역 본문에 반영하지 않습니다.
  기존 작품 분석/용어/인물/번역/검수/재검토의 작업별 설정과 이력도 유지합니다.

  OpenAI 호환 API는 각각 이름·base URL·키를 가진 여러 연결로 등록합니다.
  base URL은 /v1 등 API 접두사까지 입력합니다. Chat/Responses, 구조화 출력 방식,
  Chat 출력 한도 필드는 서버가 지원하는 값으로 선택합니다.
  이름 변경은 기존 키를 유지하고 주소 변경은 새 키를 요구합니다.
  진행 중인 호출/실행이나 프로필이 참조하는 연결은 보호됩니다.
  Windows DPAPI로 저장한 키는 Windows 사용자와 엔드포인트에 묶입니다.
  프로젝트 본문·로그·백업에 키를 저장하지 않습니다. 키 저장이 인증 성공은 아닙니다.
  고급 환경 변수 방식은 값이 아닌 변수 이름을 지정합니다.
  HTTPS와 승인된 로컬·사설망 HTTP 정책을 사용합니다.

  Codex/Grok/Antigravity/Claude는 공식 CLI의 로그인 절차를 사용합니다.
  작업실은 계정 토큰 파일을 복사하지 않습니다. 설치·로그인·모델 접근은 구별합니다.
  CLI는 구조화 번역 작업에 사용하며 채팅 도구 호출로 우회 실행하지 않습니다.
  CLI 출력 토큰 상한은 강제를 보장하지 못합니다. 시간·시도 한도는 적용합니다.
  System One(TypeSafe Jev)은 기존 번역 판정 전용이며 새 번역·채팅 생성기가 아닙니다.
  System One 키와 모델 목록도 별도 연결에서 관리합니다. 실제 Jev 호출은 미검증입니다.

  대체 AI는 등록된 순서와 시도 한도를 따릅니다. 일시적 통신/제한/시간 초과는
  재시도·대체할 수 있지만 인증·설정·결과 검증 오류를 성공처럼 바꾸지 않습니다.
  실행은 시작 당시 설정을 고정합니다. 설정 변경은 새 실행부터 적용됩니다.
  네트워크 재시도와 대체 AI 호출은 번역 수정 라운드 횟수에 더하지 않습니다.

5. 프로세스 만들고 실행
  상단 작업 준비 또는 프로세스 화면에서 번역 템플릿/빈 프로세스를 엽니다.
  실행 범위는 장면, 선택 원문 ID, 프로젝트 전체 중에서 명시적으로 선택합니다.
  상태·라벨에서 추가 필터를 고릅니다. 여러 상태는 하나 이상(OR), 여러 라벨은 모두(AND)입니다.
  대상 수와 미리보기는 범위·필터 교집합입니다. 시험과 실행도 같은 원문 ID를 사용합니다.
  없는 ID/필터나 0개 대상은 시작할 수 없습니다. 범위·필터는 초안과 함께 보존됩니다.
  노드를 추가하고 오른쪽 설정에서 프로필·묶음·조건·행동·사람 확인을 정합니다.
  Canvas의 노드/출구를 드래그하거나 오른쪽 출구 선택으로 연결합니다.
  조건은 필드/비교/값과 AND/OR 행으로 편집하며 JSON은 고급 설정에서 엽니다.
  입력 매핑은 필드 참조 또는 상수를 지정합니다. 오류 경로 표시를 켜면 모두 볼 수
  있고 기본은 선택 노드의 오류 경로를 보여 줍니다. 전체 맞춤/흐름 정리도 제공합니다.
  검사로 필수 포트·참조·유한 반복과 HTTP/백업 설정을 확인합니다.
  모의 시험은 현재 초안과 선택 범위를 복사본에서 실행합니다. 본문·실행 DB·외부
  HTTP·유료 모델을 바꾸거나 호출하지 않습니다. 모의 성공은 모델 품질 보증이 아닙니다.
  저장한 뒤 실행을 누르면 저장 정의·프로필·연결·대상을 고정하고 실행합니다.
  실행 기록의 실행 흐름 vN 보기는 당시 그래프와 고정 대상 수를 읽기 전용으로 엽니다.
  노드를 선택해 입력/출력을 조회합니다. 모의 흐름은 시험한 초안으로 표시합니다.
  편집 흐름 보기로 돌아오면 편집 초안과 확대/이동 위치가 유지됩니다.

  기본 흐름: 문맥 조회 → 초벌 후보 → 서식 검사/AI 검수 → 대사별 판정.
  통과분은 대표 번역 선택·확정, 실패분만 수정 후 재검수, 한도 도달분은 사람 대기.
  한 장면을 반드시 한 줄씩 호출하지 않습니다. 대상·범위·문맥 버전에 따라 묶습니다.
  사용자가 시작한 흐름의 자동 행동은 채팅 수락을 매번 요구하지 않습니다.
  실행 기록에서 노드 입력/출력, 대상 위치, 수정 라운드와 실제 호출 시도를 확인합니다.
  사람 대기에서는 해당 대사만 직접 편집 후 수락/거절/보류합니다. 다른 대사는
  현재 위치를 유지합니다. 일시정지·재개·취소는 완료 결과를 보존합니다.
  사용자 정의 실행기는 현재 한 번에 한 모델/외부 호출을 진행합니다.
  독립 분기·연결별 병렬 호출과 분산 실행은 지원하지 않습니다.

6. 번역 후보·상태·라벨
  대사 상세의 '후보·진행'에서 번역 후보를 페이지로 조회하고 대표 번역을 선택합니다.
  원문·번역·후보 버전, 잠금, 서식/보호 토큰, 자료·용어 유효성을 다시 검사합니다.
  보호된 번역이나 오래된/잘못된 후보는 무음으로 덮어쓰지 않습니다.
  상태와 라벨을 직접 생성하거나 기존 항목을 적용합니다. 상태의 확정 역할은
  비어 있거나 갱신 필요·서식 오류인 번역을 확정하지 못합니다.
  라벨은 게임/HTML 서식 태그가 아닌 사용자가 정한 작업 표식입니다.

7. HTTP 도구와 체크포인트·백업
  HTTP/백업 노드에서 등록된 도구 연결을 고르고 요청·응답 필드를 설정합니다.
  HTTP는 GET/POST JSON, query/body 매핑, 인증 없음/Bearer/전용 X- 헤더를 지원합니다.
  개별 응답은 입력 원문과 연결하고 묶음 응답은 원문 ID 필드로 정확히 대응합니다.
  누락·중복·범위 밖 ID·잘못된 JSON·리디렉션은 추측해서 저장하지 않습니다.
  사전/맞춤법 결과는 노드 출력이며 다음 적용 행동을 거치기 전에는 본문을 바꾸지 않습니다.
  도구 URL·설정도 실행 시작 시 고정하고 비밀값은 별도 저장합니다.
  timeout·응답 크기·최대 시도 한도를 적용합니다. 외부 쓰기 요청은 재시도의
  중복 효과를 고려해 설정해야 합니다. 임의 코드/스크립트 노드는 없습니다.

  백업은 기본 100개마다 서로 다른 대표 저장 완료 원문을 집계합니다.
  확정 완료 집계로 바꿀 수 있고 같은 원문의 재수정·후보/호출 수는 중복 집계하지 않습니다.
  95→112처럼 경계를 건너도 현재 배치까지 백업하며, 정확히 100번째 상태를 만들지는 않습니다.
  여러 임계값은 한 스냅샷에 기록하고 종료 시 잔여분도 저장합니다.
  파일에는 실제 포함 revision을 기록합니다. 실패한 파일 확정은 같은 pending 기록과
  digest로 복구하며 파일 성공 후 집계를 전진시킵니다.
  저장 폴더는 작업실 backups 아래 상대 경로입니다. 원본 게임 폴더에 쓰지 않습니다.

  기본 DB: .workbench/workbench.sqlite. 키: 별도 credentials.dpapi.json.

  프로젝트 관리에서 보관·가져오기·백업 복원·카탈로그 내보내기를 구별합니다.
  카탈로그는 번역 결과용이며 작업실 백업을 대신하지 않습니다.
  백업은 후보/자료/인물·관계/채팅·제안/흐름·대기 위치/카운터를 포함합니다.
  비밀값과 실행의 AI 엔드포인트 정의는 제외합니다. 복원은 자동 호출하지 않으며,
  남은 AI 작업은 현재 연결을 확인하고 새 실행으로 시작해야 할 수 있습니다.
  구버전 백업을 읽고 원문·기존 번역·이력·잠금·출처를 유지합니다.
  잘못된 프로젝트/참조/스냅샷/실행·백업 기록은 복원 전에 거부합니다.
  같은 ID를 다시 가져오면 수동 편집을 보존합니다. 원문·문맥 변경은 갱신 필요와
  이전 제안 충돌로 표시합니다. 게임 원본과 추출물은 변경하지 않습니다.
